## 8. Gate 决策链路验收项

必须验证 approve / request_changes / reject。

### GATE-01：approve

- Gate 状态更新为 approved。
- Project / Run / Stage 状态推进。
- 写 Audit。
- 刷新后状态可见。

### GATE-02：request_changes

- Gate 状态更新为 changes_requested 或等价状态。

- Gate 状态更新为 rejected。
- 阶段状态 blocked / rejected / halted，需明确。
- 写 Audit。

### GATE-04：非法决策

- 返回 400/403。
- 不改变状态。
- 写入安全/拒绝记录或 Trace。

## 12. 裁决规则

### accepted

必须满足：

1. 所有 P0/P1 核心链路通过。
2. 后端全量 pytest 0 failed。
3. 前端 build exit 0。
4. 浏览器级证据通过。
5. Review Pass 与 Gate 机制通过。
6. 三模式和 Auto 授权边界通过。
7. 进度追踪同步完成。
8. 无安全泄露。
9. 无 P0 阻塞。

### conditional_acceptance

仅在以下情况允许：

1. 所有 P0 阻断项通过。
2. 仅存在不影响 R10 启动的 P1/P2 缺口。
3. 缺口已登记，有明确归属。
4. 用户明确接受进入 R10 前补或 R10 起始修补。

### rework_required

任一情况触发：

1. 后端全量 pytest 有 failed 且未获用户豁免。
2. P0 或 P1 端到端链路失败。
3. Review Pass 只是框架，未接真实流程。
4. Gate 决策链路失败。
5. 三模式只是 UI/API 切换，无行为差异。
6. Auto 绕过阶段 Gate 或 L4+。
7. P2 输入包不完整。
8. 浏览器级证据缺失。
9. 进度追踪未同步。
10. 安全泄露。
