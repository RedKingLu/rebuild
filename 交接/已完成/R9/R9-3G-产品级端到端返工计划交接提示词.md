## 2. 本轮必须先承认的问题

请不要再以“R9-3F 二次自验通过”直接收口。必须先承认以下问题，并结合本地实际再次核查：

### 2.1 页面仍出现 R9 占位文案

用户当前仍看到类似：

- “P0 接入阶段页面将在 P0-P6 编排阶段（R9）接入真实业务数据。”
- “Agent 对话将在 P0-P6 编排阶段（R9）接入真实能力。当前展示项目上下文摘要。”

当前已经是 R9。如果页面仍说“将在 R9 接入”，说明 R9 的用户可见能力仍未真正接入。这类文案必须被视为 P0 缺陷，不是 P2 文案瑕疵。

### 2.2 P0 不等于引导界面

引导界面最多只是 P0 的入口。P0 完成必须包含真实接入动作：Git/源码导入、source_index、intake_report、Evidence、Trace/Audit、P0→P1 Gate、状态推进和用户可见输出。

如果引导完成后用户看不到结果，或者源码没有进入 `source/`，P0 就没有完成。

### 2.3 P1 不等于 profile API

P1 完成必须包含用户可见的全量识别与建档闭环：P1 执行反馈、Agent/执行过程展示、14 项识别、Artifact、Evidence Gap、profiling_summary、p2_input_manifest、Review Pass、P1→P2 Gate。

如果用户批准进入 P1 后“没有反应”，P1 就没有完成。

### 2.4 Agent 对话仍是占位即为 R9 阻断

R9 设计了小循环：读取上下文 → 识别/分析 → 计划 → 执行 → Review → 返工/Gate。用户需要在 Agent 对话/执行区域看到真实过程。如果该区域仍显示“将在 R9 接入真实能力”，则小循环没有进入产品体验。

### 2.5 Git 项目创建和 source materialization 必须真实闭合

如果用户从 Git 创建项目后源码没有导入 `workspace/source/`，则 P0 接入失败。之前 R9-3F 中 git/github 仍为 deferred 的诚实标记不能被写成 R9 Git 项目创建链路完成。若 Git 凭据或 OAuth 已绑定，则必须真实 clone；若未绑定，则必须在 UI 明确阻塞并引导绑定。

## 5. R9-3G 返工计划必须覆盖的能力

请制定一份分轮或分工作包计划。不要直接施工。计划必须覆盖以下能力。

### 5.1 用户入口闭环

必须规划：

1. 登录到平台。
2. Git/GitHub 绑定。
3. 模型/Provider 绑定或选择。
4. 基于 Git 仓库创建项目。
5. 创建后自动进入 Workspace。
6. 绑定缺失时的阻塞提示与修复入口。

### 5.2 P0 接入闭环

必须规划：

1. 引导改为浮窗/模态体验，参考 V10 方向，但不得复制旧代码。
2. 引导必须真实读取和写入后端。
3. Git source materialization 必须真实 clone，除非未绑定凭据，此时要阻塞并引导绑定。
4. source_index 必须生成并可见。
5. intake_report 必须可见。
6. Evidence candidates 必须可见。
7. Trace/Audit 必须可见。
8. P0→P1 Gate 必须可操作。
9. P0 完成后 UI 明确显示状态。

### 5.3 P1 建档闭环

必须规划：

1. 用户批准进入 P1 后立即触发 P1 任务。
2. Agent 对话/执行区显示 P1 执行过程。
3. 真实读取 source 和 source_index。
4. 14 项全量识别真实执行。
5. Artifact 全部生成并可见。
6. Evidence Gap 生成并可见。
7. profiling_summary 可见。
8. p2_input_manifest 可见。
9. Review Pass 真实执行，失败时能返工。
10. P1→P2 Gate 可见可操作。
11. P1 完成后 UI 明确显示 completed 或 waiting_gate。

### 5.4 Agent 对话 / 执行可视化

必须规划：

1. 替换所有“将在 R9 接入”的占位文案。
2. Agent 对话区域接入真实 P0/P1 过程。
3. 显示当前阶段、当前任务、读取的上下文、工具调用摘要、产物、Review 结果、Gate 原因。
4. 出错时显示可理解的错误和下一步，而不是无反应。
5. Manual / Plan / Auto 下对话和确认方式有差异。

### 5.5 Gate / 状态 / 任务反馈

必须规划：

1. Gate approve / request_changes / reject 全部真实可用。
2. request_changes 回到阶段内返工，不是状态死掉。
3. reject 进入明确 blocked / rejected 状态。
4. 所有 Gate 决策写 Audit。
5. 状态刷新后不丢失。
6. 阶段状态在 UI 可见。

### 5.6 三模式真实体验

必须规划：

1. Manual：每步用户确认，Agent 等待用户明确动作。
2. Plan：先生成阶段内计划，用户确认后执行。
3. Auto：阶段内低风险动作自动推进，但不绕过阶段 Gate。
4. 切换模式后 UI、Agent 对话、任务执行策略均有变化。
5. 切换写 Trace/Audit。
