R9-2 第一件事是修订 R9-1R 方案，不得直接历史吸收。

   - Auto 模式替用户审核 Agent：只处理阶段内可代理授权项，不能替代阶段 Gate 或高风险人工 Gate。

   - Manual / Plan / Auto 不能设计为 Run 启动后完全锁死。

   - 切换动作必须写 Trace/Audit。
   - 切换只影响后续动作，不回溯更改已执行动作。
   - 若当前正在执行不可中断动作，可排队生效或提示等待。
   - 阶段晋级 Gate 不受 Auto 模式绕过。

4. **普通 Review Pass 与 Auto Review Agent 边界**
   - 普通 Review Pass 不等于独立 Agent；可作为 Skill 自验。
   - Auto Review / Authorization / Safety Agent 用于阶段内授权代理、安全审核、高风险复核，不等于 R9-4 Acceptance Agent。
   - 名称上避免把 `Auto Review Skill` 与 `Auto Review Agent` 混淆。

5. **source materialization 实现方式**
   - source materialization 应作为后端 service/tool capability 设计。

   - Git clone 可用受控 Git service 或受控 subprocess，但必须有 timeout、路径 guard、脱敏、Trace/Audit、错误处理。
   - 终端 UI 可以展示日志或触发受控动作，但不应成为 materialization 的主要实现抽象。

6. **Trace 失败处理**
   - 不允许静默失败。
   - L0/L1 可记录 warning 并继续，但阶段 Gate 前必须检查关键 Trace 完整性。

## 4. 必须修正的概念边界

### 4.1 自验、Review、独立评审、独立验收

R9-2 必须给出清晰定义：

- **施工自验**：施工 Agent 使用自验 Skill、规则清单和测试命令，在提交前自查。可由施工 Agent 完成。
- **Review Pass**：阶段内质量检查，可由 Node Worker Agent 加载 review skill 完成；用于小循环内部返工判断。
- **独立评审**：非施工 Agent / 干净上下文 Agent 对方案、产物或风险做复核。用于关键设计点、高风险事项或用户要求。
- **独立验收**：Acceptance Agent 对阶段完成条件做验收。R9-4 必须独立验收，不得由施工 Agent 自己完成。
- **Auto 授权代理**：Auto 模式中替用户处理阶段内 Gate / 授权项的 Agent，不等于阶段 Gate，也不等于独立验收。

### 4.2 Gate 类型

必须区分：

1. **阶段内 Gate**：阶段内部工具授权、写盘授权、低/中风险授权。Auto 模式可由 Auto 授权代理代用户审核，但需 Trace/Audit。
2. **阶段晋级 Gate**：P0→P1、P1→P2 等。必须用户确认，Auto 不得绕过。
3. **人工介入 Gate**：超过最大返工轮数、L4+ 高风险、敏感信息风险、用户显式要求时触发。必须用户确认。
4. **验收 Gate**：R 阶段施工完成后由独立验收 Agent / 用户裁决。

### 4.3 Agent 切换原则

必须回到 D-017 类原则：

- 默认不切 Agent。
- 需要干净上下文、权限隔离、模型切换、独立验收、高风险审查、专家能力或并行隔离时才切 Agent。
- Review Pass 默认是 Skill，不是固定独立 Agent。
- R9-4 独立验收必须是独立 Agent / Acceptance Agent。

## 5. 三模式自由切换机制修订要求

R9-1R 中“Run 启动后模式锁定”的说法需要修订。

### 5.1 正确原则

Manual / Plan / Auto 应允许在 Workspace 顶部自由切换。原因：用户在工作区中应能根据当前任务状态随时调整自动化程度，类似编程工具中随时切换模型、模式、执行策略。

### 5.2 切换规则建议

必须设计：

1. 模式切换即时生效于**后续动作**。
2. 已执行动作不回滚、不改历史。
3. 当前正在执行不可中断动作时，切换进入 pending 状态，动作结束后生效。
4. 切换动作写 Trace；如果影响授权密度或自动化范围，写 Audit。
5. 切换不绕过阶段晋级 Gate。
6. Auto 模式不能绕过 L4+ 高风险人工 Gate。
7. Manual 模式切换后，下一步低风险动作也需要用户确认。
8. Plan 模式切换后，若已有阶段内计划，需要提示是否沿用、重算或废弃。
9. Auto 模式切换后，可自动执行低风险阶段内动作，但仍必须 Review Pass。

### 5.3 数据模型建议

不得把 mode 只当 Run 创建时不可变字段。建议至少设计：

- Project 或 Workspace 当前模式：用于顶部 UI 当前选择。
- Run action 或 Stage loop 当前有效模式：记录每个动作执行时采用的 mode。
- Mode change event：记录切换时间、操作者、from_mode、to_mode、reason。

具体实现可在 R9-3 施工时决定，但 R9-2 方案必须明确：**模式不是启动后写死。**

## 6. Auto 模式代理审核机制

R9-2 必须明确 Auto 模式中的“替用户审核 Agent”是什么。

### 6.1 Auto 授权代理范围

Auto 模式可由 Auto Review / Authorization / Safety Agent 或等价 Skill/Role 代用户处理：

1. 阶段内低/中风险 Gate。
2. L0-L3 动作授权。
3. 阶段内写盘、读取、识别、建档、Artifact 生成等可审计操作。
4. Review Pass 后的阶段内返工确认。

### 6.2 Auto 授权代理不得处理

1. P0→P1 阶段 Gate。
2. P1→P2 阶段 Gate。
3. L4+ 高风险动作。
4. 达到最大返工轮数后的人工介入。
5. 敏感信息泄露疑似项。
6. 用户明确要求人工确认的项。
7. R 阶段验收 accepted 裁决。

### 6.3 Auto 授权输出

必须生成结构化记录：

- decision: approved / rejected / escalate_to_human
- reason
- risk_level
- evidence_refs
- trace_refs
- audit_ref
- mode: auto
- reviewer: auto_authorization_agent 或 review_skill 标识
