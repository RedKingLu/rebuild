## 4. P0/P1 小循环机制

### 4.1 小循环基本形态（D-020 约束）

每个阶段内部遵循标准 NodeLoop：

```text
读取 / 收集上下文（Context Assembly）
  → 识别 / 分析（Skill 执行）
  → 制定阶段内小计划（Plan 生成）
  → 执行（Tool 调用 + Skill 执行）
  → Review Pass（自验证 + Auto Review Skill 评审）
  → 若不合格 → 返工循环（最多 N 轮）
  → 若达到最大轮数或高风险 → 人工 Gate
  → 若合格 → 阶段 Gate（强制用户确认）
```

### 4.2 P0 接入小循环

```text
┌─────────────────────────────────────────────────────┐
│ P0 小循环（最多 2 轮自动/半自动返工）                 │
│                                                       │
│  [读] Context Assembly                                │
│   → Project + source_config + Workspace 状态          │
│   → Environment Profile + ModelGateway + CodingAgent  │
│                                                       │
│  [识] source materialization                          │
│   → 根据 source_type 执行导入                         │
│   → 生成 source_index                                 │
│   → 验证导入完整性                                    │
│                                                       │
│  [计划] 生成 P0 小计划                                │
│   → 确认导入策略 + 异常处理策略                        │
│                                                       │
│  [执行]                                               │
│   → Skill: P-codebase-onboarding                     │
│   → Tool: 文件树 / 文件读取 / Environment Profile API │
│   → 写入 Trace / Audit                                │
│                                                       │
│  [Review] Review Pass (Auto Review Skill)             │
│   → 检查：source_index 完整性、导入异常、             │
│            Environment Profile 一致性、密钥泄露        │
│                                                       │
│  [返工] 不合格 → 修正 → 再 Review（最多 2 轮）        │
│  [Gate] 2 轮后仍不合格 → 人工 Gate                    │
│  [Gate] 合格 → P0→P1 阶段 Gate（强制用户确认）        │
└─────────────────────────────────────────────────────┘
```

**P0 小循环关键参数**：

| 参数 | 值 | 说明 |
|------|-----|------|
| 最大自动返工轮数 | 2 | 第 1 轮发现问题自动修正；第 2 轮仍不合格 → 人工 Gate |
| 每轮上下文 | P0 Context Package（§6.1） | 每轮开始重新组装 |
| 执行者 | Node Worker Agent + P0 Skills | 同一 Agent，不同 Skill |
| Reviewer | Auto Review Skill | 同一 Agent 进入 Review Pass（不切换 Agent） |
| 人工 Gate 触发 | 2 轮返工后仍不合格 / L4+ 风险 / 密钥疑似泄露 | 强制停止自动循环 |
| 阶段 Gate | P0→P1 promotion Gate | 强制用户确认（D-023），所有模式适用 |

## 5. Agent / Skill / Role / Review Pass 设计

### 5.1 最少 Agent 集合（基于 D-019）

**R9 范围仅使用 5 种 Agent 类型中的 3 种**：

| Agent 类型 | R9 用途 | 具体角色 |
|-----------|---------|---------|
| **Node Worker Agent** | P0/P1 主执行 | 调用 P0/P1 Skill 执行接入、识别、建档；同一 Agent 切换 Skill 完成不同阶段 |
| **Auto Review / Authorization / Safety Agent** | Review Pass | 评审 P0/P1 产物；验证安全性（密钥泄露检查）；Gate 前自动评审 |
| **Conversation / Gate Agent** | 用户交互与 Gate | 处理向导对话；Gate 展示与决策路由；人工介入交互 |

**不在 R9 使用的 2 种**：
- **Acceptance Agent**：独立验收归 R9-4，R9-3A~D 施工阶段不调用
- **Expert Agent**：R9 范围内无需专家能力（全量识别由 Node Worker + P1 Skills 完成）

### 5.4 上下文组装时的 Skill 过滤规则

**核心规则**：每个阶段的上下文只导入该阶段的 Skill + Common Skill。其他阶段 Skill 不使用。

| 阶段 | 导入 Skill 分类 | 排除 |
|------|----------------|------|
| P0 | `category = "common"` + `category = "p0"` | p1/p2/p3/p4/p5/p6 |
| P1 | `category = "common"` + `category = "p1"` | p0/p2/p3/p4/p5/p6 |
| P2 | `category = "common"` + `category = "p2"` | p0/p1/p3/p4/p5/p6 |
| … | … | … |

**实现方式**：在 Context Assembly 时，根据当前阶段 `current_stage`（如 `"p0"`）过滤 `SkillDefinition` 表：
```python
skills = db.query(SkillDefinition).filter(
    SkillDefinition.category.in_(["common", current_stage]),
    SkillDefinition.series == "P",
    SkillDefinition.status == "active"
).all()
```

### 5.5 Review Pass 机制

**Review Pass 不是独立 Agent**。是同一 Node Worker Agent 加载 Review Skill 完成。

```
执行完成 → Node Worker Agent 加载 Auto Review Skill
  → 评审 P0/P1 产物
  → 输出 ReviewResult { passed: bool, issues: [...], recommendations: [...] }
  → 若 passed=true → 进入阶段 Gate
  → 若 passed=false → 判断返工轮数
    → 未达最大轮数 → 修正 issues → 重新执行 → 再 Review
    → 已达最大轮数 → 触发人工 Gate
```

**何时切换独立 Agent**（仅以下条件，D-017）：
- 需要独立验收（R9-4 验收阶段 → Acceptance Agent）
- 高风险决策（L4+ → Auto Review / Authorization Agent 独立评审）
- 并行任务隔离（P0 和 P1 同时有独立子任务时）

  # 已有 Trace/Audit 摘要（最近 10 条）

  recent_audits: [...]
  
  # 已有 Evidence Gap（P0 开始应为空或仅有 R8 遗留）

  # 用户输入（向导中收集）

    - env_kind_declared

## 7. Tool 使用方案

### 7.1 P0 Tool 调用

| Tool | API | 用途 | 失败处理 |
|------|-----|------|---------|
| 文件树读取 | `GET /files` | 扫描 source/ 目录结构 | 重试 1 次；仍失败 → Evidence Gap |
| 文件读取 | `GET /file?path=` | 读取源码/配置文件 | 二进制文件跳过；权限不足 → Evidence Gap |
| 文件写入 | `PUT /file` | 写入 materials/（用户编辑） | 重试 1 次；仍失败 → 人工 Gate |
| 终端执行（local） | `POST /execute` | Git clone、ZIP 解压等导入操作 | 失败 → Evidence Gap + 人工 Gate |
| Environment Profile 读 | `GET /environment` | 读取当前环境声明 | 重试 1 次 |
| Environment Profile 写 | `PUT /environment` | 更新语言/框架/环境类型 | 重试 1 次 |
| Trace 写入 | TraceWriter | 记录每步动作 | 静默失败（不阻塞主流程） |
| Audit 写入 | AuditWriter | 记录高风险动作 | 失败 → 人工 Gate（L3+） |

### 7.2 P1 Tool 调用

| Tool | API | 用途 | 失败处理 |
|------|-----|------|---------|
| 文件树读取 | `GET /files` | 全量目录扫描 | 重试 1 次；仍失败 → Evidence Gap |
| 文件读取 | `GET /file?path=` | 读取构建文件/配置文件/依赖文件/README | 敏感文件脱敏读取 |
| AET Artifact 写入 | AET API | 生成档案/技术栈/依赖等 Artifact | 重试 1 次 |
| AET Evidence 写入 | AET API | 生成 Evidence candidates + Gaps | 重试 1 次 |
| Environment Profile 更新 | `PUT /environment` | 更新自动检测结果 | 重试 1 次 |
| Trace/Audit 写入 | TraceWriter/AuditWriter | 记录识别过程 | 同 P0 |

### 7.3 Tool 调用原则
- 所有 Tool 调用前做风险分级（L0-L5）
- L3+ Tool 调用写 Audit
- Tool 失败不静默吞掉——写入 Evidence Gap 或触发 Gate
- Tool 调用序列写入 Trace（含参数摘要、返回值摘要、耗时）

## 9. 三模式真实机制

### 9.1 保存位置与生命周期

| 字段 | 位置 | 何时写入 | 何时可改 |
|------|------|---------|---------|
| `execution_mode` | `Run.execution_mode`（DB） | Run 创建时（向导第 4 步或默认 plan） | Run 未启动时可改；Run 启动后锁定 |
| 前端展示 | `useWorkspaceStore.execMode` | 从 Run 读取初始化 | 切换时 PATCH Run（若 Run 未启动） |

### 9.2 切换规则
- 向导阶段：用户可以随时切换模式（写 DB）
- Run 启动后：模式锁定，不可切换（防止执行中模式不一致）
- 新 Run：可以重新选择模式

### 9.3 三模式在小循环中的差异

| 维度 | Manual | Plan | Auto |
|------|--------|------|------|
| **P0 向导** | 每步确认 | 可跳至摘要 | 可完全跳过 |
| **阶段内小计划** | 用户逐项审核 | Agent 生成计划，用户审核一次 | Agent 自动生成并执行 |
| **每轮执行前** | 用户确认 | 计划内自动，越界回用户 | 低风险自动 |
| **Review Pass** | 强制（每轮） | 强制（每轮） | 强制（每轮） |
| **返工循环** | 每轮执行前需用户确认 | 计划内自动修正，最多 2 轮 | 自动修正，最多 2 轮 |
| **L4+ 风险动作** | 强制用户 Gate（不可自动） | 强制用户 Gate | 强制用户 Gate |
| **阶段晋级 Gate** | **强制用户确认** | **强制用户确认** | **强制用户确认** |
| **最大返工轮数** | 2（每轮用户确认） | 2（自动执行） | 2（自动执行） |
| **失败回退** | 用户决定 | 自动回退到上轮状态 | 自动回退到上轮状态 |

### 9.4 Auto 模式的安全边界
- Auto **不能**绕过 P0→P1 / P1→P2 阶段 Gate（D-023）
- Auto **不能**自动执行 L4+ 风险动作（D-034）
- Auto **不能**跳过 Review Pass
- Auto **不能**在 Review 失败后继续推进——必须返工或人工 Gate
- Auto 可以：跳过向导、自动生成小计划、自动执行 L0-L3 识别动作、自动修正 Review 发现的问题

### 9.5 三模式 Trace/Audit 密度

| 动作风险 | Manual | Plan | Auto |
|---------|--------|------|------|
| L0-L1（只读） | Trace | Trace | Trace |
| L2（受控执行） | Trace + Audit | Trace + Audit | Trace + Audit |
| L3（外部影响） | Trace + Audit | Trace + Audit | Trace + Audit |
| L4（高风险） | Gate + Audit | Gate + Audit | Gate + Audit |
| 阶段晋级 | Gate + Audit | Gate + Audit | Gate + Audit |
