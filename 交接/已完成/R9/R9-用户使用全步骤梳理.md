## 阶段 1：绑定 Git 账号

### 步骤 1.1：点击左侧导航「集成」
- URL → `/integrations`
- 进入 `IntegrationsPage.tsx`，Tab 默认选中「Git」

### 步骤 1.2：点击「连接 GitHub」按钮
- 触发 `handleConnectGithub()`（IntegrationsPage.tsx:87）
- 请求 `GET /api/integrations/git/oauth/github/authorize` 获取 GitHub OAuth URL
- `git_oauth_service.py::get_github_authorize_url()` 返回 `https://github.com/login/oauth/authorize?client_id=...`

### 步骤 1.3：弹窗中完成 GitHub 授权
- 新窗口打开 GitHub 授权页
- 用户登录 GitHub，点击「Authorize」
- GitHub 回调 `GET /api/integrations/git/oauth/github/callback?code=...`
- 后端 `exchange_github_code(code)` 换 access_token
- `GitAccountService.create_account()` 将账号信息写入 SQLite DB
- 后端重定向到 `{frontend_url}/integrations?oauth=github&status=connected&user=RedKingLu`

### 步骤 1.4：弹窗关闭，主窗口自动刷新
- 弹窗内 `useEffect` 检测到 `oauth=github&status=connected`
- 通过 `window.opener.postMessage({type:'github-oauth-connected'})` 通知主窗口
- 弹窗 `window.close()` 关闭自己
- 主窗口收到消息，自动调用 `fetchAccounts()` 刷新列表

### 步骤 1.5：查看已绑定账号
- 「已绑定账号」区域显示 GitHub 头像 + 用户名 + 平台标签 + 状态「已连接」
- 点击账号行展开仓库列表（`handleSelectAccount`）
- 调用 `GET /api/integrations/git/accounts/{id}/repos`，`fetch_github_repos()` 从 GitHub API 获取仓库

**当前状态**：✅ 刚修复了弹窗关闭后主窗口不刷新的问题

## 阶段 2: 配置模型服务商

### 步骤 2.1：点击左侧导航「模型」
- URL → `/models`
- 进入 `ModelsPage.tsx`
- 上方统计卡片：供应商数 / 模型数 / 策略数 / 调用数
- 默认 Tab：「服务商」

### 步骤 2.2：点击右上角「+ 添加供应商」按钮
- 触发 `setShowAdd(true)`（ModelsPage.tsx:167）
- 弹出 `AddProviderModal.tsx` 浮窗（`position:fixed` overlay + card）

### 步骤 2.3：选择预置模板或手动填写
- 预置按钮：DeepSeek / 火山引擎 / 百度文心 / 阿里通义 / Claude 官方 / 自定义
- 点击预置按钮自动填充：provider_id、endpoint、API 格式

### 步骤 2.4：填写服务商信息
- **供应商名称**（必填）：例如 "DeepSeek"
- **备注**（选填）
- **官网链接**（选填）
- **API 格式**：`openai` 或 `anthropic` 下拉选择
- **请求地址 Endpoint**（必填）：例如 `https://api.deepseek.com/v1`
- **认证环境变量名**：留空则按 `{PROVIDER}_API_KEY` 生成（例如 `DEEPSEEK_API_KEY`）
- **API Key**：密码输入框，仅存后端进程内存，不落盘

### 步骤 2.5：添加模型列表
- **模型名称**：例如 `deepseek-chat`
- **显示名**：例如 `DeepSeek Chat V3`
- 可添加多个模型行，点击 `+ 添加模型` 增加
- 点击 `✕` 删除模型行

### 步骤 2.6：点击「+ 添加」提交
- `handleSubmit()` → `POST /api/models/providers`
- 后端 `ModelGateway` 注册服务商和模型
- 浮窗关闭，服务商列表自动刷新

### 步骤 2.7：验证模型连通性
- 点击服务商行的「自检」按钮
- `handleSelfTest(providerId)` → `POST /api/models/{providerId}/self-test`
- 显示测试结果：通过 ✓ / 失败 ✗ + 错误信息

**当前状态**：✅ 可用（R5 已验证）。如果用户已在 `backend/.env` 中配置了 `DEEPSEEK_API_KEY`，自检应通过。

## 阶段 4：P0 接入（Workspace + 浮窗引导）

### 步骤 4.1：进入 Workspace
- URL → `/projects/{id}/workspace`
- `WorkspacePage.tsx` 加载
- 顶部状态栏：返回平台、项目名、P0-P6 节点轨、Gate/阶段 chip、模型网关 chip、**ExecMode 切换**、编程 Agent 选择器、主题切换
- 左侧活动栏：Stage / Files / Materials / Git / Remote / Search / Agent
- 右侧检视面板（折叠）：Gate / Evidence / Trace / Audit / Context / Resource / Model

### 步骤 4.2：浮窗引导自动弹出
- `!project.onboarding_done && !onbDismissed` → 渲染 `<Modal><OnboardingWizard/></Modal>`
- 半透明遮罩，居中白色卡片，右上角 ✕ 可关闭跳过

### 步骤 4.3：引导第 1 步「环境选择」
- **运行环境**：🏠 本地环境 / 🌐 远程环境（二选一按钮）
- **主要语言**（可选输入框）：例如 "Python"
- **框架提示**（可选输入框）：例如 "FastAPI"
- 底部「下一步」按钮 → `handleStep1Next()`
- 调 `PUT /api/projects/{id}/environment` 写入 Environment Profile

### 步骤 4.4：引导第 2 步「提交方式」
- 只读显示项目来源类型：`本地目录` / `Git 仓库` / `GitHub` / `ZIP 上传` / `手动创建`
- 如果已配置 Git：✅ 显示已配置标签
- 如果未配置：提示「可在项目设置中配置 Git 集成」
- 底部「下一步」

### 步骤 4.5：引导第 3 步「模型配置」
- 加载模型网关状态：`GET /api/model/status`
- 显示网关状态：可用 ✓（绿色）/ 不可达（琥珀色）
- 使用全局默认模型配置
- 底部「下一步」

### 步骤 4.6：引导第 4 步「执行模式」
- 三选一卡片：
  - **手动**：用户审核每步动作和授权，最高控制力
  - **计划确认**：用户审核阶段计划，计划内动作自动执行（推荐）
  - **自动**：低风险动作自动，高风险回用户确认
- 底部「下一步」

### 步骤 4.7：引导第 5 步「摘要确认」
- 显示前 4 步选择的摘要：
  - ✓ 环境：本地环境 · Python · FastAPI
  - ✓ 来源：本地目录
  - ✓ 模型：全局默认
  - ✓ 模式：计划确认
- 底部「确认并进入工作区」→ `handleFinalize()`

### 步骤 4.8：引导提交（后端执行）
- 前端调 `POST /api/projects/{id}/onboarding/complete`
- 后端执行：
  1. 更新 Environment Profile
  2. 设 `project.onboarding_done = true`
  3. 创建 P0 Run
  4. 写入 `intake_report.json`
  5. 生成 Evidence candidates
  6. **Source Materialization**：调用 `SourceMaterializer.materialize()` → 实际导入源码到 `workspace/source/`
  7. 生成 source_index.json
  8. Review Pass 执行
  9. 生成 4 个 Gate 附审材料（execution_record / construction_report / review_pass / intake_report）
  10. **不创建 Gate**（由 Agent 执行创建）
- 返回 Run ID + artifacts + materialized 结果

### 步骤 4.9：Agent 驱动 P0 执行
- 前端调 `POST /api/projects/{id}/onboarding/execute`（SSE）
- SSE 事件流实时推送到 Agent 对话区：
  - `source_check`："源码导入完成：30 个文件"
  - `artifact_check`："P0 产物齐全：4/4"
  - `review`："Agent Review Pass 通过 ✓"
  - `gate_creation`："正在创建 P0→P1 Gate 并附审核材料…"
  - `complete`："P0 接入执行完成。Gate 已创建。"

### 步骤 4.10：Gate 横幅出现
- 工作区中央出现琥珀色 Gate 横幅：
  - "⚠ 阶段晋级 Gate"
  - "项目已完成 P0 接入：30 个源码文件已导入，4 项产物已生成，Review 通过。请审阅附审材料后做出决策。"
  - "点击查看审核材料 →"

**当前状态**：✅ 引导流程可用。⚠️ Agent execute 的 SSE 目前未实时显示在前端 AgentChat 中（前端只是调了 `/onboarding/execute` 但不消费 SSE 流）。需要修复前端。

## 阶段 5：Gate 审核——批准 P0→P1

### 步骤 5.1：点击 Gate 横幅
- `GatePanel.tsx` 的 `onClick={() => setExpanded(true)}`
- 展开为 Modal（800px 宽，左右两栏）

### 步骤 5.2：审阅附审材料
- 左栏材料列表（4 项，可点击切换）：
  - **阶段计划**（intake_report.json）  → 点击→ 右栏 JSON 格式化预览
  - **执行记录**（p0_execution_record.json） → 点击→ 7 步操作摘要
  - **施工报告**（p0_construction_report.md） → 点击→ Markdown 渲染
  - **Review 报告**（p0_review_pass.json） → 点击→ passed/issues/recommendations

### 步骤 5.3：点击「批准」按钮
- `GatePanel.tsx:handleDecision('approve')`
- 调 `POST /api/projects/{id}/runs/{rid}/stages/p0/promotion-decision`
  → `{"decision":"approve"}`
- 后端 `gate_service.decide()`：
  - Gate 状态 → `approved`
  - Project `current_stage` → `p1`
  - Run `stage_status["p0"]` → `completed`, `["p1"]` → `in_progress`
  - 写 Audit
- GatePanel 检测到 `stage === 'p0'` 且 `decision === 'approve'` → 自动调 `POST /api/projects/{id}/profile`

### 步骤 5.4：P1 全量识别开始
- GatePanel 显示："⏳ P1 全量识别进行中…"
- 后端 `FullStackProfiler.profile()` 执行：
  - 14 项全量识别（file_index → source_structure → module_structure → tech_stack → dependency_draft → entry_points → test_inventory → cicd_inventory → infra_clues → config_inventory → doc_inventory → uncertainty_manifest）
  - 生成 13 个 JSON artifact + profiling_summary.md + p2_input_manifest.json
  - Review Pass 执行
  - 创建 P1→P2 Gate（附 4 项材料）
- GatePanel 显示："P1 全量识别完成。"

### 步骤 5.5：P1→P2 Gate 横幅出现
- 工作区 Gate 横幅更新：
  - "⚠ 阶段晋级 Gate"
  - "全量识别完成：12 项产出，N 个待确认项。请审阅附审材料后做出决策。"
- NodeRail P0 变绿（completed），P1 变蓝（in_progress）

**当前状态**：⚠️ GatePanel 批准后自动调 P1 profiling 存在但前端 UI 等待体验不流畅——`profiling` loading 状态在 GatePanel Modal 内，用户看不到 Agent 对话区。
