## 3. 必须修正的理解：少 Agent、多 Skill

上一轮审核中提到“换 Agent 评审/验收”，容易被误解成每个环节都拆独立 Agent。这里必须修正。

### 3.1 正确原则

R9 的 P0/P1 小循环应采用：

- 少量常驻 Agent / 同一执行 Agent；
- 通过不同 Skill、Role、Mode、Review Pass 切换工作环节；
- 必要时才切换独立 Agent；
- 评审可以是同一 Agent 进入 Review Skill / Review Pass，也可以在高风险或关键 Gate 前调用独立验收 Agent；
- 不为“读取、识别、规划、执行、评审、验收”分别固定创建大量 Agent。

### 3.2 需要设计的对象

R9-1R 必须定义以下内容，而不是简单说“换 Agent”：

1. 最少 Agent 集合建议。
2. P0 使用哪些 Skill。
3. P1 使用哪些 Skill。
4. Review / 验收如何作为 Skill 或独立 Agent 执行。
5. 哪些条件触发干净上下文或独立 Agent。
6. 上下文如何组装给 Skill。
7. Skill 输出如何变成 Artifact / Evidence / Trace / Audit。
8. Tool 调用如何登记并进入返工循环。

### 3.3 推荐初始设计方向

仅作为建议，需由本地 Agent 核查事实源后确认：

- 一个主执行 Agent：负责 P0/P1 的执行、状态推进和工具调用。
- 一个 Review Skill：用于阶段内评审，不一定换 Agent。
- 一个 Gate / 用户确认机制：用于阶段晋级和最大轮数后人工介入。
- 独立验收 Agent：只在 R9-4 或关键返工评审中使用。
- P0 Skill：接入确认、source materialization、环境确认、向导处理。
- P1 Skill：项目识别、建档、Evidence Gap 生成、P2 输入包生成。
- Common Skill：上下文组装、Artifact/Evidence 写入、Trace/Audit、风险分级。
