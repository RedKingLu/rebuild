## 4. P1 重要问题修复计划

### R10-5-P1-001：/workspace 聚合端点 500
- 问题：真实源项目过 P1（uncertainty_manifest.json 含 evidence_gaps，如 framework_unknown）后，`GET /api/projects/{pid}/workspace` 返回 500，工作区头部恒入"离线模式"。
- 复现步骤：git 源项目 → onboarding → 批准 P0→P1 → 浏览器打开 `/projects/{pid}/workspace` → console 2×500，Network `/workspace`→500。
- 证据：后端 `pydantic_core.ValidationError: 2 validation errors for WorkspaceAggregateResponse: pending_evidence_gaps.0.gap_id [missing]; .evidence_type [missing]`；`/tmp/r104_backend.log`。
- 影响：所有真实源项目工作区聚合不可用（前端降级离线）；P1/P2/P3 页仍可单独渲染但头部状态失真。
- 根因初判：`app/services/aet_service.py:155-160` `list_evidence_gaps` 产 `{evidence_id, summary, type, item}`，与 `app/schemas/aet.py:63 EvidenceGapResponse`（要求 `gap_id`+`evidence_type` 无默认）字段不一致；`WorkspaceAggregateResponse.pending_evidence_gaps: list[EvidenceGapResponse]`（`app/schemas/workspace.py:32`）校验失败。
- 建议修改文件：`app/services/aet_service.py`（映射为 `gap_id`/`evidence_type`/`description`/`blocking`/`stage`）或 `app/schemas/aet.py`（EvidenceGapResponse 字段设默认/别名对齐生产者）——二选一并保证前端 evidence-gaps 消费端同步。
- 修复方式建议：统一 gap DTO：`gap_id=f"gap-{item}-{i}"、evidence_type=g.type、description=g.detail、blocking、stage`；保留前端所需字段。加 `tests/test_workspace_aggregate.py`：source 项目过 P1 后 `/workspace` 200 且 pending_evidence_gaps 结构合法。
- 验证方法：浏览器复跑 `/workspace` 200、0 console error；pytest 新增用例绿。
- 是否需要用户确认：否（schema 对齐，非架构变更）。

### R10-5-P1-002：/promotion-decision 非法 decision 不校验 + 重复 Gate
- 问题：`POST .../stages/{stage}/promotion-decision` 接受任意 decision 值，非法值返回 HTTP 200 且 resume 图导致创建重复 stage_promotion Gate。
- 复现步骤：新建项目→onboarding→`promotion-decision {"decision":"badvalue"}`→HTTP 200；查 `/gates` 出现第 2 条 waiting_decision P0 Gate。
- 证据：R10-4 §12；neg2 项目 complete+1 非法决策=2 gates；`/gates/{id}/decision` 对照返回 400。
- 影响：负路径 S6.5 失败；Gate 状态被污染（重复 Gate）；前端 GatePanel（用此端点）对非法值无清晰错误。
- 根因初判：`app/api/routes_stages.py:62 decide_promotion` 未校验 `req.decision ∈ {approve,reject,request_changes}` 即 `get_flow_runtime().resume(run_id, req.decision)`；图对未知 decision 未拒绝而重建 Gate。
- 建议修改文件：`app/api/routes_stages.py`（decide_promotion 入口校验，非法→HTTPException 400，镜像 routes_gates）；可选 `app/graph/*gate*`（gate 节点对未知 decision 拒绝/不重建）。
- 修复方式建议：入口白名单校验 400；并加 resume 前置守卫避免非法 decision 产生副作用。加 `tests/`：promotion-decision 非法值→400 且 gate 数不变、stage 不推进。
- 验证方法：复跑负路径非法值→400、gate 数不变；pytest 绿。
- 是否需要用户确认：否。

### R10-5-P1-003：P2/P3 未接 context_assembler / 未使用 Skill（S4）
- 问题：RealP2Handler/RealP3Handler.execute 及 assessment_service/planning_service 未调用 `assemble_context`，未加载/引用任何 Skill；使用硬编码 system prompt + ad-hoc `_gather_inputs`。违反 S4 与 R10-2 §1.1 T7 意图。
- 复现步骤：读 `app/graph/stage_handlers.py`（P2:210/P3:319 无 assemble_context，对比 P0:61/P1:141）；`grep skill|resource_loader` 于 assessment_service/planning_service 零命中；`tests/test_context_p2p3.py` 仅孤立测 assembler。
- 证据：R10-4 §7/§13；代码 grep。
- 影响：P2/P3 模型调用缺 C0-C6 统一上下文与 C5 Skill 层；能力契约不一致（产物虽真实，但非经设计路径）。
- 根因初判：T7 交付止于"assembler 支持 p2/p3 + 孤立测试"，未把 assemble_context/build_system_prompt 接入 handler execute。
- 建议修改文件：`app/graph/stage_handlers.py`（RealP2/P3Handler.execute 调 `assemble_context(project_id, stage, node_state=...)` 并将 C5 Skill 层 + 上下文注入 assessment_service/planning_service 的 system prompt，或改用 `build_system_prompt(ctx)`）；`assessment_service.py`/`planning_service.py`（接收 context_package/system_prompt 参数，替换硬编码常量为"Skill 内容 + 阶段模板"组合）。
- **Skill 注入口径（用户 2026-07-02 裁决，已确认）**：**必须与 Skill 使用准则一致——采用渐进式披露（progressive disclosure）**。即：
  1. 组装上下文/系统提示时，C5 层**只加载 Skill 的 name + description 等元数据（摘要）**，不得一次性灌入 Skill 全文（SKILL.md body / references）。
  2. Skill 全文/引用资源**按需逐步披露**——在 tool_loop 中当 Agent 判断需要该 Skill 时，再经工具（如 skill 读取/resource_loader）加载完整内容。
  3. 与平台既有 Skill 体系（`资源`/`平台资源/skills`）加载准则一致，复用现有 skill/resource_loader 机制，不另造一套。
  4. P2 载入 P2 评估相关 Skill 元数据、P3 载入 P3 规划/TaskGraph 相关 Skill 元数据；Skill 缺失/加载失败须发声（不静默）。
- 修复方式建议：execute 内先 `assemble_context` → `build_system_prompt`（C5 仅含 Skill 元数据摘要）→ 传入服务；服务保留结构化 user prompt；全文披露走按需工具调用。加集成测试断言 handler 实际调用 assemble_context 且 system prompt 含对应 Skill **元数据**（如 P2 "评估可行性" skill 的 description），并断言未整包注入全文。
- 验证方法：Trace/日志含 context assembly + skill_refs（元数据级）；测试断言 handler 调用；真实 P2/P3 产物 context_refs/skill_refs 非空。
- 是否需要用户确认：**已确认（渐进式披露口径，见上）**。
