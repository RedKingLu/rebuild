2. P2 输入包缺失或损坏：
   - P2 应 blocked / failed / waiting_input。
   - 不得继续进入 P3。

3. TaskGraph 边策略缺失：
   - P3 应失败或返工。
   - 不得入库一个不完整 TaskGraph。

4. 重复触发 P2/P3：
   - 应幂等或生成新版本链。

   - 不得破坏已有 Gate 状态。

5. Gate 非法 decision：
   - 应返回错误。
   - Gate 状态不得被非法推进。

6. 浏览器刷新 / 后端重启后：
   - P2/P3 产物、Gate、Evidence、Trace 应能恢复。
   - 不得只存在内存。

## 8. 验收分级标准

### 8.1 accepted

只有同时满足以下条件，才可判 accepted：

- 浏览器端到端 S1 主路径通过。
- 真实源码接入成立，至少一种真实 clone 或明确可验证源码导入路径成立。
- P0/P1 已 accepted 链路未被破坏。
- P2 真实执行并产出有意义的六类评估产物。
- P3 真实执行并产出 StagePlan / TaskPlan / TaskGraph。
- TaskGraph 必生，边策略显式。
- NodeLoop 与 Acceptance 有真实执行证据。
- ModelGateway 调用真实发生。
- Agent 上下文组装与 Skill 使用有证据。
- P2→P3、P3→P4 Gate 可展开查看真实附审材料。
- P4 保持 R11 stub，不越界执行 P4。
- pytest 全绿。
- 前端 build 成功。
- 浏览器 0 阻断性 console error。
- Evidence / Trace / Audit / Artifact 可索引、内容真实。
- 进度追踪更新完整。

### 8.2 conditional_pass / 有条件通过

仅当问题不阻断主链路，且不涉及假实现，可给有条件通过。例如：

- UI 展示小问题。
- 个别非关键文案错误。
- 追踪材料有轻微遗漏但不影响主链路实证。
- 非关键浏览器样式问题。
- 非 R10 范围的历史债务已登记且不影响 P2/P3 真实链路。

### 8.3 rework_required

出现任一情况，应判 rework_required：

- 浏览器无法从创建项目走到 P2/P3。
- P0/P1 被 R10-3 破坏。
- Git clone 或源码导入未真实验证，却声称通过。
- P2/P3 仍是 stub 或只是静态页面。
- P2/P3 产物为空、占位、模板化、无项目事实。
- P3 未生成 TaskGraph。
- TaskGraph 边策略缺失。
- P2 无 Key 时规则降级冒充成功。
- ModelGateway 未被使用或被绕过。
- Agent 未真实组装上下文或未使用对应 Skill。
- Gate 无附审材料或材料为空壳。
- Evidence 为空或不可追溯。
- pytest/build 虽通过但真实前端链路失败。
- 出现密钥泄露风险。
- P4 在 R10 被半实现或真实执行，越界 R11。

### 8.4 blocked

如果因环境缺失无法验收，例如：

- 无可用测试仓库且无法验证 Git clone。
- 无可用模型配置且 P2 必须 blocked。
- 服务无法启动。
- R10-3 施工材料缺失。
- 必要凭据无法提供，且无替代路径。

应判 blocked，并列清：

- 阻塞原因。
- 需要用户或施工 Agent 提供什么。
- 哪些验证已完成，哪些无法完成。
- 不得把未测项写成通过。
