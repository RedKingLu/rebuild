## 1. 通用输出模板

每轮输出使用以下结构：

```markdown
## 本轮任务

## 当前阶段判断

## 已读取事实源

## 事实 / 推断 / 建议

### 事实
（来自已读取文件、代码、目录或用户明确裁决）

### 推断
（基于事实的判断，标注不确定性）

### 建议
（处理方案，说明理由和风险）

## 执行计划

## 已完成内容

## 写入路径

## 待确认项

## 风险

## 下一步建议
```

如果生成文件，必须附加身份信息：

```
文件路径：
文件身份：草稿 / 正式候选 / 交接材料 / 证据 / 产物
审核状态：
下一步处理方式：
```

## 5. 文档正式化系列模板

### 5.1 是否应具备判断

```markdown
## 是否应具备判断

文档路径：
结论：是 / 否 / 需要合并 / 需要拆分 / 需要改名
理由：
依据事实源：
风险：
是否需要用户确认：是 / 否
```

> 若结论为"否 / 需要合并 / 需要拆分 / 需要改名"，必须停止并等待用户确认。

### 5.2 应具备内容定义

```markdown
## 应具备内容定义

文档目标：
读者对象：
必备章节：
必备决策引用：
必备术语：
必备约束：
必须避免的内容：
验收标准：
需要本地事实源补充的内容：
```

### 5.3 草稿检查

```markdown
## 草稿检查结果

草稿路径：
检查时间：

### 满足项
-

### 缺失项
-

### 错误项
-

### 需要本地补充项
-

### 是否可进入完善
结论：是 / 否
理由：
```

**检查维度**（至少覆盖）：

- 是否符合 rebuild 当前定位
- 是否错误使用版本号作为平台名称
- 是否混用 P 阶段和 R 阶段
- 是否过多展开旧版本
- 是否遗漏关键决策引用
- 是否遗漏前端/工作区/Gate/Agent/Skill/模型/资源/安全/API/验收等必要内容
- 是否有不确定项未登记
- 是否存在凭空结论
- 是否需要本地路径或代码事实源补充
- 是否符合"基本可用"而非占位

### 5.4 完善计划

```markdown
## 完善计划

准备保留：
准备删除：
准备新增：
准备合并：
准备改写：
需要引用的当前决策：
需要引用的历史参考：
待用户确认项：
正式候选写入路径：

```

> 如存在待用户确认项，必须先停止。

## 6. 交接材料模板

### 6.1 交接提示词结构

```markdown
# <阶段> — 新窗口 Agent 交接提示词

> 文件路径：`交接/当前/<文件名>.md`
> 文件身份：交接材料
> 生成时间：<YYYY-MM-DD>
> 处理人 / Agent：<名称>
> 目标受众：接手 <阶段> 的新窗口 Agent
> 审核状态：待用户审核

## 0. Agent 启动自检

## 1. 项目背景
（平台名称、版本、产品定位、技术栈硬约束）

## 2. 当前阶段定义
（阶段名称、目标、依赖、在 R 序列中的位置）

## 3. 当前裁决
（关联决策编号和速查摘要）

## 4. 事实源路径
（五层必读清单，含具体路径和读取目的）

## 5. 任务目标
（P0/P1 分优先级列出）

## 6. 执行边界
（三步法要求、允许/禁止事项、范围外清单）

## 7. 输入资料
（必须读取的材料清单）

## 8. 输出要求
（产出清单，含文件身份和写入位置）

## 9. 禁止事项
（引用 AGENTS.md §10 + 本阶段特有禁止项）

## 10. 验收标准
（checkbox 清单）

## 11. 风险与待确认项

## 12. 下一步建议
```

> **精简原则**：交接材料应避免复制 AGENTS.md / Skill 中已有的通用规则（如通用禁止事项、安全规则、执行流程）。只写本阶段特有裁决、边界、输出和风险，通用规则以引用方式指向 AGENTS.md 与 Skill（如"安全规则见 AGENTS.md §8"、"施工三步法见 AGENTS.md §7.1"）。

### 6.2 交接材料自检清单

```
□ 是否写明项目背景？
□ 是否写明当前阶段？
□ 是否写明当前裁决？
□ 是否写明事实源路径（含具体路径，非"参见某文档"）？
□ 是否写明任务目标（区分 P0/P1）？
□ 是否写明执行边界（含范围外清单）？
□ 是否写明输入和输出要求？
□ 是否写明禁止事项（引用 AGENTS.md）？
□ 是否写明验收标准（可验证的 checkbox）？
□ 是否列出待确认项？
□ 是否避免密钥泄露？
□ 是否自包含（新 Agent 不依赖旧窗口记忆）？
```
