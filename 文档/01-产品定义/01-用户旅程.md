
## 1. 用户画像

### 1.1 当前第一用户 [已确认]

**单人开发者 / 技术负责人 / 产品负责人**，使用 rebuild 与 Agent 协作完成软件重构与迁移。

核心诉求：

```text
1. 导入项目 → 看到清晰阶段进展 → 审批关键节点 → 验证结果 → 交付
2. 退出工作区后能恢复，不被假完成误导
3. 知道在用谁的资源（自己的 / 平台本地 / 在线社区）
4. 知道在用哪个模型（Fusion 只是可选模型之一）
```

### 1.2 非目标（首期不优先）

无源代码咨询、泛项目管理、通用 Agent 展示、无人自治、默认远程高风险写操作、复杂多租户。

## 3. 工作区心智模型

工作区是用户的核心操作空间——独立全屏 IDE 心智，从项目/概览进入，可返回平台。

### 3.1 布局原则 [已确认]

```text
中央区域   — Agent 对话 Tab 常驻不可关闭；阶段页/文件/Artifact 按类型单例替换
底部 Dock  — 终端 / 输出 / 问题 / 任务进度
右侧检视   — Evidence / Trace / Audit
文件面板   — 代码视图(源码/Patch) | 材料视图(文档/交接/产物/证据/参考资料)
```

### 3.2 离开与恢复 [已确认]

| 场景 | 行为 |
|---|---|
| 用户关闭工作区 UI | 低/中风险任务继续后台执行；高风险动作暂停等授权 |
| 用户返回工作区 | 从 DB + LangGraph checkpoint + workspace 文件 + trace/audit + event log 恢复 |
| 遇 Gate/写盘/shell/外部写 | 暂停，等用户授权后恢复 |

> 关联决策：D-052, D-053

### 3.3 后台任务可见性 [推荐]

项目/概览/工作区顶部或底部可查看 run 状态（阶段 / 状态 / active_gate / 可暂停/取消/恢复）。

## 4. 创建项目 → 进入旅程

用户通过引导界面创建 Project，获得独立 Project Workspace。

**引导应澄清的信息类别**（非固定表单字段）[推荐]：

```text
项目来源(本地/Git/ZIP/GitHub) | 用户目标 | 源码/材料位置
权限与风险 | 执行模式倾向(Manual/Plan/Auto) | 模型/资源配置状态 | 需先确认的约束
```

**接入来源** [已确认]：本地目录 / Git / ZIP / GitHub（D-058）

**异常处理** [推荐]：信息不足 → 等待补充；权限不清 → 等待授权；创建为草稿暂不进入 P0。

## 5. P0-P6 主旅程（精简叙事）

> 以下将 P0-P6 作为连续的用户旅程叙述，而非 8 份独立规格说明。每阶段聚焦：**用户此刻想干什么 → 平台帮什么 → 什么时候必须用户拍板**。

### P0 接入 —— "我的项目进来了吗？"

用户确认项目来源和基本目标。平台读取源码/材料，识别明显接入风险，生成接入记录和初始 Evidence。

**用户 Gate**：P0→P1 必须用户确认。来源不清/权限不明/需读远程仓库时也应触发 Gate。

### P1 建档 —— "平台理解我的项目了吗？"

平台理解项目结构、技术栈、依赖、配置，形成项目档案。用户看到结构化的项目事实源。

**用户 Gate**：P1→P2 必须用户确认。技术栈识别冲突或资料缺失时应列待确认项。

### P2 评估 —— "迁移风险多大？能做吗？"

平台基于档案进行风险评估和可行性判断，生成评估报告。**模型可用于分析，但输出不直接成为事实或验收结论**。Fusion 如被选用，只是擅长风险分析/方案比较的模型选项，无特殊流程。

**用户 Gate**：P2→P3 必须用户确认。重大不确定项应先确认再进入规划。

### P3 规划 —— "怎么做？步骤是什么？"

平台输出迁移方案、Stage Plan、Task Plan（含依赖/并行/重试/失败处理/Gate/模型策略/产物传递）。**Fusion 如被选用，只是当前任务的模型策略之一，不单独形成规划流程。**

**用户 Gate**：P3→P4 必须用户确认。

### P4 执行 —— "开始改了，但别乱来"

平台按计划受控执行。**Policy 优先于 Agent 判断**；L5 高风险动作强制用户 Gate；Case 无执行权；命令/Tool/MCP/写盘先映射风险级别再放行。模型只负责生成/解释/辅助，Fusion 只是一个模型选项，无额外授权。

**用户 Gate**：P4 内部可能多次触发；P4→P5 必须用户确认。

### P5 验证 —— "改对了吗？"

平台运行验证动作，生成验证报告，关联 Evidence。**确定性验证优先**；模型可辅助解释/建议但不能替代真实测试；Fusion 如被选用只是擅长综合判断的模型策略，输出不代表验收通过。

**用户 Gate**：P5→P6 必须用户确认。证据不足只能标"待补充证据"或"未通过"。

### P6 交付 —— "可以交了"

平台整理最终 Artifact、Evidence、交付说明、风险清单和后续建议。标记可沉淀的 Case/Knowledge/Skill 候选。**P6 完成仅代表基础主流程可交付**，Fusion 等增强能力在 R13-R16 单独建设。

**用户 Gate**：P6 完成必须用户确认，且必须有 Evidence/Artifact/Trace/Audit 支撑。

## 6. 资源使用旅程 [已确认 + 用户修订]

### 6.1 用户感知

用户应能看到：用了什么资源 → 来自哪里（自己的/平台本地/社区）→ 风险级别 → 只读还是执行 → 是否需要 Gate。

### 6.2 优先级三阶

```text
第一优先：用户 / 当前项目自己的资源
          （源码、文档、配置、历史产物、用户上传材料、Workspace 内 Evidence/Artifact）

第二优先：rebuild 本地资源
          （平台资源/ 下的 agents/P系列Skill/tools/mcp/cases/knowledge/policies/templates/registry）

第三优先：在线社区资源
          （社区Case/Skill/Template/Tool、在线文档、外部资料、远程MCP）
          → 默认只读参考，不得默认执行；使用前需安全/许可/权限/审核。
```

### 6.3 推荐检索流程

```text
任务需要资源 → 检索自身 → 不足则检索平台本地 → 仍不足/用户请求则检索在线社区
→ 判断类型/风险/权限/审核 → 读取摘要 → 必要时读详情 → 注入上下文或受控执行 → 记录 Trace/Evidence
```

## 7. 模型使用旅程 [已确认 + 用户修订]

### 7.1 用户感知

用户应知道"当前在用模型"，不需要理解底层 Provider。可感知：默认/项目/任务覆盖/临时指定 → 是否为 Fusion 类型 → 低置信度/冲突 → 是否需要 Gate。

### 7.2 模型选择优先级 [已确认]

```text
用户临时指定 → Task/Node override → Agent 默认 → Project 默认 → System 默认
```

> 关联决策：D-036

### 7.3 Fusion：只是一个模型选项 [用户修订]

**Fusion 在使用体验中就是一个模型 / ModelProfile / ModelStrategy。** 它与其他模型在调用方式、选择方式、任务挂载方式上**没有流程差别**，只是可能更擅长综合判断、风险分析、方案比较或评审建议。

```
正确表达：                           错误表达：
· 模型选择下拉框中有 Fusion 选项      · "进入 Fusion 流程"
· 任务策略中可指定 Fusion 模型        · "召唤 Fusion 评审专家"
· Fusion 输出供参考，Gate 照常        · "Fusion 说了算，跳过 Gate"
```

Fusion 与其他模型的差别**只体现在 ModelProfile 层面**（能力标签、适用任务、成本/延迟、上下文窗口、置信度提示），不体现在用户流程层面。

**因此本文不为 Fusion 设独立章节。**

## 8. 关键异常路径

### 8.1 信息不足

任何阶段信息不足 → 标记"待补充"，列出缺失项 → 不伪装完成 → 不自动跳过 Gate。

### 8.2 验证失败

P5 发现问题 → 回到 P3 修订计划 / P4 返工执行 → 记录返工原因和范围 → 重新验证。

### 8.3 用户中断

用户不同意评估结论/规划方案 → Agent 列出替代方案 → 等待用户裁决 → 不自行推进。

### 8.4 高风险触发

执行中触发 L5 动作 → 立即暂停 → 展示风险说明 → 等待用户授权 → 记录 Audit。

## 10. 本文验收标准

本文达到 R1 基本可用标准，当且仅当：

```text
1. 用户旅程围绕"软件重构与迁移"定位展开，不泛化；
2. 核心旅程图清晰可读，P0-P6 为连续叙事而非 8 份独立规格说明；

5. 模型选择不绑定阶段；
6. 资源优先级明确为三阶：自身 → 平台本地 → 在线社区；
7. Case 无执行权，社区资源默认只读；

9. 离开/恢复旅程对齐"退出 UI ≠ 停止任务"和状态恢复多源原则；
10. 异常路径（信息不足/验证失败/用户中断/高风险触发）有明确处理方向；
11. 待确认项清晰，未把推荐写成 accepted。
```
