## 1. 一句话定义 [已确认]

rebuild 是面向软件重构与迁移的软件重构平台。

当前版本首期重点应用于信创迁移，在用户拥有源代码的前提下，帮助用户完成项目迁移、重构、验证与交付。

**本文不得将 rebuild 扩展表述为**：泛 AI 办公平台、泛项目管理平台、纯咨询平台、通用 Agent 展示平台、无人自治执行系统。

> 关联决策：D-003

## 2. 产品定位 [已确认]

rebuild 把迁移工作组织为产品流程：

```text
项目接入 → 项目建档 → 迁移评估 → 迁移规划 → 受控执行 → 验证 → 交付
```

每个阶段产出：Artifact、Evidence、Trace、Audit；关键节点设 Gate。

**不在本文定案**（进入专题文档）：Agent 具体定义、ModelProfile 字段、项目创建表单字段、Workspace 物理路径、Execution Session 数据模型、Resource Registry schema、Fusion 触发规则、远程资源权限矩阵。

> 关联决策：D-003, D-009

## 3. 用户项目主流程：P0-P6 [已确认]

P0-P6 是 rebuild 面向用户项目的可裁剪产品流程：

```text
P0 接入  — 项目进入平台，获取源代码或项目资料
P1 建档  — 建立项目事实源（结构、技术栈、依赖、风险线索）
P2 评估  — 迁移风险与可行性评估
P3 规划  — 方案选型、方案设计、执行计划
P4 执行  — 受控权限下完成代码/配置/结构调整
P5 验证  — 验证执行结果是否满足目标
P6 交付  — 整理交付成果、归档
```

**裁剪规则**：被裁剪的阶段不得伪装为已完成；启用的阶段必须有 Gate、Artifact、Evidence 和完成条件。例如：只做评估（P0→P1→P2→P6），完整迁移（P0→P1→P2→P3→P4→P5→P6）。

**P 阶段 ≠ R 阶段**：P 阶段是用户项目产品流程，R 阶段是平台自身建设阶段。不得混用。

> 关联决策：D-009, D-010

## 4. 项目创建与接入 [已确认 + 推荐]

### 4.1 接入来源 [已确认]

首批支持：本地目录、Git、ZIP、GitHub。

> 关联决策：D-058

### 4.2 项目创建引导 [推荐]

项目创建应通过引导界面逐步确定，帮助用户澄清以下信息类别（非固定表单字段）：

```text
项目来源（本地/Git/ZIP/GitHub）
用户目标（评估/规划/完整迁移/自定义）
源码或材料位置
权限与风险说明
执行模式倾向（Manual/Plan/Auto）
模型/资源配置是否已准备
需要先确认的约束
```

具体字段、顺序、必填/可选应进入接入专题文档并经用户确认。

### 4.3 项目创建输出 [推荐]

推荐输出：Project 记录、Project Workspace 初始化、初始接入记录、初始 Evidence、待确认项、P0 接入任务入口。

## 5. Agent 与 Skill 的产品边界 [已确认 + 推荐]

### 5.1 核心原则 [已确认]

**少 Agent、多 Skill**：同一 Agent + 不同 Skill + 不同上下文 + 不同工具权限。不为计划、编排、执行、评审等相似职责过度拆分 Agent。

只有以下条件才切换 Agent：需要干净上下文、更换模型、权限/责任边界不同、并行隔离、专家能力、独立验收。

> 关联决策：D-016, D-017

### 5.2 第一阶段 Agent 类型 [已确认]

少量必要类型：Node Worker Agent、Acceptance Agent、Auto Review / Authorization / Safety Agent、Expert Agent、Conversation / Gate Agent。

**禁止**：本文不自行新增"接入 Agent、建档 Agent、评估 Agent、规划 Agent、执行 Agent"等按阶段拆分的固定 Agent。

> 关联决策：D-019

### 5.3 Agent-Skill 分工模式 [推荐]

```text
P0-P6 各阶段由 Node Worker Agent 按任务计划调用对应 Skill；
Conversation / Gate Agent 负责用户对话和 Gate；
Acceptance Agent 负责节点/任务产物验收；
Auto Review / Authorization / Safety Agent 负责自动评审、安全和授权；
Expert Agent 在确需专家能力时按条件调用。
```

理由：符合"少 Agent、多 Skill"决策，保留扩展空间。

## 6. 执行模式与 Gate [已确认]

### 6.1 核心规则

**P 阶段晋级 Gate 必须用户授权**——无论 Manual / Plan / Auto 模式，每个启用的 P 阶段进入下一阶段前必须用户确认。

执行模式只影响阶段内部 Gate 密度和授权方式：

```text
Manual  — 用户审核 Stage Plan、Task Plan、授权动作和阶段晋级
Plan    — 用户审核 Stage Plan、Task Plan Batch；计划内动作 Hook+Policy 放行；越界/风险升级回用户
Auto    — Agent 审核 Stage Plan 和 Task Plan；Hook+Policy+Auto Review Agent 处理；高风险回用户
```

Task Plan Batch 暂不设数量上限，但必须说明：批次目标、任务范围、风险级别、权限边界、验收方式、异常升级策略。

> 关联决策：D-023~D-029

## 7. 模型使用与 Fusion [已确认 + 推荐]

### 7.1 核心规则 [已确认]

- **Fusion 是模型能力/策略**，不是特殊流程、特殊阶段或独立运行时角色；Fusion 输出不绕过 Policy/Gate/Audit
- **模型选择不绑定阶段**，按优先级解析：用户临时指定 → Task/Node override → Agent 默认 → Project 默认 → System 默认
- **ModelGateway 路线**：自研抽象层 + LiteLLM SDK Adapter（暂定，变更需申请）

> 关联决策：D-035, D-036, D-039

### 7.2 Fusion 产品表达 [推荐]

推荐将 Fusion 表达为：**可配置的模型策略能力**，在高风险、高不确定、低置信度或用户手动请求时启用，用于多模型或多视角综合判断。

展示内容：触发原因、参与模型/视角、主要观点、分歧、综合建议、是否需要用户 Gate、相关 Evidence/Trace。

### 7.3 产品层模型使用原则 [推荐]

```text
用户可配置项目默认模型策略；
任务/节点可覆盖模型策略；
模型调用必须可追踪；
模型输出不能直接成为事实或验收结论。
```

## 9. Workspace / 工作区 / 后台任务 [已确认]

### 9.1 三对象模型

```text
Project Workspace   — 项目文件持久化（按 project_id 隔离）
Environment Profile — 环境声明化（不是运行环境本身）
Execution Session   — 执行按需隔离
```

### 9.2 工作区心智

- **退出 UI ≠ 停止任务**：低/中风险任务可后台继续；遇 Gate/写盘/shell/高风险动作时必须暂停等授权
- **状态恢复多源**：数据库 + LangGraph checkpoint + workspace 文件 + trace/audit + event log（非容器/终端/前端 UI）
- **三状态分离**：Coding State（文件/编辑/产物）| Execution State（命令/构建/测试）| Runtime State（服务/数据库/中间件）——分别持久化、隔离和审计
- **后台任务管理**：项目级任务面板可查看 run 状态（run_id/project_id/stage/status/active_gate/can_pause/can_cancel/can_resume）

> 关联决策：D-050~D-055

## 10. 前端与工作区体验 [已确认]

### 10.1 核心原则

- 可吸收历史 Target Demo 中已验证的信息架构和交互心智，但必须适配当前版本（P0-P6、R0-RN、AGENTS.md、skills、ModelGateway、平台资源/、新目录体系）
- 不得逐像素复制旧前端；R3 可先做体验壳但必须标记 mock

### 10.2 工作区布局

```text
独立全屏 IDE 心智    — 从项目/概览进入，不是主导航常驻页面
中央区域              — 类型单例 Tab：Agent 对话常驻不可关闭；阶段页/文件/Artifact 按类型替换
底部 Dock             — 终端、输出、问题、任务进度
右侧检视              — Evidence、Trace、Audit
文件面板双视图        — 代码视图（源码/Patch）| 材料视图（文档/交接/产物/证据/参考资料）
```

> 关联决策：D-045~D-049

### 10.3 平台助手（平台级使用助手）[已确认]

平台助手（AI 精灵 / 客服对话 Agent）是 rebuild 的**平台级内置使用助手**——浮动 AI 精灵图标，点击展开对话面板。它服务于"用好平台"，**不是 P0-P6 迁移核心能力，也不是泛 AI 办公能力**。

```text
对话答疑 + 使用引导  — 解答平台用法、引导用户操作
模型连通性自测       — 对话面板内切换模型/服务商做连通性验证，仅影响助手自身会话，
                       不改变平台/项目默认模型
代用户操作 [规划/R-future] — 代建 Project/Run、报状态；须经授权，非当前版本启用
```

平台助手独立于 P0-P6 迁移编排与 Agent/Skill 资源体系，**不改变产品定位红线**（rebuild 仍是软件重构 / 迁移平台，见 §1）。模型自测复用 ModelGateway、不泄露密钥、纳入 Audit；代操作走 Policy/Gate 授权。

> 详见 `文档/00-项目治理/01-决策记录.md` D-073。

## 11. 当前版本范围边界 [已确认]

### 11.1 优先保证

```text
1. 平台定位清晰（软件重构平台，首期信创迁移）
2. P0-P6 用户主流程清晰
3. 少 Agent、多 Skill 原则清晰
4. Manual/Plan/Auto 与 Gate 关系清晰
5. ModelGateway 与模型策略边界清晰
6. Fusion 作为模型能力（非特殊流程）的边界清晰
7. 平台资源/ 目录与资源调用边界清晰
8. Workspace/Environment/Execution 三对象清晰
9. 前端工作区心智清晰
10. 安全/密钥/Policy/Gate 规则清晰
```

### 11.2 当前版本不优先做

```text
1. 泛化到所有软件工程场景
2. 建成通用插件市场
3. 复杂多租户商业化
4. 完整社区生态
5. 全自动无人自治执行
6. 默认开放高风险远程写操作
7. 文档基线未完成前大规模施工
8. 为未来能力创建不可验证占位
9. 自动把 Case 转为 Executable Skill
10. 让模型直接决定高风险执行或阶段晋级
11. 自行新增大量固定 Agent 类型
12. 借平台助手把 rebuild 扩展为泛 AI 平台或通用 Agent 展示平台
```

> 通用禁止与红线完整总表见 AGENTS.md §18；相关决策详见 01-决策记录.md；术语与风险级别（L0-L5）详见 02-术语表.md。（P 阶段晋级 Gate D-023 / Policy 优先 D-031 / Artifact 不自动晋升 D-014 / Manual-Plan-Auto D-025 等通用红线详见 AGENTS §18 + 01-决策记录）
