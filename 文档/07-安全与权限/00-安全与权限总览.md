## 1. 安全与权限目标

安全与权限体系目标是保证 rebuild 在单人与 Agent 协作、源码重构、迁移执行、模型调用、资源调用、文件写入、外部系统操作和交付验证过程中：

```text
1. 用户清楚知道哪些动作会发生；
2. 高风险动作不会被静默执行；
3. Policy 禁止项不可被 Agent 或前端绕过；
4. 授权、拒绝、阻断、审计都可追溯；
5. 资源调用有来源、风险、权限和 Trace；
6. 凭据与敏感配置不泄露；
7. Evidence / Trace / Audit 缺口不被隐藏；
8. 前端 mock / 未接真实服务不被伪装为真实能力；
9. P0-P6 阶段晋级始终需要用户 Gate；
10. 交付结果具备可信链路，而不是"看起来完成"。
```

安全与权限体系不是：

```text
1. 单一权限弹窗；
2. 静态命令白名单；
3. Agent 自我声明安全；
4. 前端按钮禁用逻辑；
5. 终端输出检测；
6. 容器状态检测；
7. 仅用于审计的事后记录。
```

## 2. 安全对象边界

R1 安全对象包括（术语详见 `02-术语表.md` 第七部分）：

```text
User：用户；
Agent：执行或评审主体；
Hook：动作前 / 动作中 / 动作后拦截点；
Policy：硬约束规则；
Security / Authorization Agent：安全评审或授权辅助 Agent；
Gate：需要等待决策的阻塞对象；
Permission Scope：权限范围；
Risk Level：风险级别（L0-L5，详见表 02-术语表 §7 + 本目录 02-风险分级与Gate策略）；
Credential：凭据引用；
Secret：敏感值；
Trace：过程记录；
Audit：审计记录；
Resource：可调用资源；
Action：待执行动作。
```

边界规则（D-030~D-034）：

```text
1. Hook 负责拦截和触发检查；
2. Policy 负责硬约束判断；
3. Security / Authorization Agent 负责安全辅助判断，但不能覆盖 Policy；
4. Gate 负责阻塞和决策；
5. Trace 记录过程；
6. Audit 记录关键决策和高风险动作；
7. Credential 只能以引用方式参与流程；
8. Secret 不进入前端、日志、Trace、截图或交接材料。
```

## 3. 三层安全机制总览

安全机制采用三层组合（D-030）：

```text
Hook；
Policy / Rule；
Security / Authorization Agent。
```

三层职责：

```text
Hook：在命令、Tool、MCP、写盘、Git、外部系统写操作、资源调用等动作发生前后进行拦截和记录；
Policy / Rule：判断动作是否允许、是否阻断、是否需要 Gate、是否需要 Audit；
Security / Authorization Agent：对非 Policy 禁止的高风险、不确定、低置信度、越界动作进行辅助评审和升级建议。
```

总规则：

```text
1. Policy 优先级最高（D-031）；
2. Hook 不应被绕过；
3. Security / Authorization Agent 不能批准 Policy 禁止项（D-031）；
4. Gate 未决策不得继续阻塞动作；
5. 高风险动作必须可 Trace / Audit；
6. 前端只能展示后端安全状态，不能本地批准。
```

> 三层机制的详细协作规范见本目录 `01-Policy-Hook-Authorization规范.md`。

## 4. Hook 边界

Hook 覆盖范围（详见 `01-Policy-Hook-Authorization规范.md`）：

```text
命令执行；
Tool 调用；
MCP 调用；
写盘；
Patch 应用；
Git 操作；
外部系统写操作；
资源调用；
模型调用前后；
文件读取敏感检测；
凭据访问；
Gate 决策提交；
Trace / Audit 写入。
```

Hook 触发结果建议：

```text
allow；
warn；
require_gate；
require_audit；
block_by_policy；
redaction_required；
needs_review；
error。
```

规则：

```text
1. Hook 不能替代 Policy；
2. Hook 不能替代 Audit；
3. Hook 触发 require_gate 时必须暂停对应动作；
4. Hook 触发 block_by_policy 时不得进入批准流程；
5. Hook 结果必须可 Trace；
6. Hook 错误不得默认放行。
```

## 5. Policy / Rule 边界

Policy 是硬约束（D-031）。Policy 覆盖范围（详见 `01-Policy-Hook-Authorization规范.md`）：

```text
禁止动作；
强制 Gate 动作；
强制 Audit 动作；
凭据脱敏规则；
资源来源规则；
社区资源默认只读规则；
路径越界规则；
Workspace 隔离规则；
写盘范围规则；
外部系统写操作规则；
高风险动作规则；
Evidence / Trace / Audit 完整性规则。
```

Policy 结果建议：

```text
allowed；
allowed_with_warning；
requires_gate；
requires_audit；
blocked；
redaction_required；
not_applicable；
unknown。
```

规则：

```text
1. blocked 不得被 Agent 批准；
2. blocked 不得由前端改为 allowed；
3. unknown 不得默认 allowed；
4. requires_gate 必须生成或关联 Gate；
5. requires_audit 必须写 Audit 或显示 audit_pending；
6. Policy 冲突必须可追溯。
```

## 6. Security / Authorization Agent 边界

Security / Authorization Agent 是辅助判断主体，不是最高权限主体（D-031）。

可做：

```text
评估动作风险；
识别越界；
识别低置信度；
建议 require_gate；
建议 reject；
建议补充信息；
汇总风险原因；
辅助用户理解影响范围。
```

不得做：

```text
1. 批准 Policy 禁止项；
2. 覆盖用户阶段晋级 Gate；
3. 私自放行 L5 高风险动作；
4. 忽略 Evidence / Trace / Audit 缺口；
5. 生成或展示密钥明文；
6. 将自身判断写成用户授权。
```

## 7. 执行模式与权限关系

Manual / Plan / Auto 只影响阶段内部 Gate 密度和授权方式，不改变 P0-P6 产品流程，也不改变 P 阶段晋级必须用户授权的规则（D-023~D-027）。

三模式完整定义见详述源 `01-决策记录.md` D-025 + `02-术语表.md`（单一事实源，本文不复述）。本文只强调三模式下的**安全/授权差异**：Manual 全程用户审核；Plan 计划内动作 Hook+Policy 放行、越界/风险升级回用户；Auto 阶段内授权由 Hook+Policy+Auto Review Agent 处理、高风险/低置信度/冲突/超范围回用户。

共同规则（安全红线，就地保留 + 引用）：

```text
1. P 阶段晋级必须用户授权（D-023）；
2. Policy blocked 在任何模式下不得继续（D-031）；
3. L5 高风险动作暂定全部强制用户 Gate（D-034）；
4. 凭据和密钥在任何模式下不得泄露（D-032）；
5. Gate / Trace / Audit 缺口不得隐藏（D-050）；
6. Auto 不等于无限自动放行。
```

## 8. 风险分级总览

风险分级在 `02-术语表.md` 第七部分定义 L0-L3，本目录 `02-风险分级与Gate策略.md` 扩展至 L0-L5 并详述各级判断维度。本文只做速查引用：

```text
L0：只读参考        — 无破坏性，不需要额外授权
L1：方法调用        — 低风险，Plan/Auto Mode 下 Hook+Policy 放行
L2：受控执行        — 中风险，需要 Hook 检查 + 范围校验
L3：外部系统写操作  — 高风险，Plan 需用户确认，Auto 需 Agent 审核
L4：高影响范围动作  — 很高风险，Plan 需用户确认，Auto 强制升级用户
L5：不可逆/生产     — 极高风险，所有模式强制用户 Gate
```

> 详细定义见 `02-术语表.md` 第七部分 + `02-风险分级与Gate策略.md`。L4/L5 由安全专题文档细化。

核心规则（D-033）：

```text
1. 同一命令在不同上下文中风险可能不同；
2. 风险级别不能只由命令名决定；
3. 风险级别必须结合路径、范围、权限、外部影响和可回滚性判断；
4. 命令、Tool、MCP、写盘、Git 操作等必须先映射到风险级别。
```

## 9. 动作类型风险归口

动作类型归口（详见 `02-风险分级与Gate策略.md` + `03-命令-Tool-MCP-Git-写盘授权规范.md`）：

```text
Read：读取项目文件、只读参考、Case / Knowledge；
Write：写入 Workspace 文件、生成 Artifact、修改配置；
Command：shell / 构建 / 测试 / 脚本执行；
Tool：本地 Tool 调用；
MCP：MCP 调用；
Git：clone / checkout / commit / push / merge；
Patch：生成 / 应用 Patch；
External Write：外部系统写操作；
Credential：凭据访问或验证；
Model Call：模型调用；
Resource Call：资源调用；
Gate Decision：用户或授权主体决策。
```

规则：

```text
1. 读取不等于无风险；
2. 写盘必须考虑范围和可回滚性；
3. Shell 必须考虑命令、参数、路径和上下文；
4. Git push / 外部写操作默认高风险；
5. 凭据访问必须脱敏；
6. Gate Decision 必须 Audit。
```

## 10. Gate 总览

Gate 是权限体系中的阻塞与决策对象。Gate 类型（详见 `02-风险分级与Gate策略.md`）：

```text
stage_promotion_gate；
stage_plan_gate；
task_plan_gate；
high_risk_action_gate；
write_scope_gate；
external_write_gate；
resource_call_gate；
credential_gate；
evidence_gap_gate；
policy_exception_gate；
rework_gate；
delivery_gate。
```

规则：

```text
1. P 阶段晋级 Gate 必须由用户授权（D-023）；
2. L5 高风险动作必须用户 Gate（D-034）；
3. Policy 禁止项不得走 policy_exception_gate 自动批准；
4. Evidence Gap 接受风险必须写 Audit；
5. Gate 未决策不得继续；
6. Gate 决策后必须刷新后端状态。
```

## 11. P 阶段晋级 Gate

P 阶段晋级 Gate 是不可弱化的用户授权点（D-023）。

前端 / API / Agent 必须表达：

```text
当前阶段；
拟进入阶段；
阶段完成条件；
Artifact；
Evidence；
Evidence Gap；
Trace 摘要；
Audit 摘要；
风险说明；
用户决策。
```

规则：

```text
1. Manual / Plan / Auto 不改变该 Gate；
2. Stage Plan / Task Plan 通过不等于阶段晋级通过；
3. Evidence 不足不得默认晋级；
4. 被裁剪阶段不得伪装为 completed；
5. 用户授权应写 Audit。
```

## 12. 高风险动作 Gate

高风险动作（D-034，详见 `02-风险分级与Gate策略.md`）：

```text
大范围写盘；
敏感路径写入；
不可回滚或难回滚 Patch；
外部系统写操作；
Git push / merge 等影响远端状态的操作；
高风险 Tool / MCP 调用；
高风险资源调用；
可能泄露敏感信息的操作；
L5 风险动作。
```

规则：

```text
1. L5 暂定全部强制用户 Gate；
2. 高风险动作必须说明影响范围；
3. 命令摘要必须脱敏；
4. 用户未授权不得继续；
5. 高风险动作必须写 Audit；
6. Gate 不得只显示为 toast。
```

## 13. 命令权限策略

命令权限按风险级别识别，不硬编码命令清单（D-033）。详见 `03-命令-Tool-MCP-Git-写盘授权规范.md`。

判断维度：

```text
命令类型；
参数；
执行路径；
影响范围；
是否写盘；
是否外部写；
是否涉及凭据；
是否可回滚；
是否触碰受保护路径；
是否处于已批准计划范围内。
```

规则：

```text
1. 同一命令在不同上下文中风险可不同；
2. 低风险不等于永远自动放行；
3. 命令风险升级必须触发 Gate 或评审；
4. 命令输出必须脱敏；
5. 命令执行必须 Trace；
6. 高风险命令必须 Audit。
```


## 15. 写盘与 Workspace 权限

```text
4. Workspace 边界不得越过；
```

## 16. Git 权限策略

Git 操作按风险级别处理（D-033）。详见 `03-命令-Tool-MCP-Git-写盘授权规范.md`。

建议归类：

```text
git status / log / diff：通常只读，但仍需上下文判断；
git clone / fetch：接入或读取类操作，需凭据脱敏；
git checkout：可能影响工作区，需上下文判断；
git add / commit：本地状态写入，需计划范围检查；
git merge / rebase：高影响操作，需风险检查；
git push：外部系统写操作，默认高风险；
包含 token 的 Git URL：禁止回显。
```

规则：

```text
1. Git 凭据不得进入日志、Trace、前端或错误详情；
2. Git push / 外部远端写操作必须 Gate / Audit；
3. Git 操作必须明确目标仓库和分支摘要；
4. Git 操作失败不得泄露凭据；
5. Git 操作应可 Trace。
```
