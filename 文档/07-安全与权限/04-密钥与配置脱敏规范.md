## 1. 脱敏目标

密钥与配置脱敏的目标是（D-032）：

```text
1. 平台能识别凭据和敏感配置是否存在；
2. 平台能基于凭据状态执行必要流程；
3. 用户能理解凭据是否已配置、缺失、无效或无权限查看；
4. Agent、模型、Tool、MCP、Git、命令执行和前端展示均不泄露密钥；
5. Trace / Audit 具备可追溯性，但不包含敏感明文；
6. 错误响应能帮助定位问题，但不暴露凭据；
7. 交接材料和报告可用于协作，但不携带 Secret；
8. 脱敏失败时默认阻断，而不是继续展示。
```

脱敏不是简单替换字符串，而是贯穿输入、上下文、执行、输出、前端、日志、审计、导出和交接的全链路安全策略。

## 2. 敏感对象定义

R1 敏感对象包括（D-032）：

```text
Key；
API Key；
Token；
Secret；
Password；
Private Key；
Access Token；
Refresh Token；
Session Cookie；
SSH Key；
GitHub Token；
Provider Key；
连接串；
数据库密码；
.env 明文；
凭据文件；
密钥文件；
包含凭据的 Git URL；
包含凭据的命令参数；
未脱敏模型输入输出；
未脱敏 Tool / MCP 输出；
未脱敏 Trace / Audit 详情；
包含密钥的截图、导出、报告或交接材料。
```

规则：

```text
1. 以上对象默认不得明文展示；
2. 未列出的可疑敏感字段也应按敏感处理；
3. 业务字段名中包含 key / token / secret / password / credential 等词时必须触发检查；
4. 不能仅依赖字段名判断，应结合内容、来源和上下文；
5. false positive 优先安全处理，R2/R4 再优化用户体验。
```

## 3. 凭据对象边界

> 凭据可/不可展示字段的基本定义见 `00-安全与权限总览.md` §17（详述源）。本文列出脱敏操作中需关注的补充字段。

Credential 是可被引用的凭据对象，Secret 是不能被展示的敏感值。

可展示（补充操作字段）：

```text
credential_ref；
credential_id；
credential_type；
credential_scope；
credential_status；
has_credential；
redacted；
last_checked_at；
validation_status；
validation_error_ref；
provider_ref；
resource_ref；
permission_scope。
```

不得展示（同 00 §17）：

```text
credential_value / secret_value / raw_token / raw_key / raw_password；
private_key / connection_string_raw / full_env_content；
recoverable_secret_fragment。
```

规则：

```text
1. Credential 可以被引用；
2. Secret 不得被展示；
3. Credential 状态可进入 Trace / Audit；
4. Secret 明文不得进入 Trace / Audit；
5. Credential Ref 不应可反推出 Secret；
6. 前端不负责保存 Secret 明文。
```

展示规则：

```text
1. 可以显示配置文件是否存在；
2. 可以显示配置项名称；
3. 可以显示 credential_status；
4. 可以显示 redacted；
5. 不显示真实值；
6. 不显示可还原片段；
7. 不显示完整连接串；
8. 不把配置文件内容直接塞入模型上下文。
```

## 5. 脱敏状态

脱敏状态建议（R1 建议契约）：

```text
not_sensitive：未识别为敏感；
sensitive_detected：识别到敏感内容；
redacted：已脱敏；
redaction_required：必须脱敏后才能展示；
redaction_failed：脱敏失败；
credential_missing：凭据缺失；
credential_invalid：凭据无效；
permission_denied：无权限查看；
not_scanned：尚未扫描；
scan_failed：扫描失败；
mock_redaction：mock 脱敏结果。
```

规则：

```text
1. redaction_required 必须阻止原文展示；
2. redaction_failed 不得降级为展示原文；
3. not_scanned 不得显示为安全；
4. scan_failed 不得显示为无敏感信息；
5. mock_redaction 必须显式标记；
6. permission_denied 不等于不存在。
```

## 6. 脱敏显示格式

脱敏显示建议：

```text
[REDACTED]
[SECRET_REDACTED]
[TOKEN_REDACTED]
[PASSWORD_REDACTED]
[CONNECTION_STRING_REDACTED]
[PRIVATE_KEY_REDACTED]
[ENV_VALUE_REDACTED]
```

显示规则：

```text
1. 不展示前几位 / 后几位，除非 R2 安全评审明确允许；
2. 不展示长度、结构或可还原特征；
3. 不展示 base64 / JWT / pem 片段；
4. 不展示包含用户名密码的 URL；
5. 可以展示"已配置""缺失""无效""已脱敏"等状态；
6. 脱敏标签应统一。
```

## 7. 输入侧脱敏

输入来源包括：

```text
用户输入；
上传文件；
项目源码；
配置文件；
环境变量；
Git URL；
命令参数；
Tool / MCP 参数；
模型上下文；
外部系统响应；
历史参考资料。
```

规则：

```text
1. 输入进入系统后应先判断是否含敏感内容；
2. 敏感输入只能进入受控 Credential / Secret 流程；
3. 用户输入凭据后不回显；
4. 上传文件中的敏感内容不得直接展示；
5. Git URL 中的凭据必须剥离或脱敏；
6. 传入模型前必须经过上下文脱敏策略（见 §14）；
7. 历史资料中的密钥不得被吸收到当前事实源。
```

## 8. 输出侧脱敏

输出来源包括：

```text
命令 stdout / stderr；
Tool 输出；
MCP 输出；
模型输出；
Git 错误；
外部 API 响应；
Trace；
Audit；
Artifact；
Evidence candidate；
前端错误详情；
导出报告；
交接材料。
```

规则：

```text
1. 输出默认先扫描再展示；
2. 发现敏感内容时展示 output_ref 和脱敏摘要；
3. 不把敏感输出写入 Artifact / Evidence；
4. 不把敏感输出写入交接材料；
5. 不把敏感输出写入日志；
6. 输出详情按权限展示，仍不得展示 Secret 明文；
7. 脱敏失败时阻断展示。
```

## 9. 前端展示规范

> 前端安全展示完整要求见 `00-安全与权限总览.md` §22。本文列出脱敏特有的前端展示规则。

前端可展示：

```text
凭据已配置；
凭据缺失；
凭据无效；
凭据已脱敏；
配置文件存在；
敏感内容已隐藏；
无权限查看详情；
错误详情已脱敏；
输出已脱敏；
需要重新配置凭据；
当前为 mock 脱敏结果。
```

前端不得展示（D-032）：

```text
Secret 明文；
可还原片段；
完整 .env 内容；
完整连接串；
含 token 的 Git URL；
未脱敏 stdout / stderr；
未脱敏 Trace / Audit；
未脱敏模型上下文；
未脱敏截图或导出内容。
```

规则：

```text
1. 前端不是脱敏事实源；
2. 前端可以做二次防护，但不能替代后端脱敏；
3. 前端收到 redaction_required 必须阻止展示；
4. 复制、下载、截图、导出也必须遵守脱敏；
5. mock 脱敏必须显式标记；
6. "已脱敏"不等于"可公开"。
```

## 11. Trace 脱敏规范

> Trace 写入完整规范见 `01-Policy-Hook-Authorization规范.md` §26。本文列出脱敏特有的 Trace 字段约束。

Trace 可记录：

```text
trace_id / action_id / action_type；
credential_ref / credential_status / redaction_status；
resource_ref / model_profile_ref；
command_summary / output_ref / error_ref / created_at。
```

Trace 不得记录（D-032）：

```text

含 token 的 URL；
未脱敏 stdout / stderr / 模型输入输出；
```

规则：

```text

3. 权限提升也不得展示 Secret 明文；
4. Trace 不等于 Evidence；
5. Trace 写入失败不得静默。
```

## 13. Memory 脱敏规范

> Memory 分层和安全规则见 `00-安全与权限总览.md` §18 和 D-043/D-044。本文列出脱敏特有的 Memory 写入约束。

禁止进入 Memory（D-044）：

```text
密钥 / Token / env 明文 / Secret / Password；
连接串 / 私钥；
未确认推断；
临时错误日志；
一次性任务计划；
已过期旧版事实。
```

可进入 Memory 的安全摘要：

```text
credential_status；
credential_ref；
是否存在配置；
是否缺失凭据；
是否需要用户重新配置；
已脱敏状态；
Policy 结论摘要；
安全决策摘要。
```

规则：

```text
1. Memory 写入前必须检查敏感内容；
2. Agent Working Memory 不得成为 Secret 暂存区；
3. Project Memory 不得保存 env 明文；
4. Run Memory 不得保存命令未脱敏输出；
5. 历史参考中的密钥不得进入当前 Memory；
6. Memory 冲突必须回到事实源校验。
```

## 14. 模型上下文脱敏规范

模型上下文包括：

```text
System / Developer / Agent 指令；
Project Context；
Run Context；
Node Context；
Tool / MCP 输出；
检索内容；
用户输入；
文件片段；
错误详情；

```

规则（D-032）：

```text

2. env 文件不得全量塞入模型上下文；
3. 命令输出进入模型前必须脱敏；
4. Tool / MCP 输出进入模型前必须脱敏；
5. Git URL 进入模型前必须去除凭据；
6. 模型输出若包含疑似 Secret，必须 redaction_required；
7. Fusion 不绕过脱敏策略（D-036）。
```

## 15. 命令输出脱敏规范

> 命令输出处理见 `03-命令-Tool-MCP-Git-写盘授权规范.md` §7。本文列出脱敏特有的高风险场景。

命令输出高风险场景：

```text
打印 env；
打印配置文件；
打印连接串；
打印 Git remote；
打印认证失败详情；
打印 Provider Key；
打印 token；
打印私钥；
打印外部系统响应。
```

规则：
