## 1. 安全目标

源码仓库与外部执行安全的目标是：

```text
1. 防止源码、凭据、配置和日志泄露；
2. 防止未授权写盘、命令执行、Git 远端写和外部系统写操作；
3. 防止外部执行器扩大上下文、越权访问或静默执行；
4. 防止 mock、not_connected、candidate 输出伪装成真实能力；
5. 防止 Artifact/Evidence candidate 被误标为 Evidence validated；
6. 防止 Trace/Audit 缺失但结果被显示为可信；
7. 防止高风险动作绕过用户 Gate；
8. 支撑 P4 执行、P5 验证、P6 交付的可信证据链。
```

## 4. Policy / Hook / Authorization 分工

> **上游详述源**：`01-Policy-Hook-Authorization规范.md`。三层机制完整定义、Manual/Plan/Auto 差异、Security/Authorization Agent 决策范围见 01。本节仅列出与源码仓库和外部执行器直接相关的要点。

- **Hook**：在源码接入、Git 操作、外部执行器调用入口前拦截，收集动作类型/目标资源/路径范围/凭据状态/风险级别/用户授权状态/当前执行模式/当前 Stage-Run/Trace-Audit 写入状态
- **Policy**：硬约束。检查结果 7 种（allowed/gate_required/blocked/redaction_required/credential_required/unknown/error）——详见 01 §Policy
- **Security/Authorization Agent**：可辅助判断风险、解释 Policy 结果、建议 Gate 文案，但**不得批准 Policy 禁止的动作**

## 5. 源码仓库安全

> 通用凭据与脱敏规则见 `04-密钥与配置脱敏规范.md`。本节仅给出源码仓库特有的安全约束。

### 5.1 本地目录

```text
1. 本地目录路径应以 local_path_ref 表示；
2. 不得在前端、日志或交接材料展示敏感完整路径；
3. 不得跨 Project 读取源码；
4. 不得将 archive 目录作为当前 Workspace 施工目录；
5. 敏感文件只记录存在状态或脱敏摘要；
6. 权限不足不得伪装接入成功。
```

### 5.2 ZIP 源码包

```text
1. ZIP 解包必须在受控目录中执行；
2. ZIP 解包不得覆盖 Workspace 外文件；
3. path traversal 必须 blocked；
4. ZIP 内敏感文件只记录存在状态或脱敏摘要；
5. ZIP 解包成功不等于建档完成；
6. ZIP 文件名不等于 Evidence validated。
```

### 5.3 Git / GitHub 读取

读取类动作（git clone/fetch/pull/status/log/diff read/branch list/repository metadata read）：

```text
1. 读取类动作仍需 Policy Check；
2. 输出必须脱敏；
3. Git URL 中不得展示明文 token；
4. credential_invalid 不得返回密钥片段；
5. clone/pull 成功不等于 P0 completed；
6. pull 冲突必须阻塞并展示 next_actions。
```

### 5.4 Git 本地变更

本地变更类动作（git checkout/branch create/add/commit + patch generate/apply + workspace file write）：

```text
1. 必须校验变更范围；
2. blocked_paths 不得写入；
3. dirty workspace 不得静默覆盖；
4. 高风险文件变更必须 Gate；
5. commit message 不得包含密钥；
6. commit 成功不等于验证通过。
```

> 详细授权链路见 `03-命令-Tool-MCP-Git-写盘授权规范.md` §Git。

### 5.5 Git 远端写

远端写类动作（git push/PR-MR create/remote branch create/remote branch delete/tag push/external repository write）：

```text
1. 必须用户 Gate（L5）；
2. 必须 Audit；
3. 必须展示目标仓库、目标分支、commit 和变更摘要；
4. remote_url_redacted 不得含 token；
5. 不得静默 push；
6. push 失败不得静默重试；
7. push 成功不等于 P6 completed。
```

## 6. Workspace 安全

> 通用写盘授权见 `03-命令-Tool-MCP-Git-写盘授权规范.md` §写盘。Workspace 架构定义见 `02-架构设计/04-Workspace-Environment-Execution架构.md`。

```text
1. 每个 Project 必须有独立 Workspace；
2. Workspace 按 project_id 隔离；
3. 不得将不同 Project 的源码混放；
4. 不得将临时目录作为长期事实源；
5. Workspace 状态必须后端可查询；
6. 前端不得用本地缓存伪造 Workspace 状态；
7. 文件写入必须记录 Trace；
8. 高风险写入必须 Audit；
9. 写入失败不得显示任务成功。
```

路径策略：

```text
allowed_paths：允许读取或写入范围；
blocked_paths：禁止读取或写入范围；
blocked_paths 优先于 allowed_paths。
```

建议默认 blocked_paths：

```text
密钥文件 / .env 明文 / 凭据目录 / 系统目录 /
archive 历史归档目录 / 非当前 Project Workspace / 未授权外部挂载目录
```

## 7. 外部执行器安全

> 通用 Tool/MCP/Expert Agent 授权见 `03-命令-Tool-MCP-Git-写盘授权规范.md` §Tool-MCP、§Expert-Agent。本节补充领域特有约束。

外部执行器包括：

```text
OpenCode / 外部编程 Agent / Tool / MCP / Expert Agent /
确定性转换器 / local_command_executor / remote_command_executor
```

领域特有安全规则：

```text
1. 未注册资源不得执行；
2. 未声明权限边界不得执行写操作；
3. 未声明风险级别不得执行高风险动作；
4. 未声明输出策略不得进入 Evidence candidate；
5. 外部执行器不得接收明文密钥；
6. 外部执行器不得自行扩大上下文范围；
7. 外部执行器输出不自动成为当前事实；
8. 外部执行器输出不自动成为 Evidence validated；
9. 外部执行器不得决定 P 阶段晋级；
10. 外部执行器不得替代 LangGraph 主编排；
11. OpenCode 需在 R6 确认后作为正式候选执行器接入（当前为规划中）；
12. 确定性转换器以 Skill/Tool/Expert Agent/MCP 资源形式接入，遵循统一资源调用流程与风险分级。
```

## 8. Patch 与文件写入安全

> **上游详述源**：`03-命令-Tool-MCP-Git-写盘授权规范.md` §Patch、§写盘。

领域补充：

```text
1. Patch generated 不等于 Patch applied；
2. Patch 是 Artifact candidate，不自动成为 Evidence validated；
3. Patch apply 必须检查路径范围——blocked_paths 不得写入；
4. 写盘动作必须按风险级别处理（L3-L4）；
5. 高风险写盘必须 Gate；
6. 写入 .env、密钥文件、配置文件必须高风险处理（L4-L5）；
7. 外部 Agent 自称写入成功不作为事实源——写入结果必须由 Workspace 状态确认；
8. 写入必须写 file_write_trace；高风险写入必须写 Audit。
```

领域补充：

```text
8. command_timeout 必须可见；
```

## 10. 远程环境安全

> 环境与执行架构见 `02-架构设计/04-Workspace-Environment-Execution架构.md` + `03-流程与运行时/07-远程环境与执行会话规范.md`。

### 10.1 Environment Profile

```text
1. Environment Profile 创建成功不等于环境可用；
2. connection_profile_ref 不得含明文密钥；
3. credential_ref 不得暴露明文；
4. capability 未验证前不得显示 verified；
5. Profile 变更必须 Trace；高风险变更必须 Audit。
```

### 10.2 环境探测

```text
1. reachable 不等于 environment_verified；
2. probe artifact 不自动成为 Evidence validated；
3. 探测输出必须脱敏；
4. 探测失败不得显示环境可用；
5. 探测命令也必须记录 Trace。
```

### 10.3 Execution Session

```text
1. Session 创建成功不等于命令执行成功；
2. Session 状态不得只存在终端窗口；
3. Session 必须可查询和恢复；
4. not_connected/mock 必须显式返回；
5. 关闭 Session 不得删除 Evidence/Trace/Audit；
6. 会话异常终止必须可见。
```

## 11. 构建 / 测试 / 运行安全

### 11.1 构建

```text
1. 构建成功不等于测试通过；
2. 构建成功不等于 P5 completed；
3. build_evidence_candidate 需经 P5 验证流程确认；
4. 构建日志不得泄露密钥；
5. 依赖安装若写盘或联网，必须按风险处理。
```

### 11.2 测试

```text
1. 测试通过不等于 P5 completed；
2. 测试失败不得隐藏；
3. 测试覆盖不足应登记 Evidence Gap；
4. test_evidence_candidate 需经 P5 验证流程确认；
5. 测试日志不得泄露敏感信息。
```

### 11.3 运行

## 13. Gate 策略

```text
L5 高风险动作 / Git push / PR-MR create / remote branch delete /
```

## 17. 失败处理安全

## 18. 与 P0-P6 的关系

```text
P0：源码接入安全、凭据状态、Workspace 隔离、接入 Trace；
P1：建档时不得把敏感文件明文写入项目文档；
P2：评估时不得暴露源码敏感信息和凭据；
P3：规划时必须标明风险级别、权限边界和 Gate；
P4：执行时重点管控写盘、命令、外部执行器、Patch、Git commit；
P5：验证时不得把 Evidence candidate 误标为 Evidence validated；
P6：交付时重点管控 Git push、交付包、交付报告和脱敏。
```

规则：

```text
1. 安全规则不改变 P0-P6 阶段；
2. 安全规则不替代 P 阶段晋级 Gate；
3. P 阶段晋级必须用户授权；
4. 高风险动作不能以后续阶段补审计；
5. P6 不得引用未验证结果。
```
