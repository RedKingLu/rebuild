## 2. P0-P6 流程速查

> 详细阶段定义见 `02-架构设计/02-LangGraph主编排架构.md` §5.2-§5.8 和 `01-产品定义/00-产品定义基准.md` §3。

| 阶段 | 目标 | 核心输出 | 晋级 Gate |
|---|---|---|---|
| P0 接入 | 确认项目来源与材料 | 接入记录、初始 Evidence | 用户确认进入 P1 |
| P1 建档 | 识别结构/配置/依赖 | 项目档案 Artifact、Profile 草案 | 用户确认进入 P2 |
| P2 评估 | 评估风险/可行性/阻塞项 | 评估报告、不确定项清单 | 用户确认进入 P3 |
| P3 规划 | 形成方案/计划/任务图 | Stage Plan、Task Plan、TaskGraph | 用户确认进入 P4 |
| P4 执行 | 按计划受控执行 | Patch、Artifact、Trace/Audit | 用户确认进入 P5 |
| P5 验证 | 证明迁移正确性 | 验证 Evidence、对比结果 | 用户确认进入 P6 |
| P6 交付 | 整理交付包与证据链 | 交付包、交付说明、遗留风险 | 最终用户 Gate |

**裁剪规则**：被裁剪阶段标记 `skipped`，不得伪装 `completed`。启用阶段必须满足：输入→动作→Artifact→Evidence→Trace/Audit→Gate→完成条件。

## 3. 核心约束（流程运行时特有红线）

以下约束是本专题在架构红线基础上的流程运行时专项补充：

```text
1. P 阶段晋级必须用户 Gate——无论 Manual/Plan/Auto 模式；
2. 被裁剪阶段必须显式标记 skipped/not_applicable，不得伪装 completed；
3. 无 Evidence 不得标记任何阶段 completed（D-066）；
4. P5 验证不得以"构建成功""预览可打开""模型判断"为通过依据；
5. 失败不得伪装 completed——必须进入 failed/rework_required 并记录 Trace；
6. Gate 决策必须进入 Audit——不得只用前端按钮状态替代；
7. resume 后必须校验上下文/Policy/Workspace 引用是否仍有效；
8. 前端 UI 不得成为流程状态源——事件丢失时必须可通过 API 恢复；
9. 不得将旧 F0-F6、旧 S0-S7、Phase 等历史阶段命名引入 V26.1 主流程；
10. 不得引入 Mission 产品层——复杂工作拆分用多 Project 或 TaskGraph 表达（D-070）。
```

> 通用禁止与红线完整总表见 AGENTS.md §18；相关决策详见 01-决策记录.md；术语与风险级别（L0-L5）详见 02-术语表.md。
