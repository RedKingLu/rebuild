## 1. 流程定位

项目接入与源码同步流程服务于 P0 接入，并为后续 P1-P6 提供可追溯的源码基线。

其核心目标是：

```text
1. 将用户项目与 rebuild Project 建立受控关联；
2. 将源码材料落入独立 Project Workspace；
3. 记录接入来源、接入方式和接入状态；
4. 形成可追溯 Trace；
5. 形成源码接入 Evidence candidate；
6. 为 P1 建档、P2 评估、P3 规划、P4 执行、P5 验证和 P6 交付提供源码基础；
7. 为 Git / GitHub 后续同步、变更和交付提供统一流程。
```

项目接入不是迁移成功，源码同步不是验证通过。

## 3. 支持的接入方式

首批支持：

```text
local_directory；
git_repository；
zip_upload；
github_repository。
```

接入方式说明：

```text
local_directory：读取用户指定本地目录并绑定 / 复制 / 同步到 Project Workspace；
git_repository：从 Git URL clone 或绑定已有仓库；
zip_upload：上传 ZIP 后解包到 Project Workspace；
github_repository：通过 GitHub 仓库引用、凭据和分支信息接入。
```

规则：

```text
1. 接入方式必须明确；
2. source_ref 必须脱敏；
3. credential_ref 必须与明文凭据分离；
4. 接入动作必须 Trace；
5. 接入失败不得显示 P0 completed；
6. mock 接入必须显式标记；
7. 被裁剪或未启用接入方式不得显示可用。
```

## 4. 总体接入流程

统一流程：

```text
1. 创建或选择 Project；
2. 用户选择接入方式；
3. 前端提交接入请求；
4. 后端创建 Source Integration；
5. 校验 source_type、source_ref 和 credential_ref；
6. 执行 Policy Check；
7. 如需授权，创建 Gate；
8. 初始化或绑定 Project Workspace；
9. 执行源码接入动作；
10. 生成文件清单摘要；
11. 生成接入 Trace；
12. 生成 source_import_artifact；
13. 生成 source_import_evidence_candidate；
14. 更新 Project / Integration / Workspace 状态；
15. 前端刷新展示；
16. 用户审核 P0 Gate 后决定是否进入 P1。
```

完成接入不等于自动通过 P0。P0 晋级 P1 仍需用户 Gate。

## 7. Git 接入流程

### 7.1 输入

```text
project_id；
repository_url_ref；
branch；
credential_ref；
workspace_ref；
clone_depth；
redaction_policy。
```

### 7.2 Clone 流程

```text
1. 校验 repository_url_ref；
2. 校验 credential_ref 和 credential_status；
3. 对 clone 动作执行 Policy Check；
4. 初始化 Workspace code_root；
5. 执行 git clone；
6. 获取 current_branch 和 commit_sha；
7. 执行 git status；
8. 生成仓库摘要；
9. 写 git_clone_trace；
10. 写 repository_artifact；
11. 写 source_import_evidence_candidate；
12. 更新 Repository Ref 和 Integration 状态。
```

### 7.3 Pull / Fetch 流程

```text
1. 读取 Repository Ref；
2. 校验 credential_status；
3. 检查工作区是否有未提交变更；
4. 执行 Policy Check；
5. 必要时创建 Gate；
6. 执行 git fetch / pull；
7. 记录 before_commit_sha 和 after_commit_sha；
8. 写 git_sync_trace；
9. 更新 repository status；
10. 生成同步摘要。
```

### 7.4 失败处理

```text
repository_unreachable；
credential_missing；
credential_invalid；
branch_not_found；
clone_failed；
pull_conflict；
workspace_dirty；
network_error；
redaction_required。
```

规则：

```text
1. Git URL 中不得展示明文 token；
2. credential_invalid 不得返回密钥片段；
3. clone 成功不等于 P0 completed；
4. pull 冲突必须阻塞并展示 next_actions；
5. 工作区未提交变更时不得静默覆盖；
6. git output 必须脱敏。
```

## 9. 源码同步动作分类

源码同步动作按风险和语义分为三类。

### 9.1 读取类动作

```text

git log；
git diff read；
git branch list；
git fetch；
repository metadata read。
```

要求：

```text
Policy Check；
Trace；
输出脱敏；
不得改变 Workspace 或远端仓库。
```

### 9.2 本地变更类动作

```text

git branch create；
git add；
git commit；
patch generate；
patch apply；

```

要求：

```text
Policy Check；
必要 Gate；
Trace；
必要 Audit；
变更摘要；
可回滚或补救说明。
```

### 9.3 远端写类动作

```text
git push；
remote branch create；
remote branch delete；
tag push；

```

要求：

```text

用户 Gate；
Audit；
Trace；
目标仓库和分支摘要；
diff 摘要；
失败处理；
不得自动重试高风险远端写。
```

## 10. Branch / Diff / Commit / Push 流程

### 10.1 Branch 流程

```text
1. 读取 Repository Ref；
2. 查询当前分支；
3. 检查目标分支是否存在；
4. 执行 Policy Check；
5. 如创建或切换分支涉及工作区风险，触发 Gate；
6. 执行 checkout / branch create；
7. 写 git_branch_trace；
8. 更新 current_branch。
```

### 10.2 Diff 流程

```text
1. 读取当前 Workspace 状态；
2. 执行 git diff；
3. 生成脱敏 diff 摘要；
4. 写 git_diff_trace；
5. 将 diff 摘要作为 Artifact candidate；
6. 前端展示 diff 和风险提示。
```

### 10.3 Commit 流程

```text
1. 读取 diff 摘要；
2. 校验变更范围；
3. 执行 Policy Check；
4. 必要时触发 Gate；
5. 执行 git add / commit；
6. 写 git_commit_trace；
7. 必要时写 Audit；
8. 更新 commit_sha；
9. 生成变更摘要 Artifact。
```

### 10.4 Push 流程

```text
1. 读取 Repository Ref；
2. 读取当前分支和 commit_sha；
3. 生成 push 目标摘要；
4. 生成 diff / commit 摘要；
5. 执行 Policy Check；
6. 创建用户 Gate；
7. 用户授权后执行 git push；
8. 写 git_push_trace；
9. 写 git_remote_write_audit；
10. 更新 repository status；
11. 返回成功或失败摘要。
```

规则：

```text
1. Push 未经用户 Gate 不得执行；
2. Push 成功不等于 P6 交付通过；
3. Push 失败不得自动无限重试；
4. Push 输出不得包含 token；
5. Push 审核必须让用户看到目标仓库、目标分支和变更摘要。
```

## 11. Workspace 初始化与同步

Workspace 初始化流程：

```text
1. 创建 project workspace root；
2. 创建 code_root；
3. 创建 artifacts_root；
4. 创建 evidence_root；
5. 创建 runs_root；
6. 写 workspace_init_trace；
7. 记录 workspace_ref；
8. 与 Source Integration 绑定。
```

同步规则：

```text
1. Workspace 必须按 project_id 隔离；
2. 不得将不同 Project 的源码混放；
3. 不得在 archive 中直接施工；
4. 不得将临时目录作为长期事实源；
5. Workspace 状态应可通过后端查询恢复；
6. 前端显示不得依赖浏览器缓存。
```

## 13. Gate 策略

Gate 类型建议：

```text
source_import_gate；
workspace_overwrite_gate；
git_dirty_workspace_gate；
git_branch_switch_gate；
git_commit_gate；
git_remote_write_gate；
credential_reconfigure_gate；

```

规则：

```text
1. P0 晋级 P1 必须用户 Gate；

3. 工作区覆盖风险必须 Gate；
4. dirty workspace 被覆盖风险必须 Gate；
5. Policy blocked 不得通过 Gate 继续；
6. Gate 决策必须 Audit。
```

## 14. 凭据与脱敏

凭据只能通过引用进入流程：

```text
credential_ref；
credential_type；
credential_status；
permission_scope；
provider；
redaction_status。
```

不得展示：

```text
Key；
Token；
Secret；
Password；
SSH private key；
GitHub token；
Git remote URL 中的 token；
.env 明文；
连接串明文；
可还原密钥片段。
```

凭据状态建议：

```text
missing；
provided；
valid；
invalid；
expired；
permission_limited；
redaction_required；
unknown。
```

规则：

```text
1. credential_invalid 不返回密钥片段；
2. credential_missing 不得伪装可接入；
3. permission_limited 必须说明受限能力；
4. redaction_required 必须阻止原文展示；
5. 历史 env 或旧配置不得直接复制为当前凭据。
```

## 18. 与后续流程的关系

项目接入与源码同步为后续阶段提供输入：

```text
P1 建档：使用源码结构、文件清单、仓库摘要；
P2 评估：使用技术栈、依赖、仓库状态、历史变更；
P3 规划：使用分支、变更范围和执行边界；
P4 执行：使用 Workspace、Git 状态、diff 和 commit 流程；
P5 验证：使用 commit / diff / build / test / run 证据；
P6 交付：使用变更摘要、交付包、Git push 或 PR / MR 候选。
```

规则：

```text
1. 后续阶段不得绕过 Source Integration；
2. P4 写盘前应读取当前 Git 状态；
3. P5 验证应引用当前 Workspace 和 commit 状态；
4. P6 交付不得引用未验证变更；
5. Git push 或 PR / MR 创建不替代 P6 用户交付确认。
```
