## 1. 阶段契约总览

P0-P6 各阶段定位：

| 阶段 | 一句话目标 | 核心输出 |
|---|---|---|
| P0 接入 | 确认项目来源、材料和接入方式 | 接入记录、Workspace、材料清单 |
| P1 建档 | 识别结构/配置/依赖，建立项目档案 | 项目档案、Environment Profile 草案 |
| P2 评估 | 评估风险/可行性/阻塞项 | 评估报告、风险清单、不确定项清单 |
| P3 规划 | 形成方案/计划/任务图 | Stage Plan、Task Plan、TaskGraph |
| P4 执行 | 按计划受控执行迁移/重构 | 代码变更、Patch、执行 Evidence |
| P5 验证 | 证明迁移/重构正确性 | 验证 Evidence、回归对比、差异登记 |
| P6 交付 | 整理交付包与证据链 | 交付包、交付说明、遗留风险 |

每个阶段契约包含 12 个要素（统一模板）：

```text
1. 阶段目标 + 不负责边界
2. 进入条件
3. 输入
4. Agent/Skill/资源动作
5. 核心产出物
6. Artifact
7. Evidence（至少证明什么）
8. Gate（用户确认什么）
9. 完成条件
10. 失败/返工/跳过处理
```

通用规则（不逐阶段重复）：

```text
- 阶段状态枚举见 02-架构设计/03-Project-Run-TaskGraph状态架构.md
- skipped ≠ completed；completed 必须满足该阶段全部完成条件
- waiting_gate 必须关联 active_gate
- failed/rework_required 必须有 Trace；高风险失败必须有 Audit
- 状态变化进入 event log
- 阶段字段名（project_id/run_id/stage/stage_status/execution_mode 等）为 R1 建议，R4 实现时校准
- 如现有资料出现 mission_id，R2 必须校准为 run_goal/objective/task_group_id 或删除（D-070）
```

## 2. P0 接入阶段契约

### 2.1 阶段目标

确认用户项目来源、材料状态、接入方式、权限边界和初始风险，为 P1 建档建立可信输入。

P0 不负责：完整理解项目业务、完整评估迁移风险、生成迁移方案、修改代码、验证正确性、交付项目。

### 2.2 进入条件

```text
1. 用户已创建 Project；
2. 用户明确项目来源或至少提供可接入材料；
3. Project Workspace 可创建或已存在；
4. 当前 Project 不与其他 Project Workspace 混用；
5. 安全和密钥脱敏规则已生效。
```

### 2.3 输入

```text
Project 基础信息、接入来源类型（本地目录/Git/ZIP/GitHub）、用户提供的材料、接入权限声明、初始目标或说明、项目范围备注。
```

### 2.4 Agent/Skill/资源动作

```text
1. 检查接入来源类型与可达性；
2. 创建或初始化 Project Workspace；
3. 读取材料清单和源码入口；
4. 识别明显权限或材料缺失；
5. 登记初始风险和不确定项；
6. 生成接入摘要；
7. 生成接入 Evidence；
8. 准备 P0→P1 Gate 内容。
```

### 2.5 核心产出物

```text
接入摘要、Project Workspace 初始化记录、接入来源记录、材料清单、初始风险与缺口清单、P0 Evidence、P0 Trace、P1 进入建议。
```

### 2.6 Artifact

```text
项目接入记录、材料清单 Artifact、Workspace 初始化 Artifact、来源引用 Artifact。
```

### 2.7 Evidence

P0 Evidence 至少证明：

```text
1. 项目来源已识别；
2. Project Workspace 已创建或确认；
3. 接入材料已登记；
4. 接入权限或限制已记录；
5. 如接入失败，失败原因已记录。
```

### 2.8 Gate

P0→P1 必须用户 Gate。用户确认：

```text
1. 是否接受当前接入材料；
2. 是否进入 P1 建档；
3. 是否补充材料；
4. 是否取消或暂停项目；
5. 是否调整 Project 范围。
```

### 2.9 完成条件

```text
1. Project Workspace 已初始化或确认；
2. 接入来源已登记；
3. 材料清单已生成；
4. 初始风险和缺口已登记；
5. P0 Artifact 已生成；
6. P0 Evidence 已生成；
7. Trace 已记录；
8. P0→P1 用户 Gate 已完成。
```

### 2.10 失败/返工/跳过

```text
失败：接入来源不可访问、权限不足、材料损坏、Workspace 初始化失败。
返工：用户补充材料、修改接入方式、调整 Project 范围后重新进入 P0。
跳过：P0 原则上不建议跳过；如历史项目已完成接入，必须有等价 Evidence 才可标记 skipped/not_applicable。
```

## 3. P1 建档阶段契约

### 3.1 阶段目标

在不修改业务代码的前提下，识别项目结构、配置、依赖、文档材料、运行环境需求和初始事实，为 P2 评估提供可信项目档案。

P1 不负责：输出最终迁移方案、执行大规模代码修改、完整验证运行正确性、代替 P2 风险评估、代替 P5 验证。

### 3.2 进入条件

```text
1. P0 completed 或有等价接入 Evidence；
2. Project Workspace 可读取；
3. 接入材料清单存在；
4. 没有阻塞建档的权限问题；
5. 用户已授权进入 P1。
```

### 3.3 输入

```text
Project Workspace、源码与材料清单、接入 Evidence、用户目标说明、项目范围、已知风险或限制、历史参考材料索引（如适用，只读）。
```

### 3.4 Agent/Skill/资源动作

```text
1. 扫描源码目录结构；
2. 识别语言、框架、构建工具和依赖；
3. 识别配置文件和环境变量需求；
4. 识别测试目录和运行入口；
5. 识别项目文档、说明和历史材料；
6. 生成 Environment Profile 草案；
7. 生成项目档案；
8. 登记建档不确定项；
9. 生成建档 Evidence；
10. 准备 P1→P2 Gate 内容。
```

### 3.5 核心产出物

```text
项目档案 Artifact、源码结构摘要、配置与依赖摘要、测试与运行入口摘要、Environment Profile 草案、材料身份归类、建档不确定项、P1 Evidence、P1 Trace。
```

### 3.6 Artifact

```text
项目档案、源码结构索引、依赖与配置清单、Environment Profile 草案、材料身份分类记录。
```

### 3.7 Evidence

P1 Evidence 至少证明：

```text
1. 建档扫描范围；
2. 关键文件和目录确实存在或明确缺失；
3. 依赖和配置识别来源；
4. Environment Profile 草案来源；
5. 未确认项已登记。
```

### 3.8 Gate

P1→P2 必须用户 Gate。用户确认：

```text
1. 是否接受当前项目档案；
2. 是否需要补充材料；
3. 是否允许进入 P2 评估；
4. 是否修正项目范围或目标；
5. 是否确认 Environment Profile 草案作为评估输入。
```

### 3.9 完成条件

```text
1. 项目档案已生成；
2. 源码结构、配置、依赖、运行入口已识别或明确缺失；
3. Environment Profile 草案已生成或明确无法生成原因；
4. 材料身份已分类；
5. 不确定项已登记；
6. P1 Artifact 已生成；
7. P1 Evidence 已生成；
8. Trace 已记录；
9. P1→P2 用户 Gate 已完成。
```

### 3.10 失败/返工/跳过

```text
失败：Workspace 不可读、源码结构不可识别、关键材料缺失且无法继续。
返工：补充材料、重新扫描、修正 Environment Profile 草案后重新进入 P1。
跳过：仅当已有等价项目档案和 Evidence 时可 skipped/not_applicable。
```

## 4. P2 评估阶段契约

### 4.1 阶段目标

基于 P1 项目档案，对迁移/重构可行性、风险、阻塞项、复杂度、不确定项和验证缺口进行评估，为 P3 规划提供可信依据。

P2 不负责：最终选择实施方案、执行代码修改、替代 P3 规划、替代 P5 验证、用模型判断直接代替 Evidence。

### 4.2 进入条件

```text
1. P1 completed 或有等价项目档案 Evidence；
2. 项目档案可读取；
3. Environment Profile 草案可读取或缺失原因明确；
4. 用户已授权进入 P2。
```

### 4.3 输入

```text
项目档案、源码结构摘要、配置与依赖摘要、Environment Profile 草案、用户目标、范围基准、历史参考索引（如适用，只读）、P1 Evidence。
```

### 4.4 Agent/Skill/资源动作

```text
1. 识别迁移/重构风险；
2. 识别阻塞项；
3. 识别不确定项；
4. 评估技术栈和依赖风险；
5. 评估环境和运行风险；
6. 评估验证缺口；
7. 评估是否需要确定性转换资源；
8. 调用模型或知识资源辅助分析（模型输出标记为辅助分析，非事实）；
9. 生成评估报告 Artifact；
10. 生成评估 Evidence；
11. 准备 P2→P3 Gate 内容。
```

### 4.5 核心产出物

```text
评估报告、风险清单、阻塞项清单、不确定项清单、验证缺口清单、资源需求建议、P2 Evidence、P2 Trace。
```

### 4.6 Artifact

```text
迁移/重构风险评估 Artifact、阻塞项 Artifact、验证缺口 Artifact、资源需求建议 Artifact。
```

### 4.7 Evidence

P2 Evidence 至少证明：

```text
1. 评估基于哪些输入；
2. 风险判断依据；
3. 阻塞项来源；
4. 验证缺口来源；
5. 模型输出如被使用，已标记为辅助分析而非事实本身。
```

### 4.8 Gate

P2→P3 必须用户 Gate。用户确认：

```text
1. 是否接受风险评估；
2. 是否先处理阻塞项再进入 P3；
3. 是否进入 P3 规划；
4. 是否调整范围；
5. 是否指定优先级、约束或禁区。
```

### 4.9 完成条件

```text
1. 风险清单已生成；
2. 阻塞项和不确定项已登记；
3. 验证缺口已登记；
4. 资源需求建议已生成或明确无需求；
5. P2 Artifact 已生成；
6. P2 Evidence 已生成；
7. Trace 已记录；
8. P2→P3 用户 Gate 已完成。
```

### 4.10 失败/返工/跳过

```text
失败：输入材料不足以评估、关键事实冲突、用户目标不清且无法判断。
返工：补充建档、重新评估特定风险、调整范围后重新进入 P2。
跳过：仅当用户明确裁剪且有等价评估 Evidence 时可 skipped/not_applicable。
```

## 5. P3 规划阶段契约

### 5.1 阶段目标

基于 P2 评估，形成可执行、可授权、可验证、可追踪的迁移/重构方案、Stage Plan、Task Plan/Task Plan Batch 和 TaskGraph。

P3 不负责：未经授权直接执行代码修改、用计划替代执行、用计划替代验证、隐藏高风险动作、让 TaskGraph 越过 Gate。

### 5.2 进入条件

```text
1. P2 completed 或有等价评估 Evidence；
2. 风险、阻塞项、不确定项已处理或登记；
3. 用户已授权进入 P3；
4. 当前范围和目标明确到足以规划。
```

### 5.3 输入

```text
P2 评估报告、风险清单、阻塞项清单、验证缺口清单、项目档案、Environment Profile 草案、用户范围和约束、可用资源清单。
```

### 5.4 Agent/Skill/资源动作

```text
1. 形成迁移/重构方案；
2. 生成或更新 Stage Plan；
3. 生成 Task Plan/Task Plan Batch；
4. 生成 TaskGraph（如需）；
5. 显式定义 TaskGraph 边策略（串行/并行/失败/重试/合并）；
6. 定义风险等级和权限边界；
7. 定义 Artifact/Evidence 期望；
8. 定义 P4 执行策略和 P5 验证策略；
9. 准备 P3→P4 Gate 内容。
```

### 5.5 核心产出物

```text
迁移/重构方案、Stage Plan、Task Plan/Task Plan Batch、TaskGraph（或明确无需 TaskGraph 的原因）、风险与权限边界、执行与验证策略、P3 Evidence、P3 Trace。
```

### 5.6 Artifact

```text
方案 Artifact、Stage Plan Artifact、Task Plan Artifact、TaskGraph Artifact、Gate 策略 Artifact、验证策略 Artifact。
```

### 5.7 Evidence

P3 Evidence 至少证明：

```text
1. 方案来源于 P2 评估；
2. Task Plan 覆盖目标范围；
3. TaskGraph 边策略显式（如适用）；
4. 高风险动作已标识；
5. P5 验证方法已纳入计划；
6. 未解决不确定项已登记。
```

### 5.8 Gate

P3→P4 必须用户 Gate。用户确认：

```text
1. 是否接受迁移/重构方案；
2. 是否接受 Stage Plan；
3. 是否接受 Task Plan/Task Plan Batch；
4. 是否接受 TaskGraph 和执行顺序；
5. 是否接受风险和权限边界；
6. 是否允许进入 P4 执行。
```

### 5.9 完成条件

```text
1. 方案已形成；
2. Stage Plan 已形成；
3. Task Plan/Task Plan Batch 已形成；
4. TaskGraph 已形成或明确无需 TaskGraph；
5. 风险、权限、Gate 策略已明确；
6. 验证策略已明确；
7. P3 Artifact 已生成；
8. P3 Evidence 已生成；
```

### 6.4 Agent/Skill/资源动作

## 7. P5 验证阶段契约

### 7.1 阶段目标

证明迁移/重构结果的正确性、可运行性和可交付性，形成可验证 Evidence。P5 是产品核心壁垒之一——不是生成报告，而是产出可验证证据。

P5 不负责：用"看起来完成"替代验证、用模型判断替代验证、用预览成功替代关键行为验证、用构建成功替代回归验证、在 Evidence 不足时标记 completed。

### 7.2 进入条件

```text
1. P4 completed 或有等价执行 Artifact/Evidence；
2. 待验证产物明确；
3. Environment Profile 可用于构建/测试/运行，或缺失原因已登记；
4. 验证策略已存在（P3 产出）；
5. 用户已授权进入 P5。
```

### 7.3 输入

```text
P4 代码变更、Patch、执行 Artifact、P4 Evidence、Environment Profile、测试入口、回归基线、关键行为清单、验证策略、用户验收要求。
```

### 7.4 Agent/Skill/资源动作

```text
1. 执行构建验证；
2. 执行运行/启动验证；
3. 执行测试保留检查（原有测试是否仍通过）；
4. 执行测试生成或补充；
5. 执行回归基线对比；
6. 执行关键行为等价或差异显式登记；
7. 调用确定性验证资源；
8. 收集验证 Evidence；
9. 生成验证报告 Artifact；
10. 失败时生成返工建议（含回退阶段建议）；
11. 准备 P5→P6 Gate 内容。
```

### 7.5 核心产出物

```text
构建验证结果、运行/启动验证结果、测试结果（保留+生成）、回归基线对比、关键行为等价或差异登记、验证 Evidence、验证报告、返工建议、P6 交付准备建议。
```

### 7.6 Artifact

```text
验证报告 Artifact、构建结果 Artifact、测试结果 Artifact、回归对比 Artifact、关键行为差异登记 Artifact。
```

### 7.7 Evidence

P5 Evidence 至少覆盖：

```text
1. 构建可成功，或失败原因明确；
2. 运行/启动可达，或失败原因明确；
3. 测试保留与生成结果（含通过/失败明细）；
4. 回归基线对比结果；
5. 关键行为等价或差异显式登记；
6. 验证不通过项和返工建议。
```

验证正确性分层与信创目标栈等价判定细则见 `文档/08-测试与验收/02-迁移正确性与验证策略.md`。

### 7.8 Gate

P5→P6 必须用户 Gate。用户确认：

```text
1. 是否接受验证结果；
2. 是否允许进入 P6 交付；
3. 是否要求返工（含返工阶段建议）；
4. 是否接受差异和遗留风险；
5. 是否补充验证要求。
```

### 7.9 完成条件

```text
1. 构建验证已执行并记录；
2. 运行/启动验证已执行并记录；
3. 测试保留与生成已处理；
4. 回归基线对比已处理；
5. 关键行为等价或差异已登记；
6. P5 Artifact 已生成；
7. P5 Evidence 已生成且足够支撑结论；
8. Trace 已记录；
9. 高风险或关键裁决 Audit 已记录；
10. 验证失败项已进入返工或用户确认；
11. P5→P6 用户 Gate 已完成。
```

### 7.10 失败/返工/跳过

```text
失败：构建失败、启动失败、测试失败、关键行为不等价、Evidence 不足以支撑结论。
返工：返回 P4 执行修复，必要时返回 P3 调整计划。
跳过：P5 原则上不得跳过；如用户强制裁剪，必须显式登记高风险并不得标记为"验证通过"。
```
