## 1. 流程定位

远程环境与执行会话规范服务于 P4 执行、P5 验证、P6 交付，并支撑 R8 工作区真实化、R11 执行链路和 R12 验证交付链路。

其核心目标是：

```text
1. 声明项目可用执行环境；
2. 将执行动作放入按需隔离的 Execution Session；
3. 区分本地执行、远程执行和运行态服务；
4. 支撑命令、构建、测试、运行、日志和健康检查；
5. 记录执行 Trace；
6. 对高风险动作写 Audit；
7. 对敏感输出脱敏；
8. 支撑状态恢复；
9. 为 P5 验证提供 Evidence candidate；
10. 防止执行成功被误写成业务完成。
```

## 2. 核心对象

### 2.1 Environment Profile

Environment Profile 是执行环境的声明化描述，不等同于实际连接状态。

建议字段：

```text
environment_id；
project_id；
environment_name；
environment_type；
connection_profile_ref；
workspace_mount_ref；
capabilities；
credential_ref；
credential_status；
network_scope；
redaction_status；
status。
```

`environment_type` 建议值：

```text
local；
remote_host；
container；
remote_workspace；
cluster；
cloud。
```

### 2.2 Execution Session

Execution Session 是按需创建、按需隔离的执行会话。

建议字段：

```text
session_id；
project_id；
run_id；
stage_id；
environment_ref；
workspace_ref；
session_type；
status；
started_at；
updated_at；
active_processes；
active_gate；
trace_refs；
audit_refs；
output_refs；
redaction_status。
```

`session_type` 建议值：

```text
command；
build；
test；
runtime；
shell；
mixed。
```

规则：

```text
1. Session 不是长期事实源——Stage/Run 完成后可回收；
2. Session 状态与 Workspace 状态、Runtime State 分离；
3. Session 关闭不等于任务完成；
4. Session 输出必须脱敏；
5. Session 失败必须保留可复核摘要。
```

### 2.3 Execution Command

Execution Command 表示一次命令、构建、测试或运行动作，是 Execution Session 内的最小执行单元。

建议字段：

```text
command_id；
session_id；
command_type；
command_summary；
risk_level；
policy_check_ref；
gate_ref；
started_at；
finished_at；
exit_code；
stdout_ref；
stderr_ref；
output_redaction_status；
trace_ref；
audit_ref；
status。
```

`command_type` 建议值：

```text
shell；
build；
test；
runtime_start；
runtime_stop；
health_check；
script；
custom。
```

规则：

```text
1. 一个 Session 可包含多个 Execution Command；
2. 每个 Command 独立映射风险级别；
3. Command exit_code=0 不等于业务完成；
4. Command 输出必须脱敏；
5. 高风险 Command 必须独立 Gate / Audit。
```

## 3. 环境类型与执行边界

### 3.1 本地环境

```text
本地命令执行；
本地构建；
本地测试；
本地服务运行；
Workspace 直接读写。
```

要求：仍须 Trace、脱敏；高风险动作仍须 Gate / Audit。

### 3.2 远程主机

```text
SSH 连接；
远程命令执行；
远程构建；
远程测试；
远程服务启动；
远程日志回传。
```

要求：连接配置不得含明文密码或私钥；输出必须脱敏；连接状态不得替代执行结果。

### 3.3 容器

```text
容器创建；
容器内命令执行；
容器内构建；
容器内测试；
容器日志收集；
容器回收。
```

要求：容器不作为状态事实源；image 来源必须登记；容器内凭据引用必须脱敏。

### 3.4 远程 Workspace

```text
远程文件同步或挂载；
远程代码编辑；
远程 Patch 应用；
远程构建；
远程运行。
```

要求：Workspace 同步状态可追踪；不得与本地 Workspace 混淆；断开后状态可恢复。

## 4. 环境声明与注册流程

```text
1. 创建 Environment Profile；
2. 声明 environment_type；
3. 配置 connection_profile_ref；
4. 声明 capabilities；
5. 配置 credential_ref；
6. 声明 workspace_mount_ref；
7. 执行 Policy Check；
8. 检查 credential_status；
9. 执行环境探测；
10. 写 environment_probe_trace；
11. 生成 environment_profile_artifact；
12. 更新 status。
```

规则：

```text
1. 未声明不得执行；
2. credential_missing 不得伪装可用；
3. 环境探测成功不等于环境可用；
4. 环境探测失败必须记录错误摘要；
5. Environment Profile 可被多个 Session 引用。
```

### 4.1 环境探测流程

环境探测用于确认环境基本可达和能力摘要，是 Environment Profile 注册后的必要验证步骤，但不等于环境验证通过。

```text
1. 读取已注册的 Environment Profile；
2. 校验 credential_status；
3. 执行 Policy Check；
4. 必要时创建 environment_probe_gate；
5. 创建临时 Execution Session；
6. 执行连接探测；
7. 执行基础命令探测；
8. 执行路径和权限探测；
9. 执行工具链摘要探测；
10. 脱敏所有探测输出；
11. 写 environment_probe_trace；
12. 写 environment_probe_artifact；
13. 关闭或保留临时 Session；
14. 更新 Environment Profile 状态。
```

探测项建议：

```text
connection_reachable；
workspace_accessible；
command_available；
build_tool_summary；
test_tool_summary；
runtime_capability_summary；
permission_scope；
redaction_status。
```

规则：

```text
1. connection_reachable 不等于 environment_verified；
2. environment_probe_artifact 不自动成为 Evidence validated；
3. 探测输出必须脱敏；
4. 探测失败不得显示环境可用；
5. 探测命令本身也必须记录 Trace；
6. 探测结果应作为后续 Session 创建的参考输入。
```

## 5. Execution Session 生命周期

### 5.1 创建

```text
1. 读取 Environment Profile；
2. 检查 environment status；
3. 检查 project / run / stage 上下文；
4. 执行 Policy Check；
5. 创建 Session；
6. 初始化 workspace_ref；
7. 写 session_create_trace；
8. 返回 session_id。
```

### 5.2 执行

```text
1. 接收执行请求；
2. 检查 session status；
3. 映射动作风险级别；
4. 执行 Policy Check；
5. 必要时触发 Gate；
6. 执行命令 / 构建 / 测试 / 运行；
7. 捕获输出；
8. 脱敏输出；
9. 写 execution_trace；
10. 必要时写 Audit；
11. 更新 session status。
```

### 5.3 关闭

```text
1. 检查活动进程；
2. 必要时回收资源；
3. 保存必要日志；
4. 写 session_close_trace；
5. 更新 session status；
6. 必要时写 close_audit。
```

规则：

```text
1. Session 关闭前必须保存必要 Trace；
2. 活动进程被强制终止必须记录；
3. Session 关闭不等于任务验收通过；
4. Session 状态应可恢复——关闭后仍可查询；
5. 用户退出 UI 不等于 Session 关闭。
```

### 5.4 暂停

```text
1. 用户或系统请求暂停；
2. 检查当前命令状态；
3. 对可暂停的 Session 执行暂停；
4. 保存当前输出引用；
5. 写 session_pause_trace；
6. 更新 Session 状态为 paused。
```

### 5.5 恢复

```text
1. 查询 Session 状态（必须为 paused）；
2. 校验 Environment 和 Workspace 状态；
3. 执行 Policy Check；
4. 必要时触发 session_resume_gate；
5. 恢复 Session；
6. 写 session_resume_trace；
7. 更新 Session 状态为 active。
```

规则：

```text
1. 退出 UI 不等于停止任务——Session 可在后台继续；
2. 需要人工介入的动作（Gate 等待、冲突解决）必须暂停等待授权；
3. 高风险动作（L4-L5）执行中不得静默暂停——必须先完成或安全中断；
4. 暂停期间 Workspace 状态冻结——不得被其他 Session 修改；
5. 恢复时必须重新校验 Environment 和 credential_status；
6. Session 异常终止必须可见并保留 error_ref。
```

## 6. 命令执行流程

```text
1. 接收命令请求；
2. 选择或创建 Execution Session；
3. 识别 command_type；
4. 映射风险级别；
5. 执行 Policy Check；
6. 必要时创建 Gate；
7. 在 Session 中执行命令；
8. 捕获 stdout / stderr / exit_code；
9. 脱敏输出；
10. 写 command_trace；
11. 必要时写 command_audit；
12. 生成 output_ref；
13. 返回结构化结果。
```

规则：

```text
1. exit_code=0 不等于业务完成；
2. 命令输出不自动成为 Evidence validated；
3. 高风险命令不得自动执行；
4. 命令超时必须可中止；
5. 命令失败必须保留错误摘要；
6. 命令日志必须脱敏。
```

## 7. 构建流程

```text
1. 检查 build_environment；
2. 选择或创建 Execution Session；
3. 校验 build 依赖和工具链；
4. 执行 Policy Check；
5. 必要时创建 build_gate；
6. 执行构建命令或脚本；
7. 捕获构建输出；
8. 检查构建产物；
9. 脱敏输出；
10. 写 build_trace；
11. 必要时写 build_audit；
12. 生成 build_output_artifact；
13. 生成 build_evidence_candidate；
14. 更新 Session 状态。
```

规则：

```text
1. 构建成功不等于测试通过；
2. 构建产物必须可复现；
3. 构建输出必须脱敏；
4. 构建失败必须保留错误日志；
5. 构建必须在受控 Session 中执行。
```

## 8. 测试流程

```text
1. 检查 test_environment；
2. 选择或创建 Execution Session；
3. 读取测试范围和契约；
4. 执行 Policy Check；
5. 必要时创建 test_gate；
6. 执行测试命令或框架；
7. 捕获测试输出；
8. 脱敏输出；
9. 写 test_trace；
10. 必要时写 test_audit；
11. 记录通过 / 失败 / 跳过 / 错误；
12. 生成 test_report_artifact；
13. 生成 test_evidence_candidate；
14. 进入 P5 验证。
```

规则：

```text
1. 测试通过不等于 P5 completed；
2. 测试结果必须进入 P5 验证流程；
3. 测试失败必须保留完整错误摘要；
4. 回归测试必须可对比基线；
5. 关键行为等价或差异必须登记。
```

## 9. 运行 / 服务启动流程

```text
1. 检查 runtime_environment；
2. 选择或创建 Execution Session；
3. 明确 session_type=runtime；
4. 执行 Policy Check；
5. 必要时创建 runtime_gate；
6. 启动服务或应用；
7. 执行健康检查；
8. 暴露预览或访问端点；
9. 写 runtime_start_trace；
10. 持续记录 runtime log；
11. 必要时写 runtime_audit；
12. 生成 runtime_evidence_candidate。
```

规则：

```text
1. 服务启动不等于业务正确；
2. 健康检查通过不等于功能完整；
3. Runtime State 必须与 Execution State 分离；
4. 服务停止必须记录并通知；
5. 运行日志必须脱敏；
6. 预览端点不得暴露凭据。
```

## 10. 日志与输出管理

日志处理规则：

```text
1. 执行日志必须脱敏；
2. 日志必须绑定 trace_ref；
3. 日志不自动成为 Evidence；
4. 错误日志必须保留并可见；
5. 敏感文件内容不得进入日志；
6. 日志保留策略待 R4 确定。
```

日志脱敏规则：

```text
1. Key / Token / Secret / Password → 替换为 credential_ref；
2. 连接串 → 脱敏为 host_only 或 redacted；
3. env 明文 → 仅记录存在状态；
4. SSH private key → 不得记录；
5. GitHub token → 替换为 credential_ref。
```

## 11. 状态恢复

可恢复状态来源：

```text
数据库；
LangGraph checkpoint；
workspace 文件；
Trace / Audit；
event log；
后端状态查询。
```

不可作为恢复源：

```text
浏览器缓存；
SSE 事件缓存；
终端窗口；
容器存在；
前端本地状态；
外部 Agent 自述。
```

恢复规则：

```text
1. Execution Session 关闭后仍可查询历史状态；
2. Workspace 文件状态可从后端查询重建；
3. Runtime State 不依赖 Session 存在；
4. 退出 UI 不等于任务中断——后台继续执行；
5. 重新进入工作区时应查询后端状态而非前端缓存。
```

## 12. Workspace 同步

远程环境下的 Workspace 同步规则：

```text
1. 远程执行前同步必要文件；

3. 同步前后记录 workspace_sync_trace；
4. 远程修改同步回本地前需 Policy Check；
5. 不得静默覆盖本地变更；
6. 同步冲突必须 Gate 并展示 next_actions。
```

## 17. 与 P0-P6 的关系

远程环境与执行会话在不同 P 阶段的使用边界：

```text
P0 接入：通常只需要 Workspace 初始化，不应强依赖远程执行；
P1 建档：可使用环境摘要辅助建档，不要求完整 Execution Session；
P2 评估：可使用环境探测辅助评估技术栈和依赖；
P3 规划：需要明确执行环境和验证计划，声明需要的 environment_type；
P4 执行：核心使用 Execution Session 执行命令、构建、测试预检查或运行；
P5 验证：使用构建、测试、运行和健康检查生成验证证据；
P6 交付：引用经验证的执行和运行证据生成交付材料。
```

规则：

```text
1. Environment Profile 的创建不改变 P0-P6 阶段；
2. Execution Session 的创建/关闭不决定 P 阶段晋级；
3. 构建 / 测试 / 运行结果必须进入 P5 验证流程；
4. P6 不得引用未验证的执行结果；
5. P 阶段晋级仍需用户 Gate；
6. P0-P3 不应强依赖远程环境——本地环境满足即可。
```
