## 0. 编写原则

本文遵守文档事实源层级（`文档地图.md` §1）：

```text
项目治理 > 产品定义 > 架构设计 > 专题规范
```

本文只展开 P0-P6 阶段验收清单，不重新定义上级事实。

本文必须遵守：

```text
1. P0-P6 是面向用户项目的可裁剪产品流程；
2. R0-RN 是 rebuild 当前版本自身建设阶段，两者不得混用；
3. 启用的 P 阶段必须具备 Gate、Artifact、Evidence 和完成条件；
4. 被裁剪掉的阶段不得伪装为已完成；
5. （P 阶段晋级 Gate、Policy 优先、Artifact 不自动晋升、Manual/Plan/Auto 边界等通用红线详见 AGENTS §18 + 01-决策记录）；
6. Stage Plan / Task Plan 审核不等于阶段晋级授权；
7. Evidence candidate 不自动成为 Evidence validated；
8. 模型输出、资源输出、命令输出不自动成为 Evidence validated；
9. P5 验证必须基于可验证证据（D-066，详见本目录 02-迁移正确性与验证策略.md）；
10. 验证不通过或证据不足时不得标记 completed；
11. No Evidence / No Trace, No Trusted Result；
12. 高风险动作必须 Gate / Audit；L5 高风险强制用户 Gate（D-034，详见 02-术语表 第七部分）；
13. 密钥与配置必须脱敏（不泄露，D-032）；
14. 当前版本不设独立 Mission 产品层（不引入 Mission，D-070）。
```

> 通用禁止与红线完整总表见 AGENTS.md §18；相关决策详见 01-决策记录.md；术语与风险级别（L0-L5）详见 02-术语表.md。

**本文特有禁止项**（通用禁止事项详见 AGENTS.md §18）：

```text
1. 不得把 P 阶段产物生成等同于该阶段完成（如 Project 创建≠P0 完成、计划生成≠P3 完成、代码就绪≠P5 完成）；
2. 不得把 Trace / Audit 当成 Evidence；
3. 不得把 Artifact / 模型输出 / 资源输出显示为 Evidence validated；
4. 不得把 mock / 未接真实服务写成真实通过。
```

> 通用禁止与红线完整总表见 AGENTS.md §18；相关决策详见 01-决策记录.md；术语与风险级别（L0-L5）详见 02-术语表.md。

## 1. 总体验收口径

P0-P6 每个启用阶段均应从以下维度验收：

```text
阶段目标；
前置条件；
输入材料；
核心产物；
Evidence（详见 02-术语表 第九部分）；
Trace（详见 02-术语表 第九部分）；
Audit（详见 02-术语表 第九部分）；
Gate（详见 02-术语表 第八部分）；
API / SSE；
前端展示；
安全与脱敏；
失败处理；
通过条件；
阻断红线。
```

共同通过条件：

```text
1. 阶段目标完成；
2. 必要产物齐备且身份明确；
3. 必要 Evidence 齐备且验证状态明确；
4. 必要 Trace 可追溯；
5. 需要 Audit 的动作已写 Audit；
6. 阶段晋级 Gate 已由用户授权；
7. 无未处理 P0 阻断缺陷；
8. 无密钥泄露；
9. 前端未误导用户；
10. 后端状态与前端展示一致。
```

> **产品级判定**：各阶段清单聚焦逐项检查；产品级"通过/不通过/有条件通过/待确认"的综合判定标准详见本目录 **`01-产品验收基准.md`**。

## 2. 通用检查清单

### 2.1 阶段状态检查

```text
是否存在 project_id；
是否存在 run_id；
当前阶段是否正确；
阶段是否启用；
阶段状态是否来自后端事实源；
被裁剪阶段是否显示 not_enabled / not_applicable；
阶段 completed 是否具备完成条件；
状态恢复后是否一致。
```

### 2.2 Artifact 检查

```text
Artifact 是否有 artifact_id；
Artifact 是否有关联 project_id / run_id / stage；
Artifact 类型是否明确；
Artifact 状态是否明确（详见 02-术语表 第九部分）；
Artifact 是否来源可追溯；
Artifact 是否脱敏；
Artifact 是否被错误显示为 Evidence；
Artifact 是否经过必要 Gate 或验收流程才进入正式区。
```

### 2.3 Evidence 检查

```text
Evidence 是否有 evidence_id；
Evidence 是否关联 claim / 验证目标；
Evidence 是否有关联 stage；
Evidence 是否有来源；
Evidence candidate 与 validated 是否区分；
Evidence Gap 是否可见；
Evidence 是否脱敏；
Evidence 是否可 Trace。
```

### 2.4 Trace / Audit 检查

```text
关键动作是否有 Trace；
Trace 是否不含密钥；
高风险动作是否有 Audit；
Gate 决策是否有 Audit；
Audit 是否不含密钥；
Trace / Audit 缺失是否前端可见；
状态恢复后 Trace / Audit 是否可查询。
```

### 2.5 Gate 检查

```text
阶段晋级 Gate 是否存在；
Gate 是否由用户授权；
Gate 决策是否写 Audit；
Gate 未决策是否阻塞晋级；
Policy blocked 是否不可批准继续；
L5 是否强制用户 Gate（详见 02-术语表 第七部分）；
Gate 决策后是否刷新后端状态。
```

## 3. P0 接入验收清单

### 3.1 验收目标

P0 接入用于确认用户项目已被安全、可追溯地接入到 rebuild，并建立 Project Workspace 初始状态。

P0 不等于迁移完成，也不等于源码质量已评估。

### 3.2 前置条件

```text
Project 已创建；
接入方式明确：本地目录 / Git / ZIP / GitHub；
project_id 已生成；
Workspace 初始路径或引用已建立；
安全与脱敏策略已生效；
接入动作可 Trace。
```

### 3.3 核心产物

```text
Project 记录；
Project Workspace 初始结构；
源码接入摘要；
接入方式记录；
初始文件清单摘要；
接入警告或错误记录；
P0 接入报告 / 摘要 Artifact。
```

### 3.4 Evidence 检查

```text
源码接入成功证据；
文件清单或项目结构证据；
Git / ZIP / 本地目录来源证据；
Workspace 隔离证据；
凭据脱敏证据；
接入失败时的错误证据。
```

### 3.5 Trace / Audit / Gate 检查

```text
接入动作 Trace；
Git / ZIP / 本地目录处理 Trace；
凭据状态 Trace；
高风险或外部系统写操作 Audit；
P0 晋级 P1 Gate；
用户阶段晋级授权 Audit。
```

### 3.6 前端检查

```text
项目已创建但未误显示为迁移完成；
接入状态清晰；
Workspace 入口可见；
接入错误可见；
凭据缺失 / 无效状态可见；
mock / not_connected 标记清晰（详见 00-测试与验收总览 §19）；
不泄露 Git token、路径敏感信息或 .env 明文。
```

### 3.7 P0 通过条件

```text
1. Project 和 Workspace 已建立；
2. 源码接入结果明确；
3. 接入来源和文件结构可追溯；
4. 必要 Evidence 存在；
5. 必要 Trace 存在；
6. 无密钥泄露；
7. P0 晋级 Gate 已由用户授权；
8. 后端状态为 P0 completed 或可进入 P1 的等价状态。
```

### 3.8 P0 阻断红线

```text
Project 创建成功但源码未接入却显示 P0 completed；
接入失败却显示成功；
Git token / .env / 配置明文泄露；
Workspace 未隔离；
P0 无 Trace；
P0 晋级无用户 Gate；
mock 接入显示为真实接入。
```

## 4. P1 建档验收清单

### 4.1 验收目标

P1 建档用于形成当前项目事实基础，区分项目文档、交接材料、产物、证据、运行记录和参考资料（材料身份详见 02-术语表 第九部分）。

P1 不等于已经完成评估或规划。

### 4.2 前置条件

```text
P0 已通过或用户明确授权进入 P1；
源码与 Workspace 可访问；
材料视图可区分材料身份；
Artifact / Evidence 基本对象可记录；
文件读取脱敏策略生效。
```

### 4.3 核心产物

```text
项目基础档案；
源码结构摘要；
技术栈初步识别；
依赖清单草稿；
材料身份登记；
初始 Artifact 列表；
初始 Evidence candidate 列表；
P1 建档摘要 Artifact。
```

### 4.4 Evidence 检查

```text
项目结构证据；
技术栈识别证据；
依赖识别证据；
材料来源证据；
Artifact 身份证据；
Evidence candidate 与 validated 区分证据；
敏感配置脱敏证据。
```

### 4.5 Trace / Audit / Gate 检查

```text
文件读取 Trace；
建档动作 Trace；
Artifact 创建 Trace；
Evidence candidate 创建 Trace；
敏感文件脱敏 Trace；
高风险读取或越界动作 Audit；
P1 晋级 P2 Gate；
用户阶段晋级授权 Audit。
```

### 4.6 前端检查

```text
材料视图能区分项目文档、交接材料、产物、证据、运行记录、参考资料；
Artifact 不被显示为 Evidence validated；
Evidence candidate 状态清晰；
敏感配置只显示存在状态或脱敏摘要；
P1 未误显示为评估完成。
```

### 4.7 P1 通过条件

```text
1. 项目基础事实已记录；
2. 材料身份清晰；
3. 初始 Artifact / Evidence candidate 清晰；
4. 敏感信息已脱敏；
5. 建档过程可 Trace；
6. Evidence Gap 已显式记录；
7. P1 晋级 Gate 已由用户授权。
```

### 4.8 P1 阻断红线

```text
未区分材料身份；
Artifact 自动显示为 Evidence；
Evidence candidate 显示为 validated；
敏感配置泄露；
建档无 Trace；
P1 无用户晋级 Gate；
旧版本材料自动成为当前事实源。
```

## 5. P2 评估验收清单

### 5.1 验收目标

P2 评估用于识别迁移范围、技术风险、依赖风险、改造点和不确定项。

P2 不等于已经形成执行计划。

### 5.2 前置条件

```text
P1 建档事实可用；
项目结构与依赖信息可查询；
评估所需资源可用或缺口明确；
模型 / 资源真实能力状态明确（详见 00-测试与验收总览 §19）；
风险分级策略可用（详见 02-术语表 第七部分）。
```

### 5.3 核心产物

```text
迁移范围评估；
技术栈评估；
依赖风险评估；
改造点清单；
不确定项清单；
风险分级摘要；
评估 Evidence candidate；
P2 评估报告 Artifact。
```

### 5.4 Evidence 检查

```text
评估结论对应来源证据；
依赖识别证据；
风险判断证据；
改造点来源证据；
不确定项证据；
模型 / 资源输出是否仅作为候选；
评估 Evidence Gap 是否可见。
```

### 5.5 Trace / Audit / Gate 检查

```text
模型调用 Trace；
资源调用 Trace；
评估生成 Trace；
高风险资源调用 Audit；
接受不确定项风险 Audit；
P2 晋级 P3 Gate；
用户阶段晋级授权 Audit。
```

### 5.6 前端检查

```text
风险和不确定项可见；
评估结论有来源引用；
模型输出不显示为验证结论；
资源输出不显示为 Evidence validated；
真实能力状态清晰；
P2 未误显示为规划完成。
```

### 5.7 P2 通过条件

```text
1. 迁移范围、风险、依赖、改造点已形成；
2. 评估结论有 Evidence 或 Evidence Gap；
3. 评估过程可 Trace；
4. 高风险资源调用已 Audit；
5. 不确定项不被隐藏；
6. P2 晋级 Gate 已由用户授权。
```

### 5.8 P2 阻断红线

```text
评估结论无来源；
模型输出直接成为最终评估事实；
风险未分级；
不确定项被隐藏；
高风险资源调用无 Gate / Audit；
P2 无用户晋级 Gate；
敏感配置泄露。
```

## 6. P3 规划验收清单

### 6.1 验收目标

P3 规划用于形成可执行、可审查、可追踪的 Stage Plan、Task Plan / Task Plan Batch、TaskGraph 和 Gate 策略。

P3 不等于已经执行迁移。

### 6.2 前置条件

```text
P2 评估结论可用；
改造点和风险清单可用；
执行模式明确：Manual / Plan / Auto（详见 02-术语表 第八部分）；
TaskGraph 边策略可表达；
Gate / Policy / Risk 策略可用。
```

### 6.3 核心产物

```text
Stage Plan；
Task Plan；
Task Plan Batch；
TaskGraph；
风险与权限边界；
Gate 策略；
Evidence 计划；
回滚 / 失败策略；
P3 规划报告 Artifact。
```

### 6.4 Evidence 检查

```text
计划依据证据；
任务拆分依据证据；
风险分级证据；
权限边界证据；
Evidence 计划是否覆盖 P5（D-066）；
计划缺口是否登记；
用户审核记录是否可审计。
```

### 6.5 Trace / Audit / Gate 检查

```text
规划生成 Trace；
TaskGraph 创建 Trace；
Stage Plan / Task Plan 审核 Trace；
计划审核 Gate；
风险接受 Audit；
P3 晋级 P4 Gate；
用户阶段晋级授权 Audit。
```

### 6.6 前端检查

```text
Stage Plan 可读；
Task Plan / Batch 范围清晰；
TaskGraph 关键节点可视；
风险级别和 Gate 策略可见；
Manual / Plan / Auto 模式差异可见；
计划通过不被显示为执行完成。
```

### 6.7 P3 通过条件

```text
1. Stage Plan / Task Plan / TaskGraph 齐备；
2. 风险、权限、Gate、Evidence 计划齐备；
3. 计划与 P2 评估结论可追溯；
4. 高风险计划项已标记 Gate / Audit；
5. 用户已完成必要计划审核；
6. P3 晋级 Gate 已由用户授权。
```

### 6.8 P3 阻断红线

```text
计划无风险边界；
Task Plan Batch 无范围、风险、权限和验收说明；
TaskGraph 边策略缺失；
计划审核被当作阶段晋级授权；
高风险动作未配置 Gate；
P3 无用户晋级 Gate；
P5 Evidence 计划缺失。
```

## 7. P4 执行验收清单

### 7.1 验收目标

P4 执行用于按 P3 规划完成迁移 / 重构动作，包括命令、Tool、MCP、Git、写盘、Patch、资源调用等真实执行链路。

P4 不等于 P5 验证通过。

### 7.2 前置条件

```text
P3 规划已通过；
执行模式明确；
命令 / Tool / MCP / Git / 写盘授权策略可用（详见 07-安全与权限/）；
Workspace 边界可用；
Policy / Hook 可用；
Gate / Audit / Trace 可用；
回滚或失败策略明确。
```

### 7.3 核心产物

```text
执行记录；
Patch generated / applied 记录；
变更文件清单；
命令执行摘要；
Tool / MCP 调用摘要；
Git 操作摘要；
执行 Artifact；
执行 Evidence candidate；
执行问题清单。
```

### 7.4 Evidence 检查

```text
变更结果证据；
Patch 应用证据；
命令执行证据；
Tool / MCP 输出证据；
执行失败证据；
回滚证据；
执行产物是否仅为 Evidence candidate；
敏感输出是否脱敏。
```

### 7.5 Trace / Audit / Gate 检查

```text
命令执行 Trace；
Tool / MCP 调用 Trace；
文件写入 Trace；
Patch apply Trace；
Git 操作 Trace；
高风险动作 Gate；
高风险动作 Audit；
Policy blocked Trace / Audit；
P4 晋级 P5 Gate；
用户阶段晋级授权 Audit。
```

### 7.6 前端检查

```text
执行进度可见；
命令输出脱敏；
Patch generated 与 applied 区分；
Git push / 外部写操作风险可见；
Gate 不被 toast 化；
执行成功不显示为验证通过；
Audit / Trace 缺失可见。
```

### 7.7 P4 通过条件

```text
1. 规划内执行项已完成或有明确失败 / 返工结论；
2. 所有关键执行动作可 Trace；
3. 高风险动作有 Gate / Audit；
4. 变更产物清晰；
5. 执行 Evidence candidate 齐备；
6. 无密钥泄露；
7. P4 晋级 Gate 已由用户授权。
```

### 7.8 P4 阻断红线

```text
命令 exit_code=0 被显示为业务完成；
Patch applied 被显示为验证通过；
高风险写盘无 Gate / Audit；
Git remote write 无 Gate / Audit；
Tool / MCP 输出直接成为 Evidence validated；
执行无 Trace；
执行输出泄露密钥；
P4 无用户晋级 Gate。
```

## 8. P5 验证验收清单

### 8.1 验收目标

P5 验证用于证明迁移 / 重构后的正确性、可运行性和可交付性。

P5 是可信交付的核心，不得以"看起来完成"或"代码就绪"通过。完整验证策略与证据槽位定义见本目录 **`02-迁移正确性与验证策略.md`**（D-066 详述源）。

### 8.2 前置条件

```text
P4 执行已完成或具备明确待验证范围；
变更文件和执行产物可查询；
验证计划可用；
验证环境或 Environment Profile 可用；
构建 / 运行 / 测试 / 回归策略可用；
Evidence 槽位明确（详见 02-迁移正确性与验证策略 §3）。
```

### 8.3 核心产物

```text
构建验证记录；
运行 / 启动验证记录；
测试执行记录；
回归基线对比记录；
关键行为等价 / 差异登记；
验证 Evidence；
Evidence Gap；
验证失败和返工建议；
P5 验证报告 Artifact。
```

### 8.4 Evidence 检查

```text
构建成功 Evidence；
运行 / 启动可达 Evidence；
测试保留 / 生成 Evidence；
测试执行 Evidence；
回归对比 Evidence；
关键行为等价 Evidence；
差异登记 Evidence；
验证失败 Evidence；
Evidence Gap 是否阻塞；
Evidence validated 是否来自后端验证状态。
```

### 8.5 Trace / Audit / Gate 检查

```text
构建 Trace；
运行 Trace；
测试 Trace；
回归对比 Trace；
验证结论 Trace；
接受差异或证据缺口 Audit；
P5 Evidence Gap Gate；
P5 晋级 P6 Gate；
用户阶段晋级授权 Audit。
```

### 8.6 前端检查

```text
验证证据槽位可见；
构建 / 运行 / 测试 / 回归状态清晰；
Evidence Gap 高亮；
验证失败不显示为 completed；
差异登记可见；
No Evidence / No Trace 时不显示可信完成；
密钥不出现在测试日志或报告中。
```

### 8.7 P5 通过条件

```text
1. 构建、运行、测试、回归、等价或差异登记具备必要证据；
2. Evidence validated 状态明确；
3. Evidence Gap 已关闭或经 Gate 接受风险并 Audit；
4. 验证过程可 Trace；
5. 验证报告不含密钥；
6. P5 晋级 Gate 已由用户授权；
7. 后端状态允许进入 P6。
```

### 8.8 P5 阻断红线

```text
代码就绪但无验证证据；
测试未跑却显示验证通过；
构建失败却显示 completed；
Evidence Gap 被隐藏；
Trace 缺失却显示可信完成；
Evidence candidate 显示为 validated；
接受差异风险无 Audit；
P5 无用户晋级 Gate；
测试日志泄露密钥。
```

## 9. P6 交付验收清单

### 9.1 验收目标

P6 交付用于形成可交付包、交付报告和可信证据链汇总。

P6 完成只代表基础主流程可交付，不代表所有增强能力完成。

### 9.2 前置条件

```text
P5 验证已通过或风险已被明确接受；
交付范围明确；
交付材料脱敏策略生效；
Evidence / Trace / Audit 汇总可查询；
交付 Gate 可用。
```

### 9.3 核心产物

```text
交付包；
交付报告；
变更摘要；
验证摘要；
Evidence 汇总；
Trace 汇总；
Audit 汇总；
已知差异和风险清单；
后续建议；
P6 交付记录。
```

### 9.4 Evidence 检查

```text
交付内容来源 Evidence；
P5 验证 Evidence 引用；
差异和风险 Evidence；
交付包完整性证据；
交付报告脱敏证据；
Evidence Gap 关闭或接受记录；
最终 Evidence 汇总是否可查询。
```

### 9.5 Trace / Audit / Gate 检查

```text
交付包生成 Trace；
交付报告生成 Trace；
交付 Gate；
用户交付确认 Audit；
Evidence Gap 风险接受 Audit；
高风险导出 Audit；
导出脱敏 Trace。
```

### 9.6 前端检查

```text
交付包状态清晰；
交付报告可预览；
Evidence / Trace / Audit 汇总可见；
已知风险和差异可见；
交付材料不含密钥；
P6 完成不暗示增强能力全部完成；
mock / not_connected 能力不被写成已交付。
```

### 9.7 P6 通过条件

```text
1. 交付包和交付报告齐备；
2. P5 验证证据可引用；
3. Evidence / Trace / Audit 汇总齐备；
4. 已知风险和差异显式登记；
5. 交付材料已脱敏；
6. 交付 Gate 已由用户确认；
7. 后端状态显示 P6 completed 或基础主流程交付完成。
```

### 9.8 P6 阻断红线

```text
P5 未通过却交付；
交付包无验证证据；
交付报告泄露密钥；
Evidence / Trace / Audit 汇总缺失但显示可信交付；
已知差异被隐藏；
交付 Gate 缺失；
P6 完成被写成增强能力全部完成。
```
