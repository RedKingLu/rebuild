## 0. 验收原则

```text
1. 验收围绕 rebuild 定位：软件重构与迁移（泛软件重构）；场景 = 典型场景 + 开放扩展，"包括但不限于"（D-117 / D-118）；
2. 验收围绕 Project（用户可见主对象），不引入 Mission；
3. P0-P6 主干必须完备、健全、可运行、可追溯；
4. 没有 Evidence → 不得验收为完成；没有 Artifact → 不得验收为交付；
5. 没有 Trace/Audit → 不得验收为可信执行；没有用户 Gate → 不得验收为阶段晋级；
6. Fusion 按模型/ModelProfile/ModelStrategy 验收，不按特殊流程验收；
7. 资源验收遵守三阶优先级（自身→本地→社区）；
8. 默认少 Agent、多 Skill；
9. 主干完备不可后延清单以 `02-范围基准.md` §2.1 为权威源，本文不重复定义；
10. 非目标完整清单见 `02-范围基准.md` §10，本文不重复定义。
```

## 1. 验收分级

| 等级 | 条件 | 允许 | 不允许 |
|---|---|---|---|
| **通过** | 全部主干标准满足，无阻断性缺陷 | 体验待优化、质量待提升、增强能力未全部完成 | 主干缺失、伪完成、无Evidence/Artifact/Trace/Audit、Gate缺失、安全策略缺失 |
| **有条件通过** | 主干基本完备，P1/P2 问题已记录+可追踪+有修复计划 | 非阻断性缺陷 | 主干缺失、证据缺失、高风险安全问题、Gate缺失 |
| **不通过** | 存在以下任一 | — | P0-P6无法真实推进、主干降格为基础款/演示闭环、核心状态不可恢复、Artifact/Evidence/Trace/Audit缺失、P阶段晋级未经过用户Gate、安全策略缺失或可绕过、Fusion被实现为特殊流程或绕过Gate、在线社区资源默认执行、Mission被错误引入为产品层 |
| **待确认** | 重大范围/设计/决策不清 | — | 不得直接通过。须写明：问题/影响范围/建议方案/风险/需要谁确认 |

## 2. 定位验收

**通过**：
```text
1. 平台名称为 rebuild，版本号不污染长期产品命名；
2. 定位是软件重构与迁移平台（泛软件重构）；场景体系为「典型场景 + 开放扩展」两层且"包括但不限于"，准入以三判据把门（D-117 / D-118）；
3. 产品流程、Agent 运行时、资源调用、前端体验、API 和验收标准均围绕源码项目展开；
4. 用户可见主对象为 Project；
5. 不引入独立 Mission 产品层或 Mission 模板体系。
```

**不通过**：
```text
1. 将 rebuild 扩展为泛 AI 办公/泛项目管理/纯咨询/通用 Agent 展示平台；
2. 将 Mission 作为用户可见主对象；
3. 将历史版本术语（Phase、旧 F0-F6、旧 S0-S7）作为当前主流程。
```

---

## 3. P0-P6 阶段验收总则

每个启用 P 阶段均须验收：目标/输入/输出/Artifact/Evidence/Trace-Audit/完成条件明确 + 晋级 Gate 由用户授权 + 被裁剪阶段未伪装为 completed + 失败和返工路径明确。

---

## 4. P0 接入验收

**通过**：
```text
1. Project 来源清楚；
2. 接入来源覆盖已确认范围：本地目录、Git、ZIP、GitHub；
3. 用户目标、权限边界、初始风险和材料状态清楚；
4. 生成接入记录和初始 Evidence；
5. 不确定项明确登记；
6. 进入 P1 前有用户 Gate。
```

**不通过**：未确认来源却进入 P1、无权限判断、无接入记录、无 Evidence、直接把项目标记为已建档、Mission 当接入主对象。

---

## 5. P1 建档验收

**通过**：
```text
1. 项目结构已识别；
2. 源码、文档、配置、依赖和运行说明已形成索引或摘要；
3. Environment Profile 草案或环境声明信息清楚；
4. 项目档案可支撑 P2 评估；
5. 建档产物有 Artifact，建档依据有 Evidence；
6. 进入 P2 前有用户 Gate。
```

**不通过**：只生成空档案、未读取项目材料、未标注不确定项、模型猜测写成项目事实、无 Evidence、旧版本材料覆盖当前项目事实。

---

## 6. P2 评估验收

**通过**：
```text
1. 评估基于 P1 档案和项目证据；
2. 明确迁移风险、可行性、不确定项和阻塞项；
3. 明确是否建议进入 P3；
4. 评估结论可追溯；
5. 模型输出被标注为建议或分析，不自动成为事实；
6. Fusion 如被使用，仅作为模型选项；
7. 进入 P3 前有用户 Gate。
```

**不通过**：无项目证据的评估、只给笼统结论、风险和不确定项未登记、Fusion 被写成特殊评审流程、模型结论直接成为 accepted 事实、未经用户确认进入 P3。

---

## 7. P3 规划验收

**通过**：
```text
1. 形成迁移方案 + Stage Plan + Task Plan / Task Plan Batch + TaskGraph 或等价任务关系表达；
2. 明确风险级别、权限边界和验收方式；
3. 明确 Gate 计划和 Artifact / Evidence 传递方式；
4. 进入 P4 前有用户 Gate。
```

**不通过**：无计划直接执行、TaskGraph 缺少依赖/失败处理/Gate/证据传递、未标注风险等级、未说明验收方式、社区方案直接变执行计划、未经用户确认进入 P4。

---

## 8. P4 执行验收

**通过**：
```text
1. 执行基于已确认计划；
2. 执行动作受 Policy / Hook / Gate 约束；
3. 高风险动作、外部系统写操作、远程写操作等待用户 Gate；
4. 生成可追溯 Artifact + Trace / Audit；
5. 执行失败被明确记录；
6. 节点产物进入验收或自验证流程；
7. 进入 P5 前有用户 Gate。
```

**不通过**：未经计划直接执行、只有 UI 状态没有真实执行、执行无 Trace/Audit、高风险动作无 Gate、Case 直接变 Patch、在线社区资源默认执行、失败被伪装为完成。

---

## 9. P5 验证验收

**通过**：
```text
1. 验证动作和结果清楚；
2. 验证 Evidence 完整；
3. 失败项、风险和返工建议清楚；
4. 未验证项不得标记为通过；
5. 模型只能辅助解释和建议，不能替代真实验证；
6. 进入 P6 前有用户 Gate。
```

**不通过**：无验证动作/证据、测试失败但标记通过、预览可打开就标记验证通过、模型判断替代测试、未经用户确认进入 P6。

---

## 10. P6 交付验收

**通过**：
```text
1. 交付包完整 + 交付说明清楚 + Evidence 包完整；
2. Artifact、Trace、Audit 可追溯；
3. 风险与遗留项清楚 + 后续建议清楚；
4. 用户完成 P6 Gate。
```

**不通过**：无交付包/Evidence/验证结论/风险和遗留项、未经用户确认交付、把 P6 完成解释为所有增强能力全部完成。

---

## 11. Project 与工作区验收

**通过**：
```text
1. Project 是用户可见主对象，有名称/来源/状态/当前 P 阶段；
2. Project 绑定独立 Project Workspace（按 project_id 隔离）；
3. 支持代码视图 + 材料视图，支持 Artifact/Evidence/Trace/Audit 查看；
4. 退出 UI ≠ 停止任务；
5. 状态恢复来自 DB+LangGraph checkpoint+workspace文件+trace/audit+event log（非容器/终端/前端UI）；
6. Project 不依赖 Mission 产品层。
```

**不通过**：必须先创建 Mission 才能推进、Project 与 Mission 职责混淆、多项目产物混放、状态只存前端、重启丢失。

---

## 12. Agent / Skill 验收

**通过**：
```text
1. 默认同一 Agent + 不同 Skill + 不同上下文 + 不同工具权限；
2. Agent 切换符合已确认条件（干净上下文/更换模型/权限边界/责任边界/并行隔离/专家/独立验收）；
3. 不为 P0-P6 每个阶段新增固定 Agent，不为计划/编排/执行/评审过度拆分；
4. P 系列 Skill 与 R 系列 Skill 隔离，P 系列属平台运行期资源。
```

**不通过**：大量固定 Agent 成产品主心智、每阶段一个 Agent、Skill 与 Agent 职责混乱、建设期 Skill 被用于用户项目运行、社区 Skill 默认执行。

---

## 13. 模型、Fusion 与 ModelGateway 验收

**通过**：
```text
1. 模型调用通过 ModelGateway 或确认适配层组织；
2. 模型选择不绑定 P 阶段，支持优先级：用户临时指定→Task/Node override→Agent默认→Project默认→System默认；
3. Fusion 被视为模型/ModelProfile/ModelStrategy，与其他模型在流程上无特殊差别；
4. Fusion 不形成特殊流程/阶段/Agent/评审引擎，不绕过 Policy/Gate/Audit；
5. Fusion 输出不自动等于授权或验收通过；
6. 密钥不泄露到前端、日志、Trace、截图、提交或交接材料。
```

**不通过**：出现"进入 Fusion 流程"/"Fusion 阶段"/"Fusion Agent 默认必经"、Fusion 自动批准高风险动作或自动通过验收。

---

## 14. 资源调用验收

**通过**：
```text
1. 资源使用遵守三阶优先级：自身→rebuild本地→在线社区；
2. Case 可检索/可引用/可比较，不具备执行权，不自动转成脚本/Tool/Executable Skill/Patch；
3. 社区资源默认只读参考，执行前经安全/许可/权限/审核流程，必要时用户 Gate；
4. 资源调用记录来源、风险、权限和 Trace。
```

**不通过**：默认优先社区资源、跳过自身/本地资源、社区资源默认执行、Case 自动变 Tool/Patch、社区资源成权威事实源。

---

## 15. 安全与 Gate 验收

**通过**：
```text
1. 每个启用 P 阶段晋级 → 用户授权；
2. 高风险动作/外部系统写操作/远程写操作/低置信度或冲突结论 → 用户 Gate；
3. Gate 状态可恢复 + 进入 Trace/Audit；
4. Policy 优先级高于 Agent 判断；Security/Authorization Agent 不能批准 Policy 禁止的动作；
5. 命令/Tool/MCP/写盘/Git 操作先映射到风险级别；L5 全部强制用户 Gate；
6. 密钥不泄露（报告/日志/前端/Trace/截图/提交/交接材料均不得含明文密钥）。
```

**不通过**：P 阶段自动晋级、Agent 自我批准、Auto Mode 绕过阶段 Gate、Fusion 输出替代用户 Gate、历史偏好替代用户 Gate、Policy 被 Agent 覆盖、密钥泄露。

---

## 16. Artifact / Evidence / Trace / Audit 验收

**通过**：
```text
1. 关键产出有 Artifact（类型/来源/阶段关联清楚）；
2. 关键结论/验收结论/交付结论有 Evidence（可追溯来源）；
3. 执行动作有 Trace，高风险动作和 Gate 决策有 Audit；
4. 资源调用有来源/风险/权限/Trace，模型调用可追踪；
5. 失败/重试/跳过/回滚均有记录。
```

没有 Evidence 只能标记为：**推断/建议/待验证/待补充证据/不通过**。

---

## 17. 前端体验验收

**通过**：
```text
1. 用户可见 Project + 当前 P 阶段 + 当前任务/后台任务状态；
2. 独立全屏 Project Workspace（从项目/概览进入，可返回平台）；
3. Agent 对话 Tab 常驻；阶段页/文件/Artifact 按类型单例；
4. 终端/输出/问题/任务进度在底部 Dock；Evidence/Trace/Audit 在右侧检视；
5. 文件面板支持代码视图（源码/Patch）和材料视图（文档/交接/产物/证据/参考资料）；
6. 未接入真实服务的能力显式标记（不伪装为完成）。
```

**不通过**：逐像素复制旧前端、旧 Phase/F/S 阶段污染体验、mock 伪装真实完成、无 Evidence 显示已验收、退出 UI 默认停止任务。

---

## 18. 增强能力验收边界

P6 完成仅代表 P0-P6 主干可交付。主干不可后延项以 `02-范围基准.md` §2.1 为准。增强能力（Fusion 深化/远程资源/社区/文档功能）按 R13-R16 后续建设，不得提前变成 P0-P6 必须完成条件。

```text
1. 验收分级清晰（4 级），每级允许/不允许边界明确；

3. 每维度有"通过标准"和"不通过情形"；
4. P0-P6 逐阶段独立成节（§4-§10），可直接用于分阶段验收；
5. Fusion=模型选项、资源三阶优先级、少Agent多Skill——验收标准与决策记录一致；
6. 主干完备和非目标引用 02-范围基准（非复述）；
7. Mission 不作为验收对象；
8. 文档归入 08-测试与验收/（D-071）。
```
