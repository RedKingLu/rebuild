## 1. 验收目标

集成能力验收的目标是确认：

```text
1. 源码可真实接入；
2. Workspace 可真实隔离和持久化；
3. Git / GitHub 可真实同步和受控写入；
4. 外部执行器可受控注册、绑定和调用；
5. Environment Profile 可声明并探测；
6. Execution Session 可创建、执行、恢复和关闭；
7. 命令、构建、测试、运行可形成可追溯输出；
8. Policy / Gate / Audit / Trace 可真实生效；
9. 敏感信息不会泄露；
10. 前端能正确展示真实状态、风险和证据身份；
11. 失败、阻塞和未连接状态可见；
12. 所有结论可追溯到 Evidence / Trace / Audit。
```

## 3. 验收状态定义

```text
pass：验收通过，有证据、有 Trace，必要时有 Audit；
partial：部分通过，存在明确缺口和补救计划；
fail：验收失败，不能作为完成能力；
blocked：被 Policy、Gate、环境、凭据或依赖阻塞；
not_tested：未测试，不得推断为通过；
not_connected：未接真实服务或真实资源；
mock_only：仅 mock，不得标记真实能力；
needs_user_decision：需要用户裁决，不得后延为默认通过。
```

规则：

```text
1. not_tested 不得写成 pass；
2. mock_only 不得写成 pass；
3. not_connected 不得写成 pass；
4. partial 不得写成 pass；
5. blocked 必须说明阻塞原因；
6. needs_user_decision 必须停下来确认。
```

