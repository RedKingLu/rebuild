## 1. 端到端验收目标

端到端验收目标是确认 rebuild 从项目接入到交付的基础主链路在真实能力约束下可用、可追溯、可验证、可审计、可恢复、可安全交付。

端到端验收必须覆盖：

```text
Project 创建；
P0 接入；
P1 建档；
P2 评估；
P3 规划；
P4 执行；
P5 验证；
P6 交付；
Gate；
Artifact；
Evidence（详见 02-术语表 第九部分）；
Trace；
Audit；
Workspace；
API；
SSE；
状态恢复；
安全脱敏；
前端体验；
模型与资源能力；
发布冻结。
```

端到端验收不是"演示路径走完"，而是检查真实链路中的每一个完成判断是否有事实源、证据、过程和审计支撑。

---

## 2. 发布冻结目标

发布冻结目标是确认当前版本达到可冻结基线，可作为后续增量演进和回退参考。

发布冻结必须确认：

```text
1. 必要 R 阶段产物齐备；
2. P0-P6 基础主链路可交付；
3. P5 验证证据齐备；
4. P6 交付材料齐备；
5. Gate / Evidence / Trace / Audit 链路完整；
6. 安全与脱敏通过；
7. mock / not_connected / static_demo 已替换或显式保留；
8. P0 阻断缺陷清零；
9. P1 关键缺陷清零或有用户裁决；
10. 文档与实现状态一致；
11. 用户与 Copilot 完成最终审核。
```

发布冻结不是增强能力全部完成。若 R13-R16 增强能力尚未合入或被显式裁剪，应在冻结报告中列明状态和范围。

## 4. 端到端基础主链路场景

### 4.1 场景目标

验证单个用户 Project 从接入到交付的基础主链路。

### 4.2 场景步骤

```text
1. 创建 Project；
2. 选择接入方式并进入 P0；
3. 完成源码接入和 Workspace 初始化；
4. 进入 P1 建档；
5. 进入 P2 评估；
6. 进入 P3 规划；
7. 进入 P4 执行；
8. 进入 P5 验证；
9. 进入 P6 交付；
10. 汇总 Evidence / Trace / Audit；
11. 生成验收报告；
12. 用户确认交付或要求返工。
```

### 4.3 通过条件

```text
1. 每个启用 P 阶段均有后端状态；
2. 每个启用 P 阶段晋级均有用户 Gate；
3. 必要 Artifact 齐备；
4. 必要 Evidence 齐备；
5. 关键动作 Trace 齐备；
6. 高风险动作 Audit 齐备；
7. P5 验证证据齐备（详见 04-构建-运行-测试-回归验证规范）；
8. P6 交付材料齐备；
9. 前端未误导用户；
10. 全链路无密钥泄露。
```

### 4.4 阻断红线

```text
阶段无 Gate 却晋级；
Evidence 缺失却 completed；
Trace 缺失却 trusted result；
Audit 缺失却高风险完成；
P5 无验证证据；
P6 无交付证据；
mock 被写成真实；
密钥泄露。
```

## 5. P0-P6 逐阶段端到端场景

### 5.1 P0 接入场景

```text
输入：本地目录 / Git / ZIP / GitHub 中任一接入方式；
验证：Project 创建、Workspace 初始化、源码接入、凭据脱敏、接入 Trace；
通过：接入结果明确、Evidence 存在、P0 Gate 用户授权；
失败：接入失败不得显示 P0 completed。
```

### 5.2 P1 建档场景

```text
输入：P0 接入后的项目；
验证：项目档案、材料身份、初始 Artifact / Evidence candidate；
通过：材料身份清晰、建档 Trace 存在、P1 Gate 用户授权；
失败：Artifact 不得自动成为 Evidence。
```

### 5.3 P2 评估场景

```text
输入：P1 建档事实；
验证：迁移范围、依赖风险、改造点、不确定项、风险分级（详见 02-术语表 第七部分）；
通过：评估结论有来源、风险可见、P2 Gate 用户授权；
失败：模型输出不得直接作为最终评估事实。
```

### 5.4 P3 规划场景

```text
输入：P2 评估结论；
验证：Stage Plan、Task Plan、TaskGraph、Gate 策略、Evidence 计划；
通过：计划范围、风险、权限、验收方式清晰，P3 Gate 用户授权；
失败：计划审核不得替代阶段晋级 Gate。
```

### 5.5 P4 执行场景

```text
输入：P3 已批准计划；
验证：命令、Tool、MCP、Git、写盘、Patch 真实执行链路；
通过：关键动作 Trace，高风险动作 Gate / Audit，P4 Gate 用户授权；
失败：Patch applied 不得显示为验证通过。
```

### 5.6 P5 验证场景

```text
输入：P4 执行产物；
验证：构建、运行、测试、回归、关键行为等价或差异登记（详见 04-构建-运行-测试-回归验证规范）；
通过：验证 Evidence 齐备，Evidence Gap 关闭或审计接受，P5 Gate 用户授权；
失败：代码就绪或看起来完成不得作为 P5 通过。
```

### 5.7 P6 交付场景

```text
输入：P5 验证结论；
验证：交付包、交付报告、Evidence / Trace / Audit 汇总、风险和差异登记；
通过：交付材料齐备且脱敏，用户交付 Gate 完成；
失败：P6 完成不得暗示增强能力全部完成。
```
