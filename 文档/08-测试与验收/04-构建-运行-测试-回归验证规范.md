## 1. 验证目标

构建、运行、测试、回归验证的目标是回答：

```text
1. 迁移 / 重构后的项目能否构建；
2. 项目能否启动或运行到目标状态；
3. 原有测试是否保留并可执行；
4. 新增或生成测试是否覆盖关键风险；
5. 迁移前后关键行为是否等价；
6. 不等价或无法验证的差异是否显式登记；
7. 验证证据是否足以支撑 P5 通过；
8. 验证过程是否可 Trace；
9. 风险接受是否有 Gate / Audit；
10. 验证输出是否安全脱敏。
```

验证不是为了生成漂亮报告，而是为了建立"迁移后正确性如何被证明"的可信链路。

## 2. 验证对象

验证对象包括：

```text
源码项目；
迁移后的代码；
Patch applied 结果；
依赖与构建配置；
运行环境声明；
Execution Session；
测试套件；
生成测试；
回归基线；
关键业务行为；
交付包候选；
验证报告。
```

每个验证对象都应明确：对象来源、对象版本、所属 Project / Run / Stage、验证方法、验证证据、验证状态、失败处理、是否脱敏。

---

## 3. 验证证据槽位

P5 至少应具备以下验证证据槽位（与 `02-迁移正确性与验证策略.md` §3 对齐）：

```text
build_evidence：构建可成功；
runtime_evidence：运行 / 启动可达；
test_evidence：测试保留、生成和执行；
regression_evidence：回归基线对比；
behavior_evidence：关键行为等价或差异显式登记；
security_redaction_evidence：验证输出脱敏；
verification_trace：验证过程 Trace；
verification_audit：风险接受或高风险动作 Audit。
```

规则：

```text
1. 槽位为空不得显示为通过；
2. 槽位可标记 not_applicable，但必须说明理由；
3. 槽位 evidence_candidate 不等于 validated；
4. 槽位 validation_failed 必须阻塞或返工；
5. 槽位缺失必须形成 Evidence Gap；
6. 接受 Evidence Gap 风险必须 Gate / Audit。
```


## 5. 构建验证规范

### 5.1 验证目标

构建验证用于确认迁移 / 重构后的项目在声明环境下能够完成构建或明确失败原因。

构建成功不等于运行成功，也不等于业务行为正确。

### 5.2 前置条件

```text
源码和变更文件可查询；
构建命令或构建策略明确；
依赖安装策略明确；
Environment Profile 可用或缺口明确；
Execution Session 可用；
命令授权和脱敏策略可用。
```

### 5.3 Evidence 要求

```text
构建命令摘要；
构建环境摘要；
依赖解析结果；
构建开始和结束时间；
构建结果；
构建日志 output_ref；
失败错误摘要；
脱敏状态；
trace_ref。
```

### 5.4 通过条件

```text
1. 构建命令真实执行；
2. 构建结果来自后端执行事实源；
3. 构建日志已脱敏；
4. 构建过程可 Trace；
5. 构建成功 Evidence validated；
6. 构建失败时有错误摘要和返工建议。
```

### 5.5 阻断红线

```text
未执行构建却显示构建通过；
仅模型判断可构建即显示通过；
构建日志泄露密钥；
构建失败但 P5 显示 completed；
构建无 Trace；
构建 evidence_candidate 显示为 validated。
```

## 6. 运行 / 启动验证规范

### 6.1 验证目标

运行 / 启动验证用于确认迁移 / 重构后的项目能够在声明环境下启动、运行到目标状态或明确失败原因。

运行 / 启动可达不等于关键业务行为正确。

### 6.2 前置条件

```text
构建状态明确；
运行命令或启动策略明确；
端口、进程、服务或健康检查目标明确；
Environment Profile 可用；
Runtime State 可观测；
停止 / 清理策略明确。
```

### 6.3 Evidence 要求

```text
启动命令摘要；
运行环境摘要；
服务状态；
健康检查结果；
端口 / 进程摘要；
运行日志 output_ref；
错误摘要；
停止 / 清理记录；
trace_ref；
redaction_status。
```

### 6.4 通过条件

```text
1. 运行 / 启动真实执行；
2. 健康检查或可达性目标明确；
3. 运行状态来自后端事实源；
4. 日志已脱敏；
5. 运行过程可 Trace；
6. 启动失败时有明确错误和返工建议。
```

### 6.5 阻断红线

```text
服务未启动却显示运行成功；
容器存在被当作服务可用；
终端窗口存在被当作运行成功；
启动日志泄露密钥；
运行无 Trace；
启动成功被当作业务正确。
```

## 7. 测试验证规范

### 7.1 验证目标

测试验证用于确认原有测试被保留、必要测试可执行、新增或生成测试覆盖关键迁移风险。

测试命令成功不等于全部业务正确，但可以作为验证证据之一。

### 7.2 测试类型

R1 建议测试类型：

```text
existing_tests：原有测试；
generated_tests：生成测试；
smoke_tests：冒烟测试；
integration_tests：集成测试；
regression_tests：回归测试；
manual_verification：人工验证记录；
static_checks：静态检查；
contract_tests：API / 契约测试。
```

### 7.3 Evidence 要求

```text
测试类型；
测试命令摘要；
测试范围；
测试用例数量摘要；
测试执行结果；
失败用例摘要；
跳过用例摘要；
覆盖关键风险说明；
测试日志 output_ref；
trace_ref；
redaction_status。
```

### 7.4 通过条件

```text
1. 测试真实执行或 not_applicable 理由明确；
2. 原有测试保留状态明确；
3. 新增 / 生成测试来源明确；
4. 失败用例不被隐藏；
5. 跳过用例不被显示为通过；
6. 测试输出已脱敏；
7. 测试证据 validated。
```

### 7.5 阻断红线

```text
未执行测试却显示测试通过；
测试失败被隐藏；
跳过测试被计为通过；
模型生成测试未执行即作为通过证据；
测试日志泄露密钥；
测试无 Trace；
测试 Evidence Gap 被隐藏。
```

## 8. 回归验证规范

### 8.1 验证目标

回归验证用于对比迁移前后关键行为、接口、输出或用户路径，识别等价、差异和不可验证项。

回归验证是 P5 正确性证明的重要组成部分。

### 8.2 回归基线

回归基线可包括：

```text
迁移前测试结果；
迁移前 API 响应；
迁移前页面行为；
迁移前关键输出；
历史运行记录；
用户确认的业务样例；
手工记录的关键行为。
```

规则：

```text
1. 回归基线来源必须明确；
2. 历史版本材料只读参考，不自动成为当前事实；
3. 回归基线不足必须形成 Evidence Gap；
4. 无基线不得显示等价；
5. 基线含敏感信息必须脱敏；
6. 基线不可用时必须说明理由。
```

### 8.3 Evidence 要求

```text
baseline_ref；
current_result_ref；
comparison_method；
comparison_result；
equivalent_items；
different_items；
unknown_items；
accepted_differences；
trace_ref；
audit_ref；
redaction_status。
```

### 8.4 通过条件

```text
1. 回归基线可追溯；
2. 当前结果可追溯；
3. 对比方法明确；
4. 等价项和差异项显式登记；
5. 未知项不被隐藏；
6. 接受差异必须 Gate / Audit；
7. 回归证据 validated 或风险已审计接受。
```

### 8.5 阻断红线

```text
未对比却显示等价；
无基线却显示回归通过；
差异被隐藏；
未知项被显示为通过；
接受差异无 Audit；
回归日志泄露密钥；
回归无 Trace。
```

## 9. 关键行为等价与差异登记

关键行为包括：

```text
核心 API 行为；
关键页面流程；
关键业务输入输出；
权限与认证行为；
数据读写行为；
错误处理行为；
兼容性行为；
用户确认的关键场景。
```

差异登记字段建议（R1 建议契约，R4/R12 校准）：

```text
difference_id；
behavior_ref；
baseline_ref；
current_result_ref；
difference_type；
severity；
impact；
accepted；
acceptance_reason；
gate_ref；
audit_ref；
trace_ref；
next_actions。
```

规则：

```text
1. 关键行为未覆盖必须形成 Evidence Gap；
2. 差异不得隐藏；
3. 接受差异必须有用户或授权 Gate；
4. 接受差异必须写 Audit；
5. 高影响差异不得默认接受；
6. 差异登记不得包含密钥。
```

## 10. 验证失败处理

验证失败类型：

```text
build_failed；
runtime_failed；
test_failed；
regression_failed；
evidence_missing；
trace_missing；
audit_missing；
redaction_failed；
environment_missing；
dependency_missing；
unknown_failure。
```

处理规则：

```text
1. 失败必须有 error_ref；
2. 失败必须有 trace_ref 或 trace_missing 状态；
3. 失败不得显示为 completed；
4. 失败应生成返工建议或 needs_more_info；
5. 失败可触发 rework_gate；
6. 密钥泄露类失败必须阻断并脱敏处理；
7. unknown_failure 不得默认通过。
```

## 11. Evidence / Trace / Audit 要求

### 11.1 Evidence

```text
构建、运行、测试、回归和行为验证均应有 Evidence；
Evidence 必须关联验证目标；
Evidence 状态必须明确（详见 02-术语表 第九部分）；
Evidence candidate 不得显示为 validated；
Evidence Gap 必须可见。
```

### 11.2 Trace

```text
验证动作必须可 Trace；
Trace 不等于 Evidence；
Trace 不证明结果正确；
Trace 缺失必须可见；
Trace 不得包含密钥。
```

### 11.3 Audit

```text
接受风险必须 Audit；
接受差异必须 Audit；
高风险验证动作必须 Audit；
Audit 不等于授权本身；
Audit 不等于 Evidence；
Audit 不得包含密钥。
```

## 12. Gate 策略

验证相关 Gate 类型建议：

```text
verification_start_gate；
verification_rework_gate；
evidence_gap_gate；
difference_acceptance_gate；
regression_gap_gate；
P5_to_P6_stage_promotion_gate。
```

规则：

```text
1. P5 晋级 P6 必须用户 Gate（D-025）；
2. Evidence Gap 接受必须 Gate / Audit；
3. 差异接受必须 Gate / Audit；
4. 高风险验证动作必须 Gate；
5. Policy blocked 不得批准继续；
6. Gate 未决策不得显示验证通过。
```

## 13. 安全与脱敏要求

验证过程不得泄露敏感信息。

检查项：

```text
构建日志脱敏；
运行日志脱敏；
测试日志脱敏；
回归基线脱敏；
错误响应脱敏；
Trace 脱敏；
Audit 脱敏；
验证报告脱敏；
截图 / 导出脱敏；
模型上下文脱敏。
```

规则：

```text
1. 发现 Secret 必须 redaction_required；
2. redaction_failed 不得展示原文；
3. 测试日志不得包含 Key / Token / Secret / Password；
4. 验证报告不得包含密钥；
5. 导出前必须脱敏检查；
6. 密钥泄露为阻断级缺陷（P0，详见 00-测试与验收总览 §15）。
```

```text
6. 隐藏差异；

```
