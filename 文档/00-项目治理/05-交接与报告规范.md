## 0. 本文目标

本文用于统一以下问题：

```text
1. 什么是交接材料；
2. 什么是报告；
3. 交接材料、报告、项目文档、产物、证据、运行记录之间如何区分；
4. 当前任务材料应写入哪里；
5. 已完成材料如何归档；
6. 总报告、总表、待确认项、变更日志如何维护；
7. 交接提示词必须包含哪些内容；
8. 独立审核与验收报告必须如何写；
9. 如何避免报告泛滥、双事实源和"完成但无证据"；
10. 如何让新 Agent 在上下文清零后仍能独立接手任务。
```

本文的核心原则是：

```text
交接材料必须自包含；
报告必须可追溯；
总报告优先于零散报告；
状态总表用于快速追踪；
证据引用必须明确；
交接材料不自动成为项目文档；
产物不自动成为事实源；
待确认项不得后延；
验收必须有证据；
新 Agent 不能依赖旧窗口记忆。
```

> **口径说明**：`05-Agent工作准则.md` 已取消，内容合并至 `AGENTS.md`。R1 阶段的 `R1-文档正式化总报告.md`/`R1-文档正式化总表.md`、R2 阶段的 `R2-文档审核总报告.md`/`R2-变更日志.md` 即为本文规范的实例（均已归档至 `交接/已完成/R1/`、`交接/已完成/R2/`）。**关于 `平台资源/`**：D-008-REV1 曾规划该根目录，**实际从未创建**；实际统一根为 `source/`（**D-103**）。§1.7 的路径为历史叙事，口径以 D-103 为准。

## 1. 材料身份边界

rebuild 当前版本中，必须区分以下材料身份。

### 1.1 项目文档

项目文档是长期事实源或正式候选事实源。

存放位置：

```text
/home/king/rebuild/文档/
```

典型示例：

```text
00-项目总览.md
01-决策记录.md
02-术语表.md
03-版本与目录策略.md
04-变更控制规范.md
05-交接与报告规范.md
```

> 注：`05-Agent工作准则.md` 已于 2026-06-23 取消独立维护，内容合并至根目录 `AGENTS.md`。

项目文档状态可以是：

```text
draft
待审核
accepted
superseded
rework
blocked
```

### 1.2 交接材料

交接材料用于协作、上下文传递、任务承接和阶段切换。

存放位置：

```text
/home/king/rebuild/交接/
```

交接材料不自动成为项目文档。

### 1.3 报告

报告用于记录执行结果、评审结果、验收结果、调研结果、差距结果、返工结果等。

报告可以作为交接材料、产物或证据的一部分，但不自动成为项目文档。

### 1.4 产物

产物是 Agent、Copilot、脚本或流程生成的 Artifact。

存放位置：`/home/king/rebuild/产物/`；草稿存放：`/home/king/rebuild/产物/草稿/`。

### 1.5 证据

证据用于支撑判断、评估、验收和决策。存放位置：`/home/king/rebuild/证据/`。

### 1.5.1 进度追踪材料（R5-1 起）

`证据/进度追踪/` 是进度追踪与防最小化施工辅助体系。定位为治理辅助材料——不替代正式事实源，但每个 R 阶段方案、施工、验收、收口时必须检查并更新。

详述源：`证据/进度追踪/README.md`；强制要求：AGENTS.md §12。

### 1.6 运行记录

运行记录包括：Run、Trace、Audit、Event log、Execution Session log、命令执行记录、模型调用记录。运行记录不得混入正式文档正文。

### 1.7 平台资源

平台运行期资源素材的**实际统一根 = `/home/king/rebuild/source/`**（**D-103**，2026-07-03 accepted）。磁盘实测（2026-09-16）含 `source/skills/`（`p0`~`p6` / `common` / `scenarios`）与 `source/resources/`；Agent / Tool / MCP / Case / Knowledge 的登记以 Registry（数据库）为准，不必在文件系统各占一级目录。

> **历史叙事更正**：D-008-REV1 曾规划根目录 `平台资源/`（含 agents/、skills/P系列/、tools/、mcp/、cases/、knowledge/、policies/、templates/、registry/），**该目录实际从未创建**，已被 D-103 取代。R 系列建设 Skill 仍在 `skills/R-建设执行/`，**不得进入 `source/`**（建设期↔运行期隔离，D-008-REV1 的隔离原则仍有效）。

平台资源不等于项目文档。其规范说明写入 `文档/`，资源本身或注册索引写入 `source/` 或 Registry。

> 关联决策：D-008-REV1（R/P 隔离原则）、**D-103（实际存放根，路径口径以本条为准）**

## 2. 交接目录策略

建议目录结构（标注实际状态）：

```text
交接/
├── 当前/        [实际] 当前任务材料
├── 已完成/      [实际] 已完成轮次归档
├── 待确认/      [规划] 跨轮次待确认项
└── 模板/        [规划] 模板文件
```

### 2.1 `交接/当前/`

可存放：当前任务提示词、当前阶段总报告、当前阶段总表、当前变更日志、当前待确认项、当前验收记录、当前返工说明。

### 2.3 待确认项的存放（原「交接/待确认/」建议已不采用）

**该目录实际从未创建。** 待确认项的**权威登记位置 = `证据/进度追踪/03-待确认项.md`**（AGENTS §13.1 强制更新项之一）；单轮次的待确认项同时写入该轮交接/报告材料的「待确认项」章节。（2026-09-16 R23 按磁盘与 AGENTS §13 校正）

### 2.4 模板的存放（原「交接/模板/」建议已不采用）

## 3. 交接材料通用要求

交接材料必须自包含。

### 3.1 必备内容

任何交接材料都必须包含：

```text
项目背景 / 当前阶段 / 当前裁决 / 事实源路径 / 任务目标 / 执行边界
输入资料 / 输出要求 / 禁止事项 / 验收标准 / 待确认项 / 下一步建议
```

### 3.2 自包含要求

交接材料必须让新 Agent 在没有旧窗口上下文的情况下独立执行。

必须避免：

```text
如前所述 / 按上次说的 / 继续之前那个 / 你知道的那个目录 / 沿用之前结论 / 看聊天记录
```

### 3.3 密钥与敏感信息要求

禁止在交接材料中写入：Key、Token、Secret、Password、.env 明文、API Key 明文、认证凭据。

## 4. 报告类型

### 4.1 执行报告

记录任务执行过程与结果。适用于：文档正式化、目录整理、代码施工、前端/后端实现、API 契约编写、资源登记。

### 4.2 调研报告

记录资料摸排、旧版本参考、外部资料对照、能力差距分析。

### 4.3 评审报告

记录 Agent 或独立审核方对方案、文档、实现、风险的评审。

### 4.4 验收报告

记录某阶段或某任务是否满足验收标准。结论必须区分：**通过 / 有条件通过 / 不通过 / 待补充证据**。

验收报告必须明确：

```text
验收方是否独立；
验收是否基于实证；
哪些项目未验证；
哪些结论只是代码就绪；
哪些结论可标记为 accepted。
```

### 4.5 返工报告

记录返工范围、返工原因、返工项、完成情况、复验结果。

### 4.6 变更日志

记录变更申请、变更状态、影响范围、批准情况和验收结果。C2 及以上变更必须进入变更日志。

### 4.7 待确认项报告

集中记录需要用户裁决的问题。

## 5. 总报告优先规则

### 5.1 原则

默认优先维护阶段或任务总报告，不为每个小文档、小任务生成零散独立报告。

### 5.2 当前 R1 规则

R1 文档正式化统一使用：

```text
/home/king/rebuild/交接/当前/R1-文档正式化总报告.md
/home/king/rebuild/交接/当前/R1-文档正式化总表.md
```

每处理一份文档，只在总报告中追加章节，并更新总表。

### 5.3 后续阶段命名建议

```text
R2-文档审核总报告.md / R2-文档审核总表.md
R3-前端主干施工总报告.md / R3-前端主干施工总表.md
R4-API契约落地总报告.md / R4-API契约落地总表.md
```

### 5.4 何时可以单独成报告

以下情况可以单独成报告（但仍应在阶段总报告中登记索引）：

```text
独立验收报告 / 重大变更申请 / 重大风险评审 / 阶段完成包
旧版本全量摸排报告 / 专项调研报告 / 发布冻结报告
```

## 6. 总表规则

总表用于快速追踪状态，不替代总报告。

### 6.1 总表字段

```text
编号 / 对象路径 / 对象类型 / 输入路径 / 是否应具备 / 处理状态
当前版本 / 最后处理时间 / 主要风险 / 待确认项 / 输出路径 / 总报告对应章节 / 审核状态
```

### 6.2 处理状态枚举

```text
未开始 / 评估中 / 待确认 / 已生成待审核 / 已审核通过 / 需返工 / 取消 / 已合并 / 已归档 / 阻塞
```

### 6.3 总表更新要求

每完成一项处理，必须同步更新总表。禁止只写报告不更新总表。

## 12. 证据引用规范

报告中涉及判断、验收、结论时，必须引用证据。

### 12.1 证据记录字段

```text
证据编号 / evidence_id / 来源路径 / 来源类型 / 读取时间 / 摘要 / 关联任务 / 关联结论
```

### 12.2 证据不足时的写法

如果证据不足，必须写：**"证据不足，当前只能作为推断或建议，不能标记为事实或验收通过。"**

禁止写：应该没问题 / 看起来完成 / 先按通过处理 / 后面再补证据。

```text
7. 验收报告是否需要与前端/API 状态枚举对齐；
8. 归档目录命名是否采用日期、轮次还是任务名；
9. 是否需要脚本辅助生成总表索引；
10. 是否需要文档功能阶段将这些规范产品化。
```

---

## 18. 禁止事项

禁止：

```text
1. 交接材料不自包含；
2. 让新 Agent 依赖旧窗口记忆；
3. 只写零散报告，不维护总报告和总表；
4. 为每个小文档、小任务生成大量独立报告导致报告泛滥；
5. 把交接材料自动晋升为项目文档；
6. 把产物自动晋升为事实源；
7. 没有证据就写验收通过；
8. 把未验证项写成已完成；
9. 把代码就绪写成验收通过；
10. 在报告、交接材料、日志、Trace 中写入密钥；
11. 隐藏待确认项；
12. 使用"后续补齐"绕过当前必须确认的问题；
13. 未登记变更就执行 C2 及以上变更；
14. 删除或移动交接材料但不留归档索引；
15. 产生多个同类事实源。
```

## 19. 本文验收标准

本文达到 R1 基本可用标准，当且仅当：

```text

6. 明确总表字段和 10 种处理状态；

8. 提供执行报告模板；
9. 提供验收报告模板；

12. 明确证据引用规范；
13. 明确阶段完成包规范；
14. 明确归档规范；
15. 明确文件命名规范；
16. 明确禁止事项（15 条）；
17. 明确待确认项（4 项）和待 R2 校准项（10 项）；
```
