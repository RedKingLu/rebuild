## 3. 阶段通用规则

每个 R 阶段必须具备：

```text
阶段目标 / 输入材料 / 允许事项 / 禁止事项 / 主要输出 / Gate / 完成条件 / 交接材料 / 验收方式 / 待确认项处理方式
```

### 3.1 阶段进入条件

进入任何 R 阶段前必须检查：上一阶段是否完成、是否经用户与 Copilot 审核通过、当前阶段输入是否齐备、是否存在未解决阻塞、是否需要变更申请、是否存在安全/密钥/权限/L5 高风险动作。

### 3.2 阶段退出条件

退出任何 R 阶段前必须输出：阶段总报告、阶段总表或状态清单、产物清单、证据清单、变更清单、待确认项清单、风险清单、下一阶段建议、**证据/进度追踪/ 追踪一致性检查结果**（检查清单见 `证据/进度追踪/06-状态口径与更新规则.md` §3；强制要求见 AGENTS.md §12）。

### 3.2.1 最小前后端联调（R5 起强制，详述源 D-074）

从 R5 起，每个含前端可见能力的 R 阶段，其**完成条件必须包含本阶段能力对应的最小真实前后端联调闭环**：至少一个页面/入口运行期真实调用本阶段后端端点并渲染结果或来源标记，验收时须有可观测证据（如 Playwright 网络捕获、后端 Trace 增量）。仅写 service/API 而无任何页面或入口实际调用，视为该阶段未达完成条件。"最小"即可、范围须在交接/验收报告显式写明、真实能力未就绪时以诚实 mock/not_connected 标记的真实请求满足闭环。完整定义、边界与红线见 `01-决策记录.md` D-074。

### 3.3 阶段 Gate

默认 Gate：用户审核、Copilot 审核、必要时独立 Agent 审核、必要时安全/变更/验收专项 Gate。未通过 Gate，不得标记为 accepted，不得进入下一阶段。
