## 0. 本文目标

本文用于解决以下问题：

```text
1. 平台名称、版本号、发布号和历史版本如何区分；
2. 当前版本目录如何组织；
3. rebuild 建设期资源与平台运行期资源如何隔离；
4. 草稿、正式文档、交接材料、产物、证据、运行记录、参考资料如何归类；
5. 历史版本如何完整归档、只读参考和受控吸收；
6. Agent 应如何读取、写入、移动和登记材料；
7. 哪些目录可以写入，哪些目录只读，哪些内容不能混放；
8. 如何避免旧版本污染当前版本事实源；
9. 如何支撑 R1 文档正式化和后续 R 阶段施工。
```

本文的核心原则是：

```text
当前版本保持干净；历史版本完整归档；建设期资源与平台运行期资源隔离；草稿不等于正式文档；产物不自动成为事实源；交接材料不污染长期文档；证据和运行记录必须可追溯；所有吸收历史材料的动作必须说明理由、适配方式和风险。
```

> **当前状态**：R0 已于 2026-06-23 完成，创建了根目录骨架（文档/ 交接/ 产物/ 证据/ 测试/ 脚本/ 配置示例/ 工作区/）；工程代码根为顶层 `backend/`、`frontend/`、`demo-projects/`（；原临时空骨架 `代码/` 已于 R2 移除，C-R2-002）。本文描述的完整目录结构中，标注 `[实际]` 的为已创建，标注 `[规划]` 的为本文提议但尚未创建。

## 1. 命名与版本规则

### 1.1 平台名称

平台名称是：

```text
rebuild
```

所有长期产品文案、项目文档、目录说明、Agent 提示词、前端用户可见描述，应使用 `rebuild` 作为平台名称。

> 关联决策：D-001

### 1.2 当前版本号

当前版本号是：

```text
V26.1.1
```

V26.1.1 是当前基线发布号，不是平台名称。

> 关联决策：D-002

### 1.3 版本号禁止写死范围

版本号不得写死到以下长期结构中：

```text
长期目录名
API path
数据库表名
包名
模块名
类名
前端路由
运行时路径
长期对象名
```

错误示例：

```text
/api/v26.1/projects
v26_1_runtime
RebuildV261Platform
rebuild_26_1_core
```

推荐示例：

```text
/api/projects
flow_runtime
workspace_service
model_gateway
execution_provider
```

### 1.4 版本号允许出现的位置

版本号可以出现在：

```text
VERSION 文件
发布说明
文档头部元数据
交接报告
阶段报告
归档索引
临时草稿文件名
发布包元数据
```

但即使允许出现，也应明确其身份是版本号，不是平台名称。

## 2. 阶段命名规则

### 2.1 P0-P6：用户项目产品流程

P0-P6 是 rebuild 面向用户项目的可裁剪产品流程：

```text
P0 接入
P1 建档
P2 评估
P3 规划
P4 执行
P5 验证
P6 交付
```

P 阶段用于用户项目，不用于描述 rebuild 当前版本自身建设。

> 关联决策：D-009

### 2.2 R0-RN：平台自身建设阶段

R0-RN 是 rebuild 当前版本自身建设阶段。

完整 R 阶段计划以以下文件为准：

```text
文档/00-项目治理/06-R阶段总计划.md        ← 📋 规划中
```

当前（2026-06-24）R0/R1/R2 已完成，R3 准备开工。详细 R 阶段列表见 `文档/00-项目治理/01-决策记录.md` D-010。

> 关联决策：D-010

### 2.3 历史阶段术语处理

以下术语不作为当前版本主流程术语：

```text
Phase 15
旧 F0-F6
旧 S0-S7
旧 RunEngine 阶段体系
旧 VNext 主流程
```

如果历史材料中出现这些术语，只能作为历史参考，并必须说明当前版本如何吸收、改写或废弃。

### 3.4 `skills/`：仅用于 R 系列建设 Skill

根目录 `skills/` 只用于 rebuild 当前版本建设过程中的 R 系列建设 Skill。

建议结构：

```text
skills/
└── R-建设执行/
    ├── rebuild-work-guidelines/
    │   ├── SKILL.md
    │   └── references/
    │       ├── templates.md
    │       └── workflows.md
    └── （其他 Skill 不再建议创建）
```

> **注**：当前磁盘已存在 `rebuild-work-guidelines/`（accepted，V26.1.1，由原 `rebuild工作准则skill.md` 重构而来）；其余 Skill 不再建议创建（用户裁决仅保留工作准则 Skill）。

根目录 `skills/` 不存放平台运行期 P 系列 Skill。

理由：

```text
1. R 系列 Skill 服务 rebuild 建设过程；
2. P 系列 Skill 服务未来平台运行时的用户项目流程；
3. 两者事实源、生命周期、权限、调用主体、验收方式不同；
4. 混放会导致平台把建设规则误当用户项目运行能力，或把平台运行能力误用于建设流程。
```

> **与 D-008 的关系**：D-008 原始裁决将 R 系列和 P 系列 Skill 均放在 `skills/` 下。2026-06-23 经用户确认，P 系列已移入 `平台资源/skills/P系列/`，D-008 已新增 D-008-REV1 修订条目。本文与修订后的 D-008 保持一致。

### 3.5 `平台资源/`：平台运行期资源目录

> **本节内容已于 2026-06-23 经用户确认，D-008 已同步修订（D-008-REV1）。**

平台运行期使用的 P 系列 Skill，以及平台运行期 Agent、Tool、MCP、Case、Knowledge、Policy、Template 等，统一放入独立目录：

```text

├── README.md
├── agents/                         — 平台运行期 Agent 定义
├── skills/                         — P 系列 Skill
│   └── P系列/
│       ├── P0-接入Skill.md
│       ├── P1-建档Skill.md
│       ├── P2-评估Skill.md
│       ├── P3-规划Skill.md

│       ├── P5-验证Skill.md
│       └── P6-交付Skill.md
├── tools/                          — Tool 定义与注册
├── mcp/                            — MCP 能力定义
├── cases/                          — 案例（只读，无执行权）
├── knowledge/                      — 知识材料
├── policies/                       — Policy/Rule/Risk Level
├── templates/                      — Stage/Task 模板（当前版本不设独立 Mission 产品层，D-070）
└── registry/                       — 资源注册索引
```

#### 3.5.1 目录职责

```text
agents/     平台运行期 Agent 定义，例如 Node Worker、Acceptance、Auto Review、Expert、Gate Agent。
skills/     平台运行期 P 系列 Skill，与用户项目 P0-P6 流程绑定。
tools/      平台运行期可调用工具定义或工具注册信息。
mcp/        MCP 能力定义、连接配置模板、调用边界说明。
cases/      可检索、可引用、不可直接执行的案例材料。
knowledge/  平台运行期知识材料。
policies/   平台运行期 Policy / Rule / Risk Level 配置或说明。
templates/  Project 引导模板、Stage Plan、Task Plan、交付模板等。
registry/   平台运行资源注册索引，记录资源身份、版本、风险、权限和审核状态。
```

#### 3.5.2 平台运行资源与代码实现的关系

`平台资源/` 是平台运行资源的设计与配置事实源。

后续如果工程实现需要，也可以在代码目录中建立运行时加载目录，例如：

```text
backend/app/runtime_resources/
backend/app/agents/
backend/app/tools/
```

但代码实现目录不能替代 `平台资源/` 的文档化事实源。

如二者存在差异，必须在 R2 或对应工程阶段进行校准并登记。

长期项目文档和设计规范目录。


### 3.7 `交接/`

任务交接、阶段报告、总报告、总表、待确认项、执行记录、下一轮提示词等协作材料目录。

交接材料不自动成为正式项目文档。

### 3.8 `产物/`

Agent、Copilot、脚本或流程生成的产物目录。

包括草稿、报告、设计、Demo、Patch、临时包等。

产物不自动成为正式文档。

### 3.9 `证据/`

调研证据、验收证据、运行证据、引用证据等目录。

证据用于支撑判断，不等于文档结论。

### 3.10 工程代码根：`backend/`、`frontend/`、`demo-projects/`

当前版本工程代码以**工程惯例**为准，根目录为顶层 `backend/`、`frontend/`、`demo-projects/`（用户裁决 ）。文档目录以可读性为准（中文 00-09），代码目录以工程惯例为准（英文顶层），两者分线、互不混用。

不得直接复制历史版本代码。

```text
backend/        — 后端代码（Python + FastAPI + LangGraph）
frontend/       — 前端代码（React + Vite + TypeScript）
demo-projects/  — 演示/样例项目
```

> 属主已归还普通用户（king）。

### 3.11 `测试/`

测试用例、验收脚本、测试数据、测试报告相关目录。

### 3.12 `脚本/`

项目辅助脚本目录。

不得存放密钥、Token、Secret、Password。

### 3.13 `配置示例/`

配置模板和脱敏示例目录。

仅允许放置示例配置，不得放置真实密钥。

### 3.14 `工作区/`

平台运行时或示例项目工作区目录。

每个用户项目应有独立 Project Workspace，按 project_id 隔离。

## 11. 草稿到正式文档的晋升规则

草稿不能直接成为正式文档。

必须经过以下流程：

```text
1. 判断该文档是否应该具备；
2. 定义该文档应具备哪些内容；
3. 检查草稿是否满足需求；
4. 给出完善计划；
5. 生成正式候选文档；
6. 正式候选文档状态为待审核；
7. 用户与 Copilot 审核通过后，方可标记为 accepted。
```


当前 R1 文档正式化总表：
