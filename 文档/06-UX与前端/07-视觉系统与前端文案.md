## 1. 视觉系统目标

视觉系统应让 rebuild 前端呈现为：**清晰、可信、工程化、风险可见、证据可追溯、状态不误导、适合单人与 Agent 协作**。

帮助用户快速判断：当前阶段/后台任务/Gate/Evidence缺口/能力真实状态/高风险动作/结果是否可追溯。不追求炫技动画，优先保证信息密度、状态准确、风险显著。

> 关联决策：D-003, D-023, D-045, D-066

---

## 2. 视觉设计原则

```text
1. 信息清晰优先于装饰
2. 以 Project/Run/Stage 为主线组织视觉层级
3. Gate/Evidence Gap/Policy Blocked 为最高优先级状态
4. 状态颜色必须配合文字，不依赖颜色单独表达
5. mock/未接真实服务必须有强标记
6. 真实能力/受限能力/只读参考/被阻断能力必须视觉区分
7. 深浅主题可支持，不牺牲状态可读性
8. 中文文案简洁、准确、不夸大能力
```

禁止：低对比度隐藏风险、绿色表达未经验证的成功、"完成"表达"已生成"/"已接入"、"智能已处理"掩盖 Gate/Evidence 缺口、营销化文案替代工程状态。

## 3. 色彩语义

| 色彩 | 用途 | 硬规则 |
|---|---|---|
| 蓝色（主色） | 主导航、主按钮、当前选中 | — |
| 绿色 | 仅用于后端确认成功/验证通过/真实可用 | mock/not_connected/Evidence candidate 不得使用 |
| 黄/橙（警告） | 可继续但需关注 | — |
| 橙/红橙（阻塞） | waiting_gate/blocked/requires_gate | 必须比普通 warning 醒目 |
| 红色（错误） | failed/rejected/policy_blocked/credential_invalid | Policy blocked 必须强阻断视觉 |
| 灰色（中性） | read_only/static_demo/not_connected/archived | — |
| 紫色/斜纹（mock） | mock 数据与体验壳（D-049） | — |

颜色必须配合文字标签和图标。

> 关联决策：D-023, D-030, D-049, D-066

## 4. 状态标签体系

17 种通用标签：`真实可用 / 可用但受限 / 已配置未验证 / 未接真实服务 / Mock数据 / 静态演示 / 只读参考 / 等待Gate / 被Policy阻断 / 证据候选 / 证据已验证 / 证据不足 / Trace缺失 / Audit缺失 / 凭据缺失 / 凭据无效 / 已脱敏 / 高风险 / 需要用户授权`

规则：标签短而明确、不含糊词（"可能可用""看起来完成"）、全站一致、支持 hover tooltip、以后端状态为准。

---

## 5-7. 字体层级 / 布局密度 / 图标

- **字体层级**：页面标题 → 区域标题 → 卡片标题 → 状态标签 → 说明文字 → 元信息（id/时间/引用）。状态标签比元信息醒目；Gate/Evidence Gap 标题比普通卡片醒目
- **布局密度**：概览页中等密度（突出 Gate/Evidence Gap/Run）；Workspace 高密度但分区明确；高风险信息周围足够空间；Gate/Evidence Gap 不得被折叠消失
- **图标**：配文字、全站一致、mock 图标不得与真实可用相同、脱敏图标不表示"安全可公开"

---

## 8. 中文文案总原则

```text
准确表达状态，不夸大能力。
区分"已创建""已接入""已生成""已验证""已交付"。
区分"候选""已提交""验证中""已验证"。
区分"未接真实服务""Mock数据""静态演示"。
区分"只读参考""可执行资源"。
避免"AI已完成全部工作"等误导表达。
风险、阻塞、需要用户决策必须直说。
```

推荐语气：清楚、克制、工程化、可执行、不营销化、不迎合、不隐瞒风险。

## 9. 禁用文案清单

禁止：`一键完成迁移 / 已自动验证全部正确 / AI已确认无风险 / 模型已授权 / 资源已验证通过 / Trace已证明结果正确 / Audit已批准 / Evidence候选已通过 / Mock可用 / 静态演示已接入 / 未接真实服务但可执行 / 跳过Gate继续 / 忽略Policy继续 / 自动修复所有问题`

替代表达：`"已生成候选产物，待验证" / "已完成接入任务，P0是否完成需以阶段状态为准" / "发现证据缺口，请补充或处理Gate" / "当前为Mock数据，尚未接入真实服务" / "该资源为只读参考，不可执行" / "该操作被Policy阻断，不能继续执行"`

## 11-22. 专项文案（精要汇总）

| 专项 | 关键文案 | 硬规则 |
|---|---|---|
| **Project 创建** | 新建项目/接入源码项目/从本地目录-Git-ZIP-GitHub创建 | 不写"项目已迁移完成""P0已自动完成" |
| **P0-P6 阶段** | P0接入~P6交付；状态：未启用/未开始/进行中/等待Gate/阻塞/需返工/失败/已完成/已跳过 | 裁剪阶段显示"未启用/不适用"非"已完成"；证据不足显示"证据不足，不能完成" |
| **Gate** | 需要用户授权/等待Gate决策/阶段晋级确认/高风险动作确认/Policy阻断；按钮：批准/拒绝/要求补充信息/要求返工 | Policy blocked 不显示"批准"；高风险批准明确风险；Gate不写成普通提示 |
| **Evidence** | 证据候选/已提交/验证中/已验证/证据不足/验证失败/验证阻塞 | candidate不写成"已验证"；Evidence Gap不得只显示为低优先级tooltip |
| **Trace/Audit** | Trace：运行链路/调用记录/状态变化/Trace缺失/可信链路不足；Audit：审计记录/Gate决策审计/高风险动作审计/Audit缺失 | Trace不写成"证据"；Audit不写成"授权"；缺失不得静默 |
| **模型资源** | 真实可用/凭据缺失/只读参考/可执行但需检查/Mock数据/静态演示/Fusion模型能力 | Case写成"只读案例"不写成Tool；调用完成不写成"证据已验证"或"任务完成" |
| **Mock 能力** | Mock数据(仅体验展示)/静态演示(未接入真实后端)/未接真实服务/真实可用/真实可用但受限 | mock不得写"可用"；static_demo不写"已接入"；not_connected不写"真实可用" |
| **错误** | 结构：发生什么→为什么阻塞→用户可做什么→request_id/trace_ref→是否需Gate→是否可重试 | 不暴露堆栈/不显示密钥/policy_blocked不建议反复重试 |
| **空状态** | "暂无Evidence，但该阶段完成前需要补充证据"/"暂无Trace记录，当前结果尚无可追溯链路" | "暂无Evidence"≠"验证通过"；空状态提供安全下一步 |
| **按钮** | 新建项目/接入源码/打开项目/进入工作区/处理Gate/查看证据缺口/批准/拒绝/刷新状态/重试/取消 | 高风险动作明确风险；禁止"跳过Gate继续" |
| **安全脱敏** | "敏感内容已脱敏"/"该文件可能包含凭据，仅显示存在状态"/"凭据已保存为引用，前端不会回显明文" | "已脱敏"≠"可公开"；redaction_required用阻断文案 |
| **无障碍** | 状态标签aria-label/颜色配合文字/按钮表达动作目的/关键状态支持键盘访问 | 不仅靠颜色表达错误；不用"点击这里"作为唯一按钮文案 |
