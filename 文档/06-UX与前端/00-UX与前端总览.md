## 1. UX 总体目标

rebuild 前端体验应服务于一个核心目标：

```text
让用户以 Project 为中心，清楚看到一个源码项目从接入、建档、评估、规划、执行、验证到交付的全过程，
并且能随时理解当前状态、阻塞原因、需要自己决策的 Gate、已有产物、证据链、运行记录和审计记录。
```

前端体验不应只是"任务看板"或"Agent 聊天窗口"，而应同时表达：

```text
1.  项目对象（Project）
2.  P0-P6 产品流程
3.  Run 后台任务
4.  Stage Plan / Task Plan / TaskGraph
5.  Workspace 文件与材料
6.  Artifact / Evidence
7.  Trace / Audit
8.  Gate / Authorization
9.  Model / Resource
10. Execution Session
```

UX 核心判断标准：

```text
用户是否能在不阅读后端日志的情况下，知道当前项目走到哪里、为什么停下、
下一步谁决策、依据是什么、风险在哪里、证据是否充分。
```

> 关联决策：D-003（产品定位，范围已由 D-117 部分覆盖）、D-117（泛软件重构 + 两层场景体系）、D-118（准入三判据）、D-009（P0-P6 产品流程）、D-045（前端目标体验继承）

## 2. 前端信息架构总览

R1 正式候选前端信息架构分为以下 11 个一级区域：

```text
1.  平台概览
2.  Project 列表
3.  Project 详情
4.  Project Workspace
5.  Run / 后台任务面板
6.  P0-P6 阶段视图
7.  Gate / Authorization 中心
8.  Artifact / Evidence / Trace / Audit 检视（AET）
9.  Model / Resource 管理
10. 集成管理（Git / 远程 / ExecutionProvider / MCP）
11. 聚合管理（Fusion / SuperModel 配置）
12. 设置与安全提示
13. 文档与帮助入口
```

信息架构原则：

```text
1.  Project 是主对象（D-070）
2.  P0-P6 是项目推进路径（D-009）
3.  Run 是一次推进过程
4.  Workspace 是项目工作场所（D-050）
5.  Gate 是用户必须关注的阻塞点（D-023~D-034）
6.  Evidence / Trace / Audit 是可信交付的依据（D-066）
7.  集成和聚合是平台关键能力，设独立导航和管理页
8.  Model / Resource 是平台能力配置
9.  R 阶段信息属于平台建设，不作为用户项目主流程展示
```

> 关联决策：D-009, D-023~D-034, D-050, D-066, D-070

## 3. 导航原则

前端导航应避免把用户带入"平台内部工程建设阶段"的心智。

### 3.1 主导航（4 组 11 项）

主导航分为 4 组（与 V26 Target Demo v1 验证的信息架构一致，D-045）：

| 分组 | 条目 | 说明 |
|---|---|---|
| 工作台 | **概览** · **项目** | 概览为默认页 |
| 能力 | **资源** · **集成** · **模型** · **聚合** | 多 tab 管理页 |
| 知识与社区 | **案例** · **知识** · **社区 ↗** · **文档 ↗** | 社区/文档跳转独立站点/新标签页 |
| 系统 | **设置** | 平台配置 |

详细页面设计规范：
- **资源**：Agent Harness（Agents / Skills / Rules / Hooks / Commands / Contexts / MCP / Tools / Knowledge / ExecutionProviders），见 `08-资源与Agent Harness.md`（待后续补充）
- **集成**：执行器接入 / 编程 Agent 接入 / 远程资源 / Git / 其他集成，见 `08-集成页设计规范.md`
- **模型**：Provider / Profile / Binding / Usage / Failover，见 `06-模型资源可视化与真实能力标记.md`
- **聚合**：Fusion / SuperModel 聚合模型配置（D-035），见 `09-聚合页设计规范.md`
- **案例**：Candidate / Approved Case/Rule/Prompt Skill 管理
- **知识**：知识库文档列表与检索
- **社区 ↗** / **文档 ↗**：独立站点新标签页跳转，不内嵌呈现

### 3.2 Project 内导航

```text
项目总览
P0-P6 阶段
Runs
工作区
产物
证据
Trace
Audit
Gate
设置
```

### 3.3 工作区内导航（独立全屏 IDE 心智，D-046）

工作区从 Project 或概览进入，隐藏主导航，采用七区布局：

```text
顶部：   项目身份、P0-P6 迷你进度、当前 Run/阶段、Active Gate、执行模式、后台任务
左侧：   活动图标条（VSCode 式切换）→ 阶段 FlowRail / 文件树 / Git / 远程 / 搜索 / Agent 命中
中部：   类型单例 Tab（D-047） + Gate 中央横幅（Active Gate 时常驻）
底部：   终端、输出、问题、任务进度（默认折叠，可拖拽调整高度）
右侧：   Evidence / Trace / Audit / Context / Resource / Model 检视（可折叠为竖条）
全局：   返回平台入口
```

> 活动图标条（Activity Bar）是工作区的第一交互入口：点击图标展开对应左侧面板，再次点击折叠。阶段图标默认展开 P0-P6 FlowRail（D-009）。
>
> Target Demo 历史参考：V26 Target Demo v1 已验证"蓝白/左导航/工作区独立IDE + 活动图标条"布局心智，当前版本吸收其信息架构与交互模式，适配 P0-P6、AGENTS.md、skills、ModelGateway 等新体系（D-045）。

### 3.4 禁止导航结构

```text
1. 不以 Mission 作为主导航（D-070）
2. 不以 R0-RN 作为用户项目导航
3. 不使用旧 Phase / 旧 F0-F6 / 旧 S0-S7 表述
4. 不把模型、资源、工具放在比 Project 更强的主线位置
5. 不把 Gate 隐藏在通知中心里
```

## 3A. 平台助手（全局浮动 AI 精灵）

平台助手是平台级内置助手，独立于 P0-P6 产品流程，也独立于 ProjectWorkspace 内的项目交互（不属于 Agent / Skill 资源体系）。它面向"使用平台本身"的答疑与引导，而非推进某个 Project。

### 3A.1 前端形态

```text
1. 全局浮动 AI 精灵图标 — 常驻平台界面一角，跨页面持续可见
2. 点击展开 / 收起对话面板，不抢占主导航与 Project 主线位置
3. 对话面板用于：使用答疑、平台使用引导
4. 对话面板内含「模型 / 服务商切换器」 — 用于连通性自测（验证某模型 / 服务商是否接入成功）
5. 模型切换器仅影响助手自身会话，不改变 Project / Run / Node 的模型绑定
```

### 3A.2 体验规则

```text
1. 平台助手是平台级助手，独立于 ProjectWorkspace 内的 Agent 对话 Tab（§11），二者不混淆
2. 连通性自测结果按「真实能力标记」呈现：连通成功 / 失败如实标记，不臆造（与 §16 一致）
3. 模型自测复用 ModelGateway（D-039），不展示、不泄露任何密钥（AGENTS.md §12）
4. [规划 / R-future] 代用户操作平台为后续规划能力，代操作须经 Policy / Gate，并纳入 Audit
5. 边界：平台助手不泛化为通用 AI 平台，不作为 Project 推进或 Agent / Skill 资源
```

> 前端只描述形态与边界，详述源为决策记录。详见 `文档/00-项目治理/01-决策记录.md` D-073。

## 9. Project Workspace 总体体验

Workspace 是 Project 的独立工作场所，应采用独立全屏 IDE 心智（D-046）。

Workspace 不是普通主导航页面常驻，而应从 Project 或概览进入，并提供返回平台入口。

### 9.1 Workspace 核心区域（七区布局）

```text
1. 活动图标条（Activity Bar）   — VSCode 式 6 项切换：阶段/文件/Git/远程/搜索/Agent
2. 左侧面板                     — 随活动图标切换内容（FlowRail/文件树/Git/远程/搜索/Agent命中）
3. 顶部项目与运行状态栏         — 项目名+P0-P6迷你进度+当前阶段+执行模式+后台任务+Gate指示
4. Gate 中央横幅                — Active Gate 时常驻中央顶部，阻断提示（D-023）
5. 中央类型单例 Tab             — Agent 常驻 + 阶段页/文件/Artifact 核心 4 类（D-047）
6. 底部 Dock                    — 终端/输出/问题/任务进度，默认折叠可拖拽
7. 右侧检视面板                 — Evidence/Trace/Audit/Context/Resource/Model，可折叠为竖条
```

### 9.2 Workspace 红线

```text
1. Workspace UI 不得成为状态源（D-053）
2. 终端不等于状态源
3. 容器状态不等于状态源
4. 文件展示不得泄露密钥
5. 前端不得把本地缓存当成项目事实
```

### 9.3 首次进入 Workspace 引导

首次进入新项目的工作区时，前端弹出引导向导（参考 V10 `ProjectInitWizard` 模式，适配 V26.1）：

```text
引导步骤（覆盖 4 项必要初始化决策）：
1. 环境选择    — 本地环境 / 远程环境
2. 提交方式    — 本地 Git / GitHub 集成
3. 模型配置    — 自动（跟随系统）/ 全局统一 / 自定义
4. 执行模式    — Auto / Plan / Manual（D-025）
摘要确认      — 展示 4 项选择 + 确认进入
```

规则：
```text
1. 引导仅在首次进入 Workspace 时显示（guide_completed 标记）
2. 源文件检测/克隆不再作为引导步骤（由 P0 接入阶段负责，D-009）
3. 用户可跳过引导（使用默认配置），后续可在项目设置中修改
4. 引导配置写入后端，不由前端本地保存（D-053）
```

> 关联决策：D-046（全屏IDE心智）、D-047（类型单例Tab）、D-050（每项目独立Workspace）、D-051（三对象模型）、D-053（状态恢复多源）

## 11. 中央类型单例 Tab

中央区域采用类型单例 Tab（D-047），核心 4 种：


```text

Diff/Patch Tab — 代码变更查看
报告预览 Tab  — 分析/验证报告查看
```

### 11.1 类型单例规则

```text

2. Agent 对话常驻，用于解释、提问、触发 Gate 对话
3. 文件编辑和预览应区分
4. Artifact / Evidence 应区分身份
5. 高风险操作不得仅通过 Tab 关闭来取消
6. 可编辑文件有未保存变更时，切换文件弹出"保存并切换 / 放弃并切换 / 取消"
```

## 14. Gate 与 Authorization 前端体验

Gate 是用户必须处理的流程阻塞点（D-023~D-034）。

### 14.1 Gate 展示应包含

```text
gate_id
gate_type
关联 Project / Run / Stage / Node

关联 Artifact / Evidence / Evidence Gap
可选决策
推荐动作
Trace / Audit 引用
```

### 14.2 Gate 展示位置

Gate 在 Workspace 中有两个展示位置：

```text
主位置：中央编辑区顶部横幅（Active Gate 时常驻）
  — 黄色/橙色横幅，展示标题+摘要+风险+确认/返回按钮
  — 阻断性质：用户决策前横幅不消失，阻塞动作不执行
  — 用户批准/拒绝后横幅消失，状态刷新
辅助位置：右侧检视 Gate 详情（历史 Gate 列表 + 当前 Gate 字段详情）
  阶段页中的 Gate 卡片（进入阶段页时可见）
```

### 14.3 Gate 体验规则

```text
1. P 阶段晋级 Gate 必须由用户授权（D-023）
2. L5 高风险动作暂定全部强制用户 Gate（D-034）
3. Policy 禁止项不得由 Agent 或前端批准
4. Gate 未决策时不得继续执行阻塞动作
5. Gate 决策必须写 Audit
6. Gate 不得只用 toast 展示（D-023）
7. Gate 横幅为阻断态：黄/橙底，位于中央编辑区顶部，不可折叠消失
```

> 关联决策：D-023~D-034（安全/Gate/Authorization 体系）

## 19. 前端状态管理原则

前端状态应分为五类：

```text
server_state  ：来自后端 API / SSE 的可刷新状态
ui_state      ：展开、收起、当前选中、Tab 状态
draft_state   ：未提交表单和编辑草稿
cache_state   ：可丢弃缓存
mock_state    ：明确标记的 mock 数据
```

### 19.1 规则

```text
1. server_state 需要能从后端重新查询
2. ui_state 不得成为业务事实
3. draft_state 不得伪装为已提交
4. cache_state 不得伪装为最新后端状态
5. mock_state 必须可识别
6. 前端不得自行推断 completed
```

> 关联决策：D-053（状态恢复多源——容器/终端/前端 UI 不得作为状态源）
