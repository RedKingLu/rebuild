## 1. 可视化目标

模型资源可视化的目标是让用户清楚理解：

```text
1.  当前 Project/Run/Node 使用了哪些模型
2.  模型服务商和 Model Profile 是否可用
3.  当前模型选择来源是什么
4.  是否使用了 Fusion 能力
5.  当前有哪些平台资源
6.  哪些资源只是只读参考
7.  哪些资源可执行但需要 Gate/Policy/Trace/Audit
8.  哪些能力还是 mock/静态演示/未接真实服务
9.  哪些能力真实可用
10. 哪些能力因凭据、权限、风险或后端未接入而不可用
```

核心体验判断标准：

```text
用户看到一个模型或资源卡片时，必须能立即判断它"是什么、能不能用、
是否真实接入、风险是什么、是否会产生 Trace/Audit、是否需要 Gate"。
```

> 关联决策：D-035, D-039, D-049, D-066

## 2. 能力标记总览

前端必须对每个模型和资源显示真实能力状态（14 种）：

```text
real_available           — 真实可用
real_limited             — 真实可用但受限
configured_not_verified  — 已配置未验证
credential_missing       — 缺少凭据
credential_invalid       — 凭据无效
not_connected            — 未接真实服务
mock                     — mock 数据（D-049）
static_demo              — 静态演示（D-049）
read_only                — 只读参考
blocked_by_policy        — 被 Policy 阻断（D-030）
waiting_gate             — 等待 Gate（D-023）
disabled                 — 已禁用
deprecated               — 已废弃
unknown                  — 状态未知，需刷新或校准
```

展示规则：

```text
1. 状态必须醒目
2. mock/static_demo/not_connected 必须显式标记（D-049）
3. read_only 不得展示执行按钮
4. credential_missing/credential_invalid 不得回显密钥
5. blocked_by_policy 不得提供"强行执行"（D-030）
6. unknown 不得显示为可用
```

> 关联决策：D-023, D-030, D-049

## 3. 模型可视化入口

模型信息可出现位置：

```text
平台模型页 / Project 设置 / Run/Node 详情
Workspace 右侧 Model 检视（03-ProjectWorkspace布局规范 §22）
Agent 对话引用区 / 模型调用 Trace / 成本/usage 摘要页
```

入口规则：

```text
1. Project 主流程不应被模型配置抢占
2. 当前 Run/Node 可显示实际选择的模型
3. 模型设置应与 Project/Agent/Task/Node 绑定层级区分
4. 模型凭据状态只显示状态和脱敏引用
5. 模型调用失败应能进入 Trace/error_ref
```

此外，平台助手（全局浮动 AI 精灵）对话面板内的"模型 / 服务商切换 + 连通性自测"是模型接入成功与否的直接体验入口，结果按"真实能力标记"呈现（连通成功 / 失败如实标记，不臆造）；自测复用 ModelGateway（D-039）且不泄露密钥，仅影响助手自身会话。详见 `文档/00-项目治理/01-决策记录.md` D-073。

## 4. Model Provider 可视化

Provider 卡片：`provider_id / provider_name / provider_type / status / credential_status / supported_capabilities / last_checked_at / trace_ref / 真实能力标记`

规则：credential_status 只展示 exists/missing/invalid/redacted；不展示 Provider Key；未做连通性测试标记 configured_not_verified；mock provider 显式标记。

## 5. Model Profile 可视化

Profile 卡片：`model_profile_id / profile_name / provider_ref / model_family / capability_tags / default_parameters摘要 / context_limit_note / usage_policy_ref / cost_policy_ref / status / 真实能力标记 / trace_ref`

规则：capability_tags 可显示 Fusion/long_context/coding/review 等；default_parameters 不含密钥；未真实调用验证的 Profile 不得显示 real_available。

## 6. 模型绑定层级可视化

模型选择优先级：`用户临时指定 → Task/Node override → Agent 默认模型 → Project 默认模型 → System 默认模型`

前端展示：当前实际模型 / 选择来源 / 覆盖层级 / fallback 状态 / 是否 override / 是否 Fusion / Trace 引用

规则：模型选择不绑定阶段（D-039）；override/fallback 必须可见；绑定变化应产生 Trace。

> 关联决策：D-039

## 7. Model Call 可视化

Call 卡片：`model_call_id / 关联 project_id/run_id/stage/node_id / selected_model_ref / provider_ref / call_purpose / model_call_status / usage_summary / output_ref / trace_ref / error_ref`

状态：queued / running / completed / failed / canceled / blocked / redacted

规则：model_call_completed ≠ 任务完成；模型输出不自动成为 Artifact/Evidence；output_ref 默认只显示引用和摘要；Trace 不含密钥。

## 8. Fusion 能力可视化

Fusion 只作为模型能力或模型策略展示（D-035）。

展示：`fusion_capability_id / 关联 model_profile_ref / capability_tags / recommended_use_cases / not_recommended_use_cases / risk_notes / status / trace_ref`

规则：Fusion 不显示为独立流程/阶段/评审引擎；Fusion 不绕过 Policy/Gate/Audit；Fusion 输出不自动等于授权或验收通过。

> 关联决策：D-035

## 9. Usage / 成本可视化

usage/成本是模型模块功能，不抢占主流程。展示：`project_id/run_id/stage/model_call_id/provider_ref/model_profile_ref/usage_summary/cost_summary/budget_policy_ref/trace_ref`

规则：token/成本预算不作为阶段 Gate 默认条件；费用数据不泄露 Provider 凭据；R1 为建议契约，R5 按真实实现校准；不因费用缺失阻塞 P0-P6 主链路。

## 10. 资源可视化入口

位置：平台资源页 / Workspace 右侧 Resource 检视 / Agent 对话引用区 / Task-Node 详情 / 资源调用前检查卡片 / 资源调用 Trace / Gate 详情 / Evidence-Artifact 来源详情

规则：资源不抢占 Project 主线；可执行资源必须展示风险和权限边界（D-034）；只读资源不得展示执行按钮；社区资源必须展示审核/许可/安全状态；资源调用可追溯 Trace。

> 关联决策：D-034

## 11. Resource Registry 可视化

资源卡片：`resource_id / resource_type / name / version / status / source_type / review_status / risk_level / permission_scope / gate_policy / trace_policy / audit_policy / capability_tags / 真实能力标记`

资源状态（10 种）：draft / under_review / approved / active / read_only / deprecated / superseded / disabled / blocked / archived

规则：active 前须审核；read_only 不得执行；disabled/blocked 不得调用；社区资源默认 read_only；状态变化可追溯 Trace/Audit。

## 12. 资源类型可视化

10 种资源类型：

```text
Skill                  — 流程/方法/能力封装
Tool                   — 可执行工具
MCP                    — 外部或本地 MCP 能力
Expert Agent           — 专家型 Agent 资源
Case                   — 经验案例，只读参考（不具备执行权）
Knowledge              — 知识材料（不得显示为可执行）
Template               — 模板（不得默认执行）
Policy                 — 策略资源（不得显示为可由 Agent 绕过）
Deterministic Converter — 确定性转换资源
External Resource      — 外部资源
```

规则：Case 不得显示为 Tool；Tool/MCP/Expert Agent 必须显示风险等级；Deterministic Converter 显示为资源，不显示为独立主线引擎。

## 13. 只读参考资源

包括：Case / Knowledge / 社区未审核资源 / 历史版本资料（D-004）/ 外部调研材料 / 只读 Template / 归档资源

规则：必须显示"只读参考"；不展示执行按钮/应用 Patch 按钮；引用到当前项目时形成 Trace；不自动成为当前事实源或 Evidence validated。

> 关联决策：D-004

## 14. 可执行资源

包括：Tool / MCP / Expert Agent / 部分 Skill / 确定性转换资源

必须展示：`risk_level / permission_scope / input_contract / output_contract / write_scope / gate_policy / trace_policy / audit_policy / last_call_status / 真实能力标记`

规则：可执行≠可直接执行；调用前检查状态/适用范围/风险/权限；allowed=true≠无需 Gate；高风险资源必须 Gate/Audit（D-034）；输出不自动成为 Evidence validated（D-066）。

> 关联决策：D-034, D-066

## 15. 资源调用前检查可视化

检查卡片：`resource_check_id / resource_id / resource_status / applicable / allowed / risk_level / requires_gate / requires_audit / policy_check_ref / gate_ref / blocking_reasons / warnings / trace_ref / next_actions`

规则：applicable=false 不得显示执行；allowed=false 显示阻断原因；requires_gate=true 打开 Gate；policy_blocked 不显示"强行执行"（D-030）；warnings 不掩盖 blocking_reasons。

> 关联决策：D-030

## 16. 资源调用记录可视化

规则：resource_call_completed≠任务完成；output_refs≠Artifact accepted；evidence_candidate_refs≠Evidence validated（D-066）；高风险调用显示 audit_ref；调用失败显示 error_ref/trace_ref；输出摘要脱敏。

## 17. 确定性转换资源可视化

规则：不显示为独立主线引擎；dry-run 与 apply 区分；patch_generated≠patch_applied≠P5 验证通过；高风险转换必须 Gate/Audit（D-034）；转换输出不自动成为 Evidence validated（D-066）。

## 18. 真实能力标记视觉规范

统一视觉标记（颜色+文字双通道）：

```text
real_available          — 绿色实心标签
real_limited            — 蓝色/黄色标签
configured_not_verified — 黄色标签
not_connected           — 灰色标签
mock                    — 紫色/斜纹标签（D-049）
static_demo             — 灰色虚线标签（D-049）
```

## 19. Mock / 静态演示 / 未接真实服务区分

三者必须区分（D-049）：

```text
mock         — 前端或测试数据模拟对象
static_demo  — 用于体验展示的静态样例
not_connected — UI 已有但尚未接入真实后端或外部服务
```

规则：mock 不显示为真实可用；static_demo 不允许真实执行；not_connected 不显示为 provider 可用或 resource active；触发未接真实服务能力时提示"未接真实服务"；R4/R5/R6/R13-R16 逐项校准。

> 关联决策：D-049

## 20-22. 联动（Gate/Policy/Trace/Audit + Evidence + Project/Run/Node）

- **Gate/Policy/Trace/Audit 联动**：模型调用失败显示 trace_ref；资源检查失败显示 policy_check_ref；requires_gate=true 打开 Gate；高风险调用显示 audit_ref；Policy blocked 不提供执行按钮（D-030）
- **Evidence 联动**：模型/资源输出可显示 output_ref；Artifact refs 与 Evidence candidate refs 必须区分；Evidence validated 必须来自后端验证状态（D-066）；No Evidence/No Trace 时不得显示可信完成
- **Project/Run/Node 联动**：每次模型/资源调用可定位到 project_id/run_id/stage/task_graph_id/node_id/agent_ref/skill_ref；前端不得凭 UI 状态自行补齐关联

> 关联决策：D-030, D-066

## 23-26. 错误/安全/SSE/状态恢复

- **错误 18 种**：model_unavailable / model_call_failed / credential_missing/invalid / resource_not_active/read_only/blocked/check_failed/call_failed / policy_blocked / gate_required/not_resolved / trace_missing / audit_missing / redaction_required / not_connected / mock_only / internal_error
- **安全脱敏**：可展示 credential_ref/credential_status/redacted/provider_ref/trace_ref/audit_ref；不得展示 Provider Key/API Key/GitHub Token/Secret/Password/.env 明文/未脱敏连接串/可还原密钥片段/未脱敏模型输入输出/未脱敏 Trace-Audit 详情
- **SSE 21 事件**：model_provider_created / model_profile_updated / model_binding_updated / model_call_started/completed/failed / model_usage_recorded / fusion_evaluation_completed / resource_registered/status_changed/check_completed/call_started/completed/failed/blocked/gate_required / converter_dry_run_completed/patch_generated / trace_written / audit_written / resync_required
- **状态恢复**：重新查询后端模型/资源对象；不从缓存推断真实可用；credential_status 以后端为准；resync_required 全量刷新
