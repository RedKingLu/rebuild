## 1. 信息架构目标

信息架构目标是让用户能以 Project 为中心理解 rebuild。

用户进入平台后，应能回答：

```text
1.  我有哪些 Project
2.  哪些 Project 正在运行
3.  哪些 Project 需要我决策
4.  哪些 Project 存在 Evidence 缺口
5.  如何创建一个新的 Project
6.  如何接入源码
7.  创建后从哪里进入 Workspace
8.  Project 当前处于 P0-P6 哪个阶段
9.  后台 Run 是否仍在执行
10. 下一步我该做什么
```

信息架构不应让用户先理解 Agent、RunEngine、内部 R 阶段或历史版本概念。

> 关联决策：D-003（产品定位）、D-009（P0-P6 流程）、D-070（Project 主对象）

## 2. 信息架构层级

R1 正式候选信息架构分为三层：

```text
平台层：    概览、项目、资源、模型、文档、设置
Project 层：项目总览、P0-P6、Runs、工作区、产物、证据、Trace、Audit、Gate、设置
Workspace 层：文件、阶段页、Agent 对话、TaskGraph、执行输出、Evidence/Trace/Audit/Gate 检视
```

层级规则：

```text
1. 平台层服务多 Project 管理
2. Project 层服务单 Project 推进
3. Workspace 层服务源码、产物、执行和证据协作（D-046, D-050）
4. 模型与资源是平台能力，不抢占 Project 主线
5. Gate 可在平台层、Project 层、Workspace 层都有入口（D-023）
6. R 阶段信息只应出现在平台建设文档或内部管理中，不作为用户项目导航（D-010）
```

> 关联决策：D-010, D-023, D-046, D-050

## 7. Project 创建流程总览

Project 创建采用简化两步流程：

```text
1. 基本信息    — Project 名称、描述、project_type 等元数据
2. 来源配置    — 本地目录 / Git / ZIP / GitHub 四类来源（D-035），含凭据状态
```

创建后直接进入 Workspace，源文件检测与导入由 P0 接入阶段驱动（D-009）。

首次进入 Workspace 时弹出引导向导（5 步：环境选择 → 提交方式 → 模型配置 → 执行模式 → 摘要确认），详见 `03-ProjectWorkspace布局规范.md` §25。

流程规则：

```text
1. 基本信息用于创建 Project 元数据
2. 来源选择与配置合并为一步（local_dir / git / zip / github）
3. 来源配置不得回显密钥
4. 创建成功 ≠ P0 完成（D-009）
5. 创建成功后直接进入 Workspace，源检测由 P0 阶段负责
6. 首次进入 Workspace 时弹出引导向导，配置环境/提交/模型/模式（可跳过）
```

> 关联决策：D-035（首批接入方式）

规则：

```text

2. description 可选
3. project_type / scenario_hint 不能引入 Mission 模板体系（D-070）
4. initial_notes 不得保存密钥明文（AGENTS.md §12）
5. 创建 Project 后不自动进入 completed
```

> 关联决策：D-070

## 15. 项目创建与 Workspace 关系

每个 Project 必须有独立 Project Workspace（D-050）。

前端应表达：

```text
Project Workspace 是项目文件、产物、Evidence、runs、任务状态隔离的工作场所
Project 创建后可初始化 Workspace
接入源码应落入 Project Workspace
Workspace 可从 Project 详情页进入
Workspace 采用独立全屏 IDE 心智（D-046）
```

规则：

```text
1. Workspace 不是普通导航常驻页（D-046）
2. Workspace UI 不等于状态源（D-053）
3. 退出 Workspace 不等于停止任务（D-052）
4. Workspace 路径展示需脱敏
5. Workspace 入口应显示是否 ready / unavailable / blocked
```

> 关联决策：D-046, D-050, D-052, D-053

## 16. 项目创建与 P0-P6 关系

Project 创建后应进入 P0-P6 语义，但不得自动完成阶段。

规则：

```text
1. Project 创建可以引导进入 P0 接入（D-009）
2. 接入完成可以为 P0 提供 Artifact / Evidence 候选（D-066）
3. P0 completed 必须由后端流程和 Gate / Evidence / Trace 等条件决定
4. 被裁剪阶段不得显示 completed（D-009）
5. P 阶段晋级必须用户 Gate（D-023）
```

前端展示建议：

```text
项目创建成功后，阶段条显示 P0 当前状态
如果接入任务仍在运行，P0 显示 importing / running / waiting_gate 等后端状态
如果接入失败，P0 显示 blocked / failed
如果接入完成但证据不足，P0 不得显示 completed
```

> 关联决策：D-009, D-023, D-066

## 17. 项目创建与 Gate 关系

项目创建和接入过程中可能触发 Gate（D-023~D-034）。

触发示例：

```text
覆盖已有 Workspace 内容
外部系统写操作（L3）
高风险路径（L4+）
凭据权限异常
ZIP 解压风险
策略阻断
不确定来源
```

展示规则：

```text
1. Gate 必须在创建流程中阻塞显示（D-023）
2. Gate 不得只显示为 toast
3. Gate 未决策不得继续阻塞动作
4. Gate 决策必须写 Audit
5. Policy 禁止项不得由前端批准
```

## 21. 前端状态管理


规则：

```text
1. server_state 必须可从后端重新查询
2. form_state 不得作为 Project 已创建事实（D-053）
3. draft_state 不得作为已提交事实
4. ui_state 不得判断完成状态（D-053）
5. mock_state 必须显式标记（D-049）
6. 前端不得自行推断 Project / Import / P0 completed
```

## 22. 安全与脱敏

项目创建和接入流程必须脱敏（AGENTS.md §12）。

可展示：

```text

credential_ref
redacted

```

不得展示：

```text
Git token
GitHub token
Password
Secret
.env 明文
未脱敏连接串
可还原密钥片段
包含凭据的 Git URL
```

规则：

```text
1. 凭据输入后不回显
2. 错误详情不包含凭据
3. Trace / Event / Audit 不包含凭据明文
4. 截图、导出、报告不包含凭据
5. redaction_required 必须阻止展示原文
```
