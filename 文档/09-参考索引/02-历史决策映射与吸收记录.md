
## 3. 映射状态定义

历史决策映射状态（与 `01-历史版本索引.md` §6 横向对照规则对齐）：

```text
保留并改写：历史意图仍适用，但需改写为当前版本语义；
合并吸收：内容被合并进当前更高层或更准确决策；
受控吸收：吸收经验、结构或教训，但不直接沿用；
移入参考：仅作为参考，不进入当前决策主线；
作为反例：作为失败教训或风险警示；
废弃：与当前版本裁决冲突或属于旧体系；
待确认：当前无法判断，需要用户或后续 Agent 确认；
禁止继承：明确不得复制、复活或沿用。
```

状态使用规则：

```text
1. "保留并改写"必须有当前落点（current_decision_ref 或 current_document_ref）；
2. "合并吸收"必须说明合并到哪个当前决策或文档；
3. "受控吸收"必须登记适配方式和风险；
4. "移入参考"不得写成当前事实；
5. "作为反例"必须说明反例价值（可关联 03-历史失败案例与可复用资产候选.md）；
6. "废弃"必须说明废弃原因；
7. "待确认"不得口头后延——必须进入当前待确认项清单；
8. "禁止继承"必须进入红线或审核清单。
```

## 4. 历史决策映射字段

每条映射记录（DM-*）包含以下字段：

```text
mapping_id              — DM-YYYYMMDD-序号
historical_version      — V8 / V10 / V26.0
historical_decision_id  — 旧决策编号（如有）
historical_title        — 旧决策标题（如有）
source_path             — archive 中的来源路径
source_type             — 文档 / 代码 / 报告 / 交接 / Demo / 配置示例
source_identity         — 只读参考 / 可受控吸收 / 反例 / 废弃 / 待确认
current_status          — 保留并改写 / 合并吸收 / 受控吸收 / 移入参考 / 作为反例 / 废弃 / 待确认 / 禁止继承
current_decision_ref    — 当前决策编号（如 D-XXX），不得伪造
current_document_ref    — 当前版本文档路径
current_stage_ref       — 关联 R 阶段
absorbed_points         — 吸收要点
rewritten_points        — 改写要点
rejected_points         — 拒绝/废弃要点
reason                  — 处理理由
adaptation_method       — 适配方式
risk                    — 风险（不得为空）
required_actions        — 需要的后续动作
review_status           — 待审核 / 已审核 / 需用户确认
reviewer                — 审核人
created_at / updated_at — 时间戳
redaction_status        — 已脱敏 / 不含敏感信息 / 需脱敏 / 不可展示
```

字段规则：

```text
1. source_path 必须指向历史参考源或当前事实源；
2. current_decision_ref 不得伪造——必须对应 01-决策记录 中实际存在的 D-XXX；
3. current_document_ref 必须是当前版本文档路径；
4. risk 不得为空；
5. redaction_status 必须明确；
6. 不得记录密钥、Token、env 明文或连接串。
```

## 11. 吸收记录与 Evidence 边界

吸收记录不是 Evidence validated。

规则：

```text
1. 吸收记录只说明参考和转化过程；
2. 吸收记录不能证明当前实现可用；
3. 吸收记录不能证明当前验收通过；
4. 若吸收内容影响实现，必须在当前实现中形成新的 Evidence；
5. 若吸收内容影响决策，必须回到当前决策记录或变更控制（→ 04-变更控制规范.md）；
6. 若吸收内容影响安全，必须走 Policy / Gate / Audit（→ 07-安全与权限/）。
```

> Evidence 完整定义见：`文档/00-项目治理/02-术语表.md` 第九部分；Evidence 验收规范见：`文档/08-测试与验收/05-Artifact-Evidence-Trace-Audit验收规范.md`。

## 12. 安全与脱敏规则

映射和吸收记录不得包含：

```text
Key；
Token；
Secret；
Password；
.env 明文；
连接串明文；
Git token；
Provider Key；
未脱敏日志；
未脱敏 Trace / Audit；
可还原密钥片段。
```

允许记录：

```text
配置存在；
凭据类型；
凭据状态；
redacted；
风险摘要；
需要用户重新配置。
```

规则：

```text
1. 历史密钥不得复制；
2. 历史配置只能作为配置形态参考；
3. 吸收记录输出前必须脱敏检查；
4. 发现敏感内容必须标记 redaction_required；
5. 脱敏失败不得展示原文。
```

> 安全与脱敏详细规范见：`文档/07-安全与权限/04-密钥与配置脱敏规范.md`；AGENTS.md §12。

## 13. 审核流程

历史决策映射与吸收记录审核流程：

```text
1. 编写人按本文 §8（AR-*）或 §9（DM-*）模板登记映射或吸收记录；
2. 本地 Agent 核查来源路径和摘要是否准确；
3. 独立验收 Agent 检查是否误用旧事实（对照本文 §7 高风险类型和 §15 红线）；
4. 如影响当前决策，提交用户与 Copilot 审核；
5. 审核通过后，更新当前文档或任务，并将审核状态改为"已审核"；
6. 审核未通过时，标记为"废弃""反例"或"待确认"（回到 §3 映射状态）。
```

规则：

```text
1. 未审核记录不得作为当前事实；
2. 需用户确认项不得后延或口头忽略；
3. 影响安全的吸收必须走安全审核；
4. 影响 API 的吸收必须 R2/R4 校准；
5. 影响前端真实能力的吸收必须 R3/R17 验收。
```
