## 2. 历史失败案例定义

历史失败案例是指历史版本中已经暴露或被记录为风险、缺陷、偏离、返工原因、体验误导、实现空洞、安全问题或验收失败的材料。

失败案例不等于历史版本全盘失败，也不等于当前方案必然失败。

失败案例可来自：

```text
历史验收报告；
历史交接材料；
历史设计偏离报告；
历史代码实现；
历史 Demo；
历史 API 对接问题；
历史模型配置问题；
历史前端体验问题；
历史安全与密钥问题；
历史执行链路问题；
历史证据链缺口；
历史用户裁决和返工记录。
```

> 跨版本失败教训详表（已从用户口述 + archive 索引提取的 9 条已确认教训）见：`07-版本演进与历史资产吸收.md` §3。本文的 FC-* 模板用于登记 R2 深读 archive 后发现的**额外**失败案例，或对 §3 已有教训的逐条展开。

## 3. 可复用资产候选定义

可复用资产候选是指历史版本中可能对当前版本有价值，但尚未经过当前版本校准、审核和验收的经验、结构、字段、交互、流程、测试、案例、资源或实现思路。

**候选不等于采纳。**

候选可包括：

```text
信息架构；
页面结构；
字段经验；
API 形态；
错误码经验；
SSE 事件经验；
状态恢复经验；
Workspace 组织方式；
模型服务商配置经验；
Agent / Skill / Tool / MCP 边界经验；
Case / Knowledge 组织经验；
测试与验收清单；
反例和失败教训；
确定性转换工具思路；
验证策略候选。
```

候选不得包括：

```text
密钥；
旧 env 明文；
可还原凭据片段；
未经脱敏日志；
旧 RunEngine 直接复活；
旧 S0-S7 / F0-F6 主流程；
未经审核的可执行社区资源；
未经当前 Policy / Gate / Audit 校准的执行路径。
```

> 四类吸收策略中"应吸收/应借鉴"的具体条目见：`07-版本演进与历史资产吸收.md` §4。本文的 AC-* 模板用于登记从 archive 深读中新发现的候选资产。

## 4. 分类体系

### 4.1 失败案例分类（F-*）

```text
F-ARCH：架构失败或架构偏离；
F-FLOW：流程与阶段体系失败；
F-RUNTIME：运行时 / 编排 / 状态机失败；
F-FRONTEND：前端体验或真实能力标记失败；
F-API：API / SSE / 状态契约失败；
F-MODEL：模型网关、多服务商、成本或凭据配置失败；
F-AGENT：Agent / Skill / Tool / MCP / Case 边界失败；
F-WORKSPACE：Workspace / Execution / Runtime 状态失败；
F-EVIDENCE：Artifact / Evidence / Trace / Audit 链路失败；
F-SECURITY：安全、权限、密钥、脱敏失败；
F-TEST：测试、验证、回归、交付失败；
F-DOC：文档事实源、交接、上下文污染失败。
```

### 4.2 可复用资产候选分类（A-*）

```text
A-IA：信息架构候选；
A-UX：前端交互候选；
A-API：API / SSE 字段候选；
A-DATA：状态和数据模型候选；
A-MODEL：模型网关和 Provider 配置候选；
A-AGENT：Agent / Skill / Resource 候选；
A-TOOL：Tool / MCP / 确定性转换候选；
A-WORKSPACE：Workspace / Execution 候选；
A-EVIDENCE：Evidence / Trace / Audit 候选；
A-TEST：测试与验收候选；
A-DOC：文档结构与交接候选；
A-RISK：风险控制与反例候选。
```

> F-* 和 A-* 分类与 `02-历史决策映射与吸收记录.md` §7 高风险历史决策类型（13 类）互补——F-* 侧重"出过什么问题"，§7 侧重"哪些类型要警惕"。两者可交叉引用。

## 5. 失败案例登记字段

失败案例记录字段：

```text
failure_id              — FC-YYYYMMDD-序号
historical_version      — V8 / V10 / V26.0
source_path             — archive 中的来源路径
source_type             — 文档 / 代码 / 报告 / 交接 / Demo / 配置示例
failure_category        — F-ARCH / F-FLOW / ...（见 §4.1）
failure_title           — 失败案例标题
failure_summary         — 脱敏摘要（不得复制旧正文）
observed_symptom        — 观察到的现象
root_cause_hypothesis   — 根因推断（必须标明是推断）
confirmed_root_cause    — 已确认根因（只有来源明确时才填写）
current_relevance       — 对当前版本的相关性（不得夸大）
current_risk            — 当前版本复发风险
avoidance_rule          — 避免规则（必须能转化为审核清单或设计约束）
related_R_stage         — 关联 R 阶段
related_current_docs    — 关联当前文档
follow_up_actions       — 后续动作
review_status           — 审核状态（见 §15）
redaction_status        — 已脱敏 / 不含敏感信息 / 需脱敏 / 不可展示
created_at / updated_at — 时间戳
```

字段规则：

```text
1. source_path 必须指向历史参考源或当前事实源；
2. failure_summary 只能写脱敏摘要；
3. root_cause_hypothesis 必须标明是推断（事实/推断/建议分离，见 AGENTS.md §6.5）；
4. confirmed_root_cause 只有来源明确时才填写；
5. current_relevance 不得夸大；
6. avoidance_rule 必须能转化为当前审核清单或设计约束；
7. redaction_status 必须明确。
```

## 6. 可复用资产候选登记字段

资产候选记录字段：

```text
asset_candidate_id      — AC-YYYYMMDD-序号
historical_version      — V8 / V10 / V26.0
source_path             — archive 中的来源路径
source_type             — 文档 / 代码 / 报告 / 交接 / Demo / 配置示例
asset_category          — A-IA / A-UX / A-API / ...（见 §4.2）
asset_title             — 资产候选标题
asset_summary           — 脱敏摘要（不得复制旧正文或旧代码）
reuse_value             — 可复用价值（必须说明价值来源，不得泛泛而谈）
reuse_scope             — 复用范围
required_adaptation     — 必要适配（如何改成当前语义）
rejected_parts          — 不可继承部分（旧流程/旧接口/旧实现/旧安全风险等）
risk                    — 风险
related_R_stage         — 关联 R 阶段
related_current_docs    — 关联当前文档
validation_required     — 验证要求（当前版本需怎样验证后才可采纳）
owner_or_reviewer       — 负责人或审核人
review_status           — 审核状态（见 §15）
redaction_status        — 已脱敏 / 不含敏感信息 / 需脱敏 / 不可展示
created_at / updated_at — 时间戳
```

字段规则：

```text
1. asset_summary 只能写脱敏摘要；
2. reuse_value 必须说明价值来源；
3. required_adaptation 必须说明如何改成当前语义；
4. rejected_parts 必须列出不能继承内容；
5. validation_required 必须说明需要什么当前验证；
6. review_status 未通过前不得标记已采纳；
7. asset_candidate 不得作为 Evidence validated。
```

## 9. 已知历史失败主题候选

以下是 R1 建议优先登记和核查的失败主题候选。它们**不是已完成的失败案例全文**，而是后续深读入口——每个主题都必须找到具体来源（archive 中的真实文件）后才能按 §7 FC-* 模板登记为正式案例。

```text
旧 RunEngine / 自研运行时调试困难；
旧流程阶段与当前 P0-P6 / R0-RN 冲突；
旧前端 Demo 或 mock 被误认为真实能力；
模型调用未真实发生但任务状态推进；
产物生成但 Evidence 不足；
Trace / Audit 缺失但结果被显示为可信；
环境和 Execution 状态混淆；
Workspace、Runtime、Execution 状态未分离；
API 字段缺失导致前后端联调困难；
SSE 事件被误用为事实源；
模型服务商和多 Provider 配置不完整；
Case、Skill、Tool、MCP 边界混淆；
社区资源默认可执行的风险；
测试、构建、运行、回归证据不足；
密钥、env、配置脱敏不足；
文档事实源重复或漂移；
交接材料不自包含导致外部 Agent 无法独立执行。
```

登记规则：

```text
1. 每个主题都必须找到具体来源后再登记为正式 FC-* 案例；
2. 未找到来源前只能标记为"待核查"；
3. 不得把主题候选当作已证实事实；
4. 不得用主题候选替代当前验收。
```

## 12. 候选采纳流程

可复用资产候选采纳流程（三步法在资产吸收中的具体化）：

```text
1. 登记候选（按 §8 AC-* 模板，状态 = candidate）；
2. 核查来源（在 archive 中找到真实文件）；
3. 标记材料身份（只读参考 / 可受控吸收 / 反例 / 废弃 / 待确认）；
4. 先立当前方案（三步法第一步——不先看旧代码）；
5. 对比历史候选（三步法第二步——深度吸收）；
6. 登记可吸收和不可吸收内容（按 §8 "可复用价值""不可继承部分"）；
7. 说明适配方式（按 §8 "必要适配"）；
8. 登记风险；
9. 更新当前文档或任务（三步法第三步——完善后执行）；
10. 形成当前版本 Evidence（不是历史 Evidence）；
11. 通过审核后标记"已吸收"（状态 = adapted → validated）。
```

规则：

```text
1. 未审核候选不得标记已吸收；
2. 未形成当前 Evidence 不得标记真实能力可用；
3. 影响安全的候选必须走 Policy / Gate / Audit（→ 07-安全与权限/）；
4. 影响 API 的候选必须 R2/R4 校准（→ 05-API与集成契约/）；
5. 影响前端体验的候选必须 R3/R17 验收（→ 06-UX与前端/）；
6. 影响验证策略的候选必须 R12 验收（→ 08-测试与验收/）。
```

## 15. 审核状态

本文涉及的审核状态（FC-* 和 AC-* 共用，与 `02-历史决策映射与吸收记录.md` §3 映射状态互补）：

```text
candidate              — 候选，尚未核查
source_verified        — 来源已核查
analysis_done          — 分析完成
accepted_for_adaptation — 允许受控吸收
rejected               — 不吸收
deprecated             — 明确废弃
needs_user_decision    — 需用户确认
adapted                — 已适配到当前方案
validated              — 已通过当前版本验证
```

状态流转规则：

```text
1. candidate → source_verified → analysis_done → accepted_for_adaptation → adapted → validated
2. 任一阶段可转入 rejected / deprecated / needs_user_decision
3. candidate 不得写成 adapted（跳过核查和审核）
4. adapted 不得写成 validated（跳过当前版本验证）
5. validated 必须有当前 Evidence（不是历史 Evidence）
6. needs_user_decision 不得后延——必须进入当前待确认项清单
7. rejected / deprecated 仍可作为反例保留，供 R17 核查是否复发
```

> 与 02 的 DM 映射状态关系：02 的"作为反例"对应本文的 F-* 分类；02 的"受控吸收"对应本文 accepted_for_adaptation → adapted → validated 流程；02 的"废弃"对应本文 deprecated。
