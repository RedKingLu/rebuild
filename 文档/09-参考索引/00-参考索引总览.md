## 0. 编写原则

本文遵守当前文档事实源层级：

```text
项目治理 > 产品定义 > 架构设计 > 专题规范
```

参考索引目录的职责是帮助查找、引用和受控吸收参考材料，不负责重新裁决产品事实。

本文必须遵守：

```text
1. 当前版本决策以 文档/00-项目治理/01-决策记录.md 为准；
2. V8 / V10 / V26.0 的决策、文档、代码、报告和交接材料仅作为参考源，不自动成为当前版本事实源；
3. 历史版本只读参考，不直接复制到当前版本（详见 AGENTS.md §11）；
4. 吸收历史材料必须记录理由、适配方式和风险（详见 文档/00-项目治理/07-版本演进与历史资产吸收.md §4）；
5. 当前版本正式事实源从 /home/king/rebuild/文档/、/home/king/rebuild/交接/、/home/king/rebuild/产物/、/home/king/rebuild/证据/ 开始建立；
6. 历史资产代码级深读并入各对应 R 阶段，不单独成阶段（详见 AGENTS.md §11.1 三步法、D-067）；
7. 模块建设遵循"先立己方案 → 深度吸收旧方案 → 完善后执行"三步法；
8. 参考材料不得绕过 Policy / Gate / Audit；
9. 参考材料不得携带或泄露 Key / Token / Secret / Password；
10. 当前版本不设独立 Mission 产品层。
```

> 通用禁止与红线完整总表见 AGENTS.md §18；相关决策详见 01-决策记录.md；术语与风险级别（L0-L5）详见 02-术语表.md。（P 阶段晋级 Gate D-023 / Policy 优先 D-031 / Artifact 不自动晋升 D-014 / Manual-Plan-Auto D-025 等通用红线详见 AGENTS §18 + 01-决策记录）


## 1. 参考索引目标

参考索引用于解决以下问题：

```text
1. 历史材料在哪里；
2. 哪些材料可以参考；
3. 哪些材料只能只读；
4. 哪些历史资产可受控吸收；
5. 哪些旧实现应明确废弃；
6. 当前文档引用历史材料时应如何标注；
7. 后续 R 阶段深读历史代码时如何登记；
8. 外部 Agent 在无本地上下文时如何理解参考边界。
```

参考索引不是为了扩大事实源，而是为了降低重复踩坑、避免上下文污染、避免旧版本事实回流。

## 6. 历史版本参考规则

历史版本参考时必须记录：

```text
参考路径；
参考对象；
参考目的；
当前版本适配方式；
不吸收内容；
风险；
是否需要用户确认；
是否形成当前产物；
是否进入 Evidence；
是否已脱敏。
```

历史版本参考禁止：

```text
1. 不得直接复制旧代码运行；
2. 不得直接复制旧文档作为当前正文；
3. 不得复活旧 RunEngine；
4. 不得复活旧 S0-S7 / 旧 F0-F6 主流程；
5. 不得直接继承旧 API 字段为当前实现；
6. 不得把旧验收通过作为当前验收通过；
7. 不得把旧 Demo 当作当前真实能力。
```

> 历史版本参考规则与禁止事项在 `文档/00-项目治理/07-版本演进与历史资产吸收.md` 中有更完整的展开（含跨版本失败教训详表和四类吸收策略）。本文 §6 提供操作级引用格式，详情以 07 为准。AGENTS.md §11 和 §18 提供了适用于所有 Agent 的历史版本使用硬规则和禁止事项总表。

## 7. 历史资产吸收规则

历史资产吸收遵循"三步法"（详见 AGENTS.md §11.1、D-067）：

```text
第一步：先独立提出当前版本自己的方案（不先看旧代码，保证主体性）；
第二步：再深度吸收对应历史方案（archive 只读，记录 吸收/不吸收/适配/风险）；
第三步：用吸收到的经验完善自己的方案，再执行。
```

吸收记录建议字段：

```text
absorption_id；
R_stage；
module；
reference_path；
reference_identity；
absorbed_points；
rejected_points；
adaptation_method；
risk；
current_document_refs；
evidence_refs；
review_status；
created_at。
```

吸收判断：

```text
1. 能复用经验，不等于能复用代码；
2. 能参考界面结构，不等于逐像素复制；
3. 能吸收字段经验，不等于直接固化旧字段；
4. 能借鉴失败教训，不等于保留旧实现；
5. 能参考验收报告，不等于当前验收通过。
```

> 历史资产吸收策略的完整四分类（应吸收/应借鉴/应抛弃/应内化教训）和跨版本失败教训详表见：`文档/00-项目治理/07-版本演进与历史资产吸收.md` §3-§4。本文 §7 仅提供操作级吸收记录模板和判断原则。

## 8. R 阶段深读索引规则

历史资产代码级深读并入各对应 R 阶段（不单独成阶段，见 AGENTS.md §11.1）。

建议映射：

```text
R3：前端历史信息架构、页面、交互、Demo 经验；
R4：工程骨架、API、SSE、状态模型、数据层历史经验；
R5：ModelGateway、模型配置、多服务商适配历史经验；
R6：Agent、Skill、Tool、MCP、资源注册历史经验；
R7：项目接入、本地目录、Git、ZIP、GitHub 经验；
R8：Workspace、Environment Profile、Execution Session 经验；
R9-R12：P0-P6 主链路、执行、验证、交付经验；
R13-R16：Fusion、远程资源、社区、文档功能历史经验；
R17：全量联调、发布冻结、体验打磨经验。
```

规则：

```text
1. 不单独开"历史深读阶段"；
2. 进入对应 R 阶段前先立当前方案（三步法第一步）；
3. 深读后必须登记吸收与不吸收内容；
4. 深读不得导致旧事实污染当前决策；
5. 深读结果必须进入对应模块文档或吸收索引（登记到 02-历史决策映射与吸收记录.md 或对应 R 阶段产物）。
```

## 9. 参考引用格式

引用参考材料时使用：

```text
参考材料：<路径或文件名>
材料身份：只读参考 / 可受控吸收 / 反例 / 废弃 / 待核查
引用目的：说明为什么引用
吸收结论：吸收 / 不吸收 / 部分吸收 / 待确认
适配方式：如何转化为当前版本语义
风险：可能带来的旧事实污染或实现风险
当前落点：写入哪个当前文档、产物或证据
```

示例：

```text
参考材料：/home/king/rebuild-archive/V10/...
材料身份：反例 / 可受控吸收
引用目的：识别旧 RunEngine 调试失败原因
吸收结论：吸收教训，不吸收旧实现
适配方式：在 R4 工程骨架中避免复活旧自研状态机
风险：旧接口字段可能污染当前 API 命名
当前落点：文档/02-架构设计/... 或 文档/09-参考索引/02-历史决策映射与吸收记录.md
```

```text
6. 外部链接、截图、摘要不得包含密钥。
```

## 11. 参考材料与 Evidence 边界

参考材料可以帮助提出假设、形成对比、定位风险，但不能自动成为 Evidence validated。

规则：

```text
1. 参考材料不等于 Evidence；
2. 历史验收报告不等于当前验收通过；
3. 历史运行日志不等于当前运行成功；
4. 历史代码存在不等于当前能力可用；
5. 外部调研结论不等于当前产品事实；
6. 若参考材料要进入 Evidence，必须经过当前版本验证流程。
```

> Evidence 完整定义见：`文档/00-项目治理/02-术语表.md` 第九部分；Evidence 验收规范见：`文档/08-测试与验收/05-Artifact-Evidence-Trace-Audit验收规范.md`。

## 12. 安全与脱敏规则

参考索引必须遵守安全与脱敏要求。

不得进入参考索引正文：

```text
Key；
Token；
Secret；
Password；
.env 明文；
连接串明文；
Git token；
Provider Key；
未脱敏 Trace / Audit；
未脱敏命令输出；
未脱敏截图。
```

允许记录：

```text
配置存在状态；
credential_ref；
credential_status；
redacted；
脱敏摘要；
安全风险说明；
需用户重新配置提示。
```

红线：

```text
1. 不得为了索引完整展示密钥；
2. 不得把历史 env 明文复制到当前文档；
3. 不得把外部 Agent 交接材料写入密钥；
4. 不得把凭据写入 Memory；
5. 不得把未脱敏参考材料交给模型上下文；
6. 脱敏失败必须阻断展示。
```

> 安全与脱敏详细规范见：`文档/07-安全与权限/04-密钥与配置脱敏规范.md`；AGENTS.md §12。
