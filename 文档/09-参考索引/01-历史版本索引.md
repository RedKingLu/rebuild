## 1. 历史版本索引目标

历史版本索引用于帮助后续 Agent 快速判断：

```text
1. 历史材料位于哪里；
2. 每个历史版本是什么参考身份；
3. 哪些内容可作为经验参考；
4. 哪些内容应作为反例或失败教训；
5. 哪些内容禁止直接继承；
6. 哪些内容需要在对应 R 阶段深读；
7. 引用历史材料时如何登记；
8. 如何避免历史事实污染当前版本。
```

历史版本索引的价值在于"可查、可控、可追溯"，不是"恢复旧版本"。

> 版本演进旅程、重启根因、跨版本失败教训详表和四类吸收策略（应吸收/应借鉴/应抛弃/应内化教训）的完整记录见：`文档/00-项目治理/07-版本演进与历史资产吸收.md`。本文提供操作级版本索引和引用规则。

## 6. 历史版本横向对照规则

横向对照历史版本时必须区分：

```text
沿用：经当前决策记录或专题文档确认后继续使用；
改写：保留意图，但改成当前 P0-P6 / R0-RN 语义；
吸收：吸收经验或设计资产，但不直接复制；
反例：作为失败教训；
废弃：与当前裁决冲突；
待确认：无法判断，需要用户或后续 Agent 确认。
```

> 四类吸收策略（应吸收/应借鉴/应抛弃/应内化教训）的完整分类和具体条目见：`07-版本演进与历史资产吸收.md` §4。

对照时不得：

```text
1. 只因历史版本存在就沿用；
2. 只因历史版本失败就全盘丢弃；
3. 混用不同历史版本术语；
4. 用旧文档覆盖新决策；
5. 将旧结论直接写入当前产品定义。
```

## 8. 历史代码引用规则

历史代码引用必须更严格。

允许：

```text
阅读旧代码结构；
记录旧实现失败原因；
提炼字段和接口经验；
提炼模块边界经验；
提炼测试和验证缺口；
提炼安全和权限教训；
形成当前版本自有方案的改进建议。
```

禁止：

```text
1. 直接复制旧代码作为当前骨架；
2. 直接运行旧实现作为当前能力；
3. 复活旧 RunEngine；
4. 用旧状态机替代 LangGraph 主编排；
5. 复制旧配置中的密钥；
6. 把旧代码可运行写成当前能力可用；
7. 不登记吸收记录就使用旧代码思路。
```

> 代码引用三步法（先立己方案 → 深读旧方案 → 完善后执行）详见 AGENTS.md §11.1 和 D-067。

.env 明文；
