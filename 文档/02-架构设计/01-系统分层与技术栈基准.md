## 1. 系统分层基准

rebuild 当前版本采用以下系统分层（继承自 `00-架构总纲.md` §2）：

```text
Arch-L0 治理与策略层
Arch-L1 产品流程层
Arch-L2 编排与运行时层
Arch-L3 Agent / Skill / 资源层
Arch-L4 模型网关层
Arch-L5 工作区与执行环境层
Arch-L6 数据、事件、证据与审计层
Arch-L7 API 与前端交互层
Arch-L8 测试、验证与交付层
```

这些层不是代码目录的强制命名，也不是微服务拆分方案，而是架构职责边界。

后续代码结构可以采用 monorepo、模块包、服务包或目录分层，但必须能清晰映射到这些职责边界。

> **命名区分**：本文 Arch-L0~Arch-L8 为架构分层编号。风险级别 L0-L5（`02-术语表.md`）为安全维度编号，互不冲突。

## 2. 技术栈基准总览

当前技术栈基准如下：

```text
后端：Python + FastAPI（暂定）
主编排：LangGraph（确定）
前端：React + Vite + TypeScript（暂定）
数据库：SQLite 起步，保留 PostgreSQL 适配空间（暂定）
模型网关：rebuild ModelGateway + LiteLLM SDK Adapter（暂定）
存储：本地文件系统起步，按 Project Workspace 组织（暂定）
事件：SSE / event log / LangGraph checkpoint 协同（建议，R2/R4 校准）
测试：以后端测试、前端测试、端到端验收和 P5 验证证据为主（建议，测试与验收目录细化）
部署：本地开发优先，后续按 R 阶段补充容器化或发布方式（待校准）
```

技术栈变更规则：

```text
1. LangGraph 主编排不得随意替换（D-037）；
2. 后端、前端、数据库、模型网关适配路线为暂定项，变更必须提出申请与理由（D-038）；
3. 变更必须说明影响范围、替代方案、迁移成本、风险和验收方式；
4. 不得以技术栈变更为由降低 P0-P6 主干完备性；
5. 不得引入重型基础设施替代已经确认的薄编排原则（D-065）。
```

## 3. Arch-L0 治理与策略层

### 3.1 职责

治理与策略层负责：

```text

版本与目录策略；
文档地图；
变更控制；
交接规范；
AGENTS.md；
历史资产只读参考（D-062）；
事实源层级（D-068）；
不确定项处理；
准则与红线。
```

### 3.2 技术栈含义

Arch-L0 不对应某个运行时框架，但必须在工程中体现为：

```text
1. 文档事实源可找到；
2. AGENTS.md 可约束 Agent 行为；
3. 变更控制可记录技术栈变更；
4. 历史资产吸收可追踪（D-067）；
5. 决策编号可被架构、API、UX、测试文档引用。
```

### 3.3 不应做的事

```text
1. 不在架构目录另建 ADR 事实源；
2. 不在代码注释中替代决策记录；
3. 不把 README 作为完整目录事实源；
4. 不让专题文档覆盖决策记录。
```

## 4. Arch-L1 产品流程层

### 4.1 职责

产品流程层负责：

```text
Project；
P0 接入 → P1 建档 → P2 评估 → P3 规划 → P4 执行 → P5 验证 → P6 交付；
用户 Gate；
项目场景引导。
```

### 4.2 系统边界

架构上必须确保：

```text
1. Project 是用户可见主对象（D-070）；
2. Project 可进入 P0-P6；
3. 同一 Project 内可产生 Run、Stage Plan、Task Plan、TaskGraph、Artifact、Evidence、Trace、Audit；
4. P 阶段晋级必须用户授权（D-023）；
5. 被裁剪阶段不得伪装 completed；
6. 不设置独立 Mission 产品层。
```

### 4.3 技术栈映射

产品流程层通常映射到：

```text
后端领域服务：ProjectService、StageService、RunService、GateService 等；
编排图：LangGraph stage graph；
前端页面：Project 列表、Project 概览、阶段页、Gate 交互；
数据对象：project、run、stage_status、gate、artifact、evidence、trace、audit。
```

具体命名由 R2/R4 根据实现校准，本文不固定类名、表名或 API 字段。

## 5. Arch-L2 编排与运行时层

### 5.1 职责

编排与运行时层负责：

```text
LangGraph 主流程；
阶段跳转；
checkpoint；
interrupt / resume；
NodeLoop；
TaskGraph；
执行模式（D-023~D-029）；
失败、重试、返工和 Gate 流转。
```

### 5.2 技术栈基准

```text
主编排：LangGraph（确定）
运行时语言：Python（随后端暂定）
接口承载：FastAPI（暂定）
状态恢复：数据库 + LangGraph checkpoint + workspace 文件 + trace/audit + event log（确定方向，字段待校准）
```

### 5.3 LangGraph 使用边界

LangGraph 应承载：

```text
1. P0-P6 主流程；
2. 阶段跳转；
3. Gate interrupt；
4. resume；
5. checkpoint；
6. 节点级流转；
7. 失败或返工分支。
```

不得用自研状态机替代：

```text
1. 阶段主流程；
2. checkpoint 主能力；
3. interrupt/resume 主能力；
4. P0-P6 图式编排职责。
```

### 5.4 自研适配层边界（D-065）

允许自研：

```text
状态 schema；
业务服务；
API/SSE；
Artifact/Evidence/Trace/Audit 数据层；
Workspace Service；
ExecutionProvider；
Policy/Audit 服务；
模型和资源 Adapter；
领域规则。
```

自研适配层不得膨胀为另一个主编排引擎。

## 6. Arch-L3 Agent / Skill / 资源层

### 6.1 职责

Agent / Skill / 资源层负责：

```text
执行节点任务；
调用 Skill；
调用 Tool/MCP；
检索 Case/Knowledge；
执行安全检查；
生成 Artifact；
生成 Evidence；
执行自验证；
把结果交给 Acceptance Agent 或 Gate。
```

### 6.2 Agent 基准（D-019）

当前第一阶段只保留少量必要 Agent 类型：

```text
Node Worker Agent；
Acceptance Agent；
Auto Review / Authorization / Safety Agent；
Expert Agent；
Conversation / Gate Agent。
```

不为每个阶段固定新 Agent。

### 6.3 Skill 与平台资源目录（D-008-REV1）

目录基准：

```text
skills/                         ← R 系列建设 Skill
平台资源/
├── agents/
├── skills/
│   └── P系列/
├── tools/
├── mcp/
├── cases/
├── knowledge/
├── policies/
├── templates/
└── registry/
```

如果当前磁盘状态未完全对齐，以 R2 目录盘点和校准为准。

### 6.4 Case / Knowledge / Template 边界

```text
Case：经验材料，可检索、可引用、可比较，不具备执行权（D-040）；
Knowledge：知识材料，用于辅助判断，不自动成为当前项目事实；
Template：模板材料，用于生成结构，不自动进入正式文档；
Tool/MCP：可执行能力，必须受 Policy/Gate/Audit 约束。
```

## 7. Arch-L4 模型网关层

### 7.1 职责

模型网关层负责：

```text
模型 Provider 适配；
模型配置；
模型选择策略；
模型调用记录；
模型错误处理；
模型能力标签；
Fusion 作为模型能力；
token/成本预算扩展。
```

### 7.2 技术栈基准

```text
ModelGateway：rebuild 自研薄抽象层（暂定）
Adapter：LiteLLM SDK Adapter（暂定）
Fusion：ModelProfile/ModelStrategy 类型能力（确定边界，D-035）
```

### 7.3 ModelGateway 薄抽象原则（D-065）

ModelGateway 只做必要抽象：

```text
1. 统一调用入口；
2. 统一模型配置读取；
3. 统一模型选择优先级；
4. 统一调用记录；
5. 统一错误与 fallback；
6. 统一能力标签；
7. 统一密钥脱敏边界。
```

ModelGateway 不应重复实现 LiteLLM 已覆盖的通用 Provider 能力。

### 7.4 Fusion 边界（D-035）

Fusion 不作为：

```text
特殊阶段；
特殊流程；
特殊评审引擎；
独立 Agent；
默认验收者；
授权主体。
```

Fusion 只作为模型能力或模型策略被 ModelGateway 管理。

## 8. Arch-L5 工作区与执行环境层

### 8.1 职责

工作区与执行环境层负责：

```text
Project Workspace；
Environment Profile；
Execution Session；
源码与材料持久化；
执行隔离；
构建、测试、Patch；
运行与预览；
执行输出收集。
```

### 8.2 技术栈基准

```text
存储：本地文件系统起步，按 Project Workspace 组织（暂定）
执行：Execution Session 按需隔离（实现方式待 R8/R11 校准）
环境：Environment Profile 声明化（字段待 R2/R4 校准）
```

### 8.3 Project Workspace 基准（D-050）

Project Workspace 必须支撑：

```text
1. 每项目独立；
2. 源码、材料、Artifact、Evidence、runs、Trace/Audit 按 project_id 隔离；
3. 前端可按代码视图和材料视图展示（D-048）；
4. 不作为唯一状态源；
5. 不替代 Execution Session。
```

### 8.4 Environment Profile 基准

Environment Profile 必须支撑：

```text
1. 项目运行环境声明；
2. 构建要求；
3. 测试要求；
4. 依赖要求；
5. 外部服务要求；
6. 环境风险；
7. 执行前置条件。
```

### 8.5 Execution Session 基准

Execution Session 必须支撑：

```text
1. 命令执行；
2. 构建执行；
3. 测试执行；
4. Patch 生成；
5. Tool/MCP/外部 Agent 调用；
6. 输出采集；
7. Policy/Hook/Gate/Audit。
```

具体隔离方式待 R8/R11 施工校准。

## 9. Arch-L6 数据、事件、证据与审计层

### 9.1 职责

该层负责：

```text
数据库；
checkpoint；
event log；
Artifact 存储；
Evidence 存储；
Trace 记录；
Audit 记录；
Gate 决策持久化；
资源调用记录；
模型调用记录。
```

### 9.2 技术栈基准

```text
数据库：SQLite 起步，保留 PostgreSQL 适配空间（暂定）
checkpoint：LangGraph checkpoint（确定方向）
event log：建议保留事件日志（字段待校准）
workspace 文件：作为文件型产物和材料持久化基础（暂定）
```

### 9.3 SQLite / PostgreSQL 边界

SQLite 起步适合：

```text
1. 单人开发；
2. 本地优先；
3. 快速联调；
4. R1-R4 阶段基线搭建；
5. 简化部署和调试。
```

保留 PostgreSQL 适配空间用于：

```text
1. 后续多项目高并发；
2. 更强事务与并发；
3. 多用户或商业化部署；
4. 更严格审计和报表。
```

本文不要求 R1 直接实现 PostgreSQL，但不得写死 SQLite 到不可迁移的架构中。

### 9.4 Evidence / Trace / Audit 原则（D-066）

```text
No Evidence, No Accepted Result；
No Artifact, No Completed；
No Trace, No Trusted Execution；
High Risk Action Requires Audit；
Gate Decision Requires Audit。
```

具体字段进入 API 与测试验收专题。

```text
审计替代者；

```

前端必须显式标记 mock 或未接真实服务的能力。

```text
Python + FastAPI；
React + Vite + TypeScript；
SQLite 起步，PostgreSQL 适配空间；
ModelGateway + LiteLLM SDK Adapter；
本地文件系统起步；
SSE 事件传输方案；
```

### 12.2 变更申请必须说明

```text
变更对象；
当前方案；
拟替代方案；
变更原因；
影响范围；
迁移成本；
新增风险；
对 P0-P6 主链路影响；
对 API/UX/测试验收影响；
回退方案；
验收方式。
```

### 12.3 难以变更或不可随意变更项

```text
LangGraph 主编排底座（D-037）；
项目治理事实源层级（D-068）；
Project 作为用户可见主对象（D-070）；
P0-P6 产品流程（D-009）；
P 阶段晋级用户 Gate（D-023）；
Policy 优先级高于 Agent（D-031）；
```
