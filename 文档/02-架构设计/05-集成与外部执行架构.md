## 1. 架构定位

集成与外部执行是支撑 P0-P6 基础主链路的横切基础能力。

它不是一个独立产品阶段，也不是 R13-R16 的低优先级增强功能。

其核心作用是让 rebuild 能够：

```text
1. 接入真实源码；
2. 同步真实仓库状态；
3. 在受控 Workspace 中读取和修改代码；
4. 调用外部编程执行器或工具完成代码改造；
5. 在本地或远程执行环境中运行命令、构建、测试和服务；
6. 对高风险动作进行 Policy / Gate / Audit 管控；
7. 记录 Artifact / Evidence / Trace / Audit；
8. 支撑 P5 验证和 P6 交付。
```

如果集成能力缺失，则 P0 接入、P4 执行、P5 验证和 P6 交付都容易退化为手工链路、mock 链路或不可复核链路。

## 3. 架构分层

建议采用以下分层：

```text
用户 / 前端
  ↓
API 与 SSE 层
  ↓
Project / Run / Stage 服务
  ↓
Workspace Service
Environment Service
Execution Session Service
  ↓
Integration Orchestrator
  ↓
ExecutionProvider / Resource Invocation Layer
  ↓
Git Adapter / GitHub Adapter / ZIP Adapter / Local FS Adapter
OpenCode Adapter / Tool Adapter / MCP Adapter / Expert Agent Adapter
Remote Environment Adapter
  ↓
Policy / Gate / Audit / Trace 横切层
  ↓
Artifact / Evidence / Trace / Audit 数据层
```

分层规则：

```text
1. 前端不直接执行 Git、命令、远程调用或外部 Agent；
2. API 层不绕过 Policy / Gate / Audit；
3. Integration Orchestrator 只做编排与路由，不承载业务事实判断；
4. ExecutionProvider 统一封装执行动作和资源调用；
5. Adapter 只适配外部系统或执行器，不直接决定阶段完成；
6. Evidence validated 必须由验证流程产生；
7. Trace / Audit 必须由后端事实源写入。
```

## 4. 与 P0-P6 的关系

### 4.1 P0 接入

P0 依赖集成能力完成：

```text
本地目录接入；
Git clone；
GitHub repository 接入；
ZIP 解包；
Workspace 初始化；
凭据引用和状态检查；
接入 Trace；
源码接入 Evidence candidate。
```

P0 不应依赖：

```text
手工复制源码后伪装接入；
前端静态项目列表；
未记录来源的文件目录；
未脱敏凭据；
无法追溯的临时目录。
```

### 4.2 P4 执行

P4 依赖集成与外部执行完成：

```text
文件读取；
文件写入；
Patch generated；
Patch applied；
命令执行；
Tool / MCP 调用；
OpenCode / 外部编程 Agent 调用；
Git status / diff / commit；
高风险动作 Gate / Audit。
```

P4 不等于验证通过。Patch applied 或命令 exit_code=0 只能作为执行记录或 Evidence candidate。

### 4.3 P5 验证

P5 依赖执行环境完成：

```text
构建；
运行 / 启动；
测试；
回归；
关键行为等价或差异登记；
验证 Evidence；
验证 Trace；
风险接受 Audit。
```

远程环境连接成功不等于 P5 通过。

### 4.4 P6 交付

P6 可能依赖 Git / 交付集成能力完成：

```text
交付包生成；
交付报告生成；
变更摘要；
Git commit；
Git push 或 PR / MR 候选；
Evidence / Trace / Audit 汇总。
```

Git push 属于远端写操作，必须按高风险策略处理。

## 5. 与 R 阶段的关系

```text
R4：基础工程骨架与 API 契约落地，需预留集成与执行 API；
R6：Agent / Skill / 资源基础，需定义外部执行器和 Tool / MCP 资源注册；
R7：集成与项目接入，需真实接入本地目录、Git、ZIP、GitHub；
R8：工作区真实化，需打通 Workspace 与 Execution Session；
R9：P0-P1 最小真实链路，需验证源码接入和建档链路；
R11：P4 执行链路，需验证外部编程 Agent、Tool / MCP、写盘和 Git 变更链路；
R12：P5-P6 验证与交付，需验证构建、测试、交付和 Git 交付链路；
R14：远程资源调用增强，扩展远程资源和外部系统能力；
R17：全量联调、体验打磨与发布冻结，检查集成链路是否真实可用。
```

说明：

```text
1. Git / GitHub 接入不应等到 R14；
2. OpenCode / 外部执行器基础边界应在 R6/R11 前明确；
3. 远程环境基础声明和执行会话应在 R8/R11 前明确；
4. R14 可深化远程资源调用，但不能成为基础集成能力缺失的理由。
```

## 7. 源码接入架构

源码接入支持四类入口：

```text
local_directory；
git_repository；
zip_upload；
github_repository。
```

统一接入流程：

```text
1. 接收接入请求；
2. 创建 Project Integration；
3. 校验 source_type 和 source_ref；
4. 校验 credential_ref 和 credential_status；
5. 执行 Policy Check；
6. 需要时触发 Gate；
7. 创建或绑定 Project Workspace；
8. 执行接入动作；
9. 生成接入 Trace；
10. 生成 Artifact / Evidence candidate；
11. 返回后端状态；
12. 前端刷新展示。
```

源码接入必须产生：

```text
source_import_trace；
workspace_init_trace；
source_summary_artifact；
source_import_evidence_candidate；
redaction_status；
error_ref 或 success_ref。
```

## 8. Git / GitHub 架构边界

Git / GitHub 能力分为读取、变更准备、远端写三类。

### 8.1 读取类

```text
git clone；
git fetch；
git pull；
git status；
git branch list；
git log；
git diff read。
```

读取类通常用于 P0 接入、P1 建档和 P2 评估，但仍需 Policy 检查、Trace 和脱敏。

### 8.2 变更准备类

```text
git checkout；
git branch create；
git add；
git commit；
patch generate；
patch apply。
```

变更准备类涉及 Workspace 写入和代码变更，必须记录 Trace；其中写盘、Patch apply、commit 需按风险策略触发 Gate / Audit。

### 8.3 远端写类

```text
git push；
PR / MR create；
remote branch delete；
remote tag create；
external repository write。
```

远端写类必须作为高风险动作处理，至少需要：

```text
明确目标仓库；
明确分支；
明确变更摘要；
明确 diff；
Policy Check；
用户 Gate；
Audit；
Trace；
失败回滚或补救说明。
```

红线：

```text
1. 不得静默 push；
2. 不得把 push 成功写成业务验收通过；
3. 不得在错误信息中返回 token；
4. 不得绕过用户 Gate 执行远端写；
5. 不得让外部 Agent 直接持有未受控凭据。
```

## 9. 远程环境架构边界

远程环境是执行环境的一种，不是事实源本身。

远程环境能力包括：

```text
连接配置；
凭据引用；
环境探测；
Workspace 同步或挂载；
命令执行；
构建执行；
测试执行；
服务启动；
日志收集；
健康检查；
状态回收；
会话关闭。
```

远程环境必须通过 Environment Profile 声明，通过 Execution Session 执行。

规则：

```text
1. 远程连接成功不等于环境可用；
2. 环境可用不等于构建成功；
3. 构建成功不等于测试通过；
4. Runtime State 与 Execution State 必须区分；
5. 远程日志必须脱敏；
6. 凭据必须通过 credential_ref 引用；
7. 会话状态必须可恢复；
8. 远程写操作必须 Gate / Audit。
```

## 10. 外部编程 Agent / OpenCode 架构边界

> **R8-5 更新（D-076 / D-077 / D-078，2026-06-27）：**  
> 执行能力已严格分层，代码执行路径（ExecutionProvider）与 AI 编程 Agent 路径（CodingAgentAdapter）完全解耦。  
> OpenCode / qcode 等外部 AI 编程 Agent 现通过 `CodingAgentConfig` 在集成页面配置，工作区选择器（R8 stub / R11 真实）供用户选择使用哪种编程方式。  
> 真实任务委托（LangGraph → CodingAgentAdapter → 外部 Agent，平台审核 Agent 拦截外部 Agent 请求）在 R11 实现。

### 10.1 执行能力分层（D-076）

```text
代码执行路径：
  LangGraph → ExecutionProvider (local_subprocess / container)
  └── 从不依赖 OpenCode 或任何外部 AI Agent
  └── 安全沙箱：DENY_SUBSTRINGS + ALLOWED_COMMANDS + 超时 + env 脱敏

AI 编程 Agent 路径（R11）：
  LangGraph P4 → CodingAgentAdapter
  ├── OpenCodeCLIAdapter（opencode_cli）
  ├── QCodeCLIAdapter（qcode_cli）
  ├── OpenAICompatAdapter（openai_compat）
  └── PlatformAgentAdapter（platform_agent）
       └── 平台审核 Agent 拦截所有外部 Agent 请求（命令执行 / 写盘 / Git 操作）
```

### 10.2 CodingAgentConfig 配置结构（D-077）

```text
agent_type: opencode_cli | qcode_cli | openai_compat | platform_agent
invoke_mode: cli | api | mcp
config: { model?, endpoint?, ...（非敏感配置）}
credential_ref: 指向 Credential 表（D-075，AES-256-GCM，Key 不出后端）
status: not_configured | configured | connected | error
enabled: bool
```

### 10.3 工作区编程 Agent 选择机制（D-078）

```text
R8（当前）：UI 选择器 stub，仅记录用户选择，不影响执行
R11：
  用户选 "平台自有 Agent" → LangGraph 内部 P4 节点执行
  用户选 外部 Agent     → LangGraph P4 → CodingAgentAdapter
                         → 平台审核 Agent 拦截外部 Agent 的命令/写盘请求
                         → ExecutionProvider 执行审核通过的命令
```

### 10.4 外部编程 Agent 职责范围

OpenCode 或其他外部编程 Agent 在当前版本中应被视为外部执行器或资源适配器，而不是平台主编排。

外部编程 Agent 可承担：

```text
读取受控上下文；
读取受控文件；
生成修改建议；
生成 Patch；
执行受控写盘；
执行受控命令；
返回输出摘要；
返回错误和不确定项。
```

外部编程 Agent 不得承担：

```text
1. 决定 P 阶段晋级；
2. 绕过 Stage Plan / Task Plan；
3. 绕过 Policy；
4. 绕过 Gate；
5. 直接写 Evidence validated；
6. 直接访问未脱敏密钥；
7. 直接对远程仓库写入；
8. 替代 LangGraph 主编排。
```

外部编程 Agent 输出应进入：

```text
output_ref；
execution_trace；
artifact_candidate；
evidence_candidate；
issue_or_error_ref；
next_action_suggestion。
```

外部编程 Agent 输出不得自动成为：

```text
current_fact；
validated_evidence；
stage_completed；
user_authorization；
trusted_result。
```

## 11. Tool / MCP / Expert Agent 架构边界

Tool、MCP 和 Expert Agent 均应作为资源接入。

统一要求：

```text
1. 在 Resource Registry 中登记；
2. 标注资源类型；
3. 标注来源；
4. 标注权限范围；
5. 标注风险级别；
6. 定义输入输出契约；
7. 定义上下文策略；
8. 定义输出脱敏策略；
9. 记录调用 Trace；
10. 高风险调用写 Audit；
11. 必要时触发 Gate。
```

资源类型建议：

```text
read_only_reference；
analysis_tool；
code_transformer；
command_executor；
file_editor；
remote_connector；
expert_agent；
mcp_server；
external_service_adapter。
```

规则：

```text
1. Case 不是 Skill，也不是 Tool；
2. Knowledge 默认只读；
3. 社区资源默认只读参考；
4. Tool / MCP 输出不自动成为 Evidence validated；
5. Expert Agent 建议不自动成为决策；
6. 可执行资源必须经过安全、许可、权限和审核流程。
```

## 12. ExecutionProvider 职责边界

ExecutionProvider 是执行动作的统一入口之一。

建议职责：

```text
1. 接收执行请求；
2. 识别动作类型；
3. 映射风险级别；
4. 调用 Policy Check；
5. 触发 Gate；
6. 分派到具体 Adapter；
7. 记录 Trace；
8. 写入 Audit；
9. 生成 output_ref；
10. 返回结构化结果。
```

不得承担：

```text
1. 直接决定阶段 completed；
2. 直接决定 Evidence validated；
3. 绕过 LangGraph 主编排；
4. 绕过 Workspace 边界；
5. 暴露密钥；
6. 用 exit_code 替代业务判断。
```

ExecutionProvider 与 LangGraph 的关系：

```text
LangGraph 负责编排 P0-P6 主流程、节点流转、checkpoint、interrupt/resume；
ExecutionProvider 负责执行动作和资源调用适配；
两者通过结构化 Node / Action 请求和状态回写协作；
ExecutionProvider 不替代 LangGraph 主编排。
```

## 13. Policy / Gate / Audit / Trace 横切架构

所有集成与外部执行动作必须经过横切控制。

### 13.1 Policy

```text
Policy 在动作执行前检查；
Policy blocked 不得由 Agent 批准继续；
Policy error 不得默认 allowed；
Policy 结果必须可追踪。
```

### 13.2 Gate

```text
P 阶段晋级必须用户 Gate；
L5 高风险动作必须用户 Gate；
远端写操作必须 Gate；
高风险写盘和 Patch apply 需按风险策略 Gate；
Gate 未决策不得继续执行。
```

### 13.3 Audit

```text
Gate 决策必须 Audit；
高风险动作必须 Audit；
外部系统写操作必须 Audit；
风险接受必须 Audit；
Audit 不等于 Evidence；
Audit 不等于授权本身。
```

### 13.4 Trace

```text
源码接入必须 Trace；
Git 操作必须 Trace；
外部执行器调用必须 Trace；
文件写入必须 Trace；
远程环境动作必须 Trace；
Trace 不等于 Evidence；
Trace 不证明结果正确。
```

## 14. 状态与事实源

状态事实源应来自：

```text
数据库；
LangGraph checkpoint；
workspace 文件；
Trace / Audit；
event log；
后端状态查询。
```

不得作为事实源：

```text
浏览器缓存；
SSE 事件缓存；
终端窗口；
容器存在；
外部 Agent 自述；
模型输出；
前端本地状态。
```

状态分离：

```text
Coding State：文件、编辑、产物、协作；
Execution State：命令、构建、测试、Patch、外部 Agent；
Runtime State：服务、数据库、中间件、预览。
```

规则：

```text
1. 三类状态分别持久化；
2. 三类状态分别审计；
3. 三类状态不得互相冒充；
4. Runtime ready 不等于 Execution success；
5. Execution success 不等于 Evidence validated。
```
