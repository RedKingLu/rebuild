## 2. 模型模块速查

> 详细定义见 `02-架构设计/00-架构总纲.md` §2.5（Arch-L4 模型网关层）和 `01-决策记录.md` 第八部分。

| 模块 | 核心职责 | 关键约束 |
|---|---|---|
| ModelGateway | 统一模型调用入口；解析模型选择；调用 LiteLLM Adapter；记录 Trace | 薄抽象层，不复刻 LiteLLM 已有能力（D-065） |
| LiteLLM SDK Adapter | 多服务商适配（暂定路线，变更需申请） | 不绕过 ModelGateway 直接暴露给 Agent |
| 模型选择解析器 | 按优先级解析：用户指定 → Task/Node override → Agent 默认 → Project 默认 → System 默认 | 不绑定 P 阶段（D-036） |
| Fusion | 多模型/多视角综合判断（模型策略，非独立运行时） | 不绕过 Policy/Gate/Audit；输出不自动等于授权（D-035） |
| token/成本预算 | 记录/估算/控制模型调用成本 | 不进入 P0-P6 主线默认 Gate 条件（D-064） |

调用路径：

```text
LangGraph node → Agent/Skill → ModelGateway → LiteLLM SDK Adapter / Provider
```

> 详细定义见 `02-架构设计/00-架构总纲.md` §2.4（Arch-L3）和 §6、`01-决策记录.md` 第九部分、`02-术语表.md` 第十部分。

| 资源类型 | 一句话定义 | 权威源 | 关键约束 |

| Agent | 具备职责/上下文/模型策略/工具权限的执行主体 | D-018 | 少 Agent、多 Skill（D-016） |
| Skill | 可复用的方法/流程/能力约束（R 系列建设用 vs P 系列运行用） | D-008-REV1 | P 系列归入 平台资源/ |
| Tool | 可调用执行某类操作的工具能力 | 术语表 §10 | 受来源/风险/权限/Trace 约束 |
| MCP | 外部能力或上下文连接方式 | 术语表 §10 | 外部写操作必须 Gate |

## 4. 核心约束（模型与资源专题特有红线）

以下约束是本专题在架构红线基础上的专项补充：

```text
1. 不得把 Fusion 写成特殊流程、特殊阶段、特殊评审引擎或独立运行时角色（D-035）；
2. 不得让 Fusion 绕过 Policy/Gate/Audit；
3. 不得把模型输出作为唯一事实、授权或验收依据；
4. 不得自研替代 LiteLLM 已覆盖的多服务商适配能力，除非走架构变更申请（D-065）；
5. 不得把 token/成本预算设为 P0-P6 主线默认 Gate 条件（D-064）；
6. 不得将 Case 直接执行——Case 无执行权；
7. 不得将社区资源默认执行——默认 L0 只读参考（D-041）；
8. 不得将确定性转换设计为独立主线引擎（D-063）；
9. 不得让 Tool/MCP/外部 Agent 绕过统一资源调用流程（D-041）；
10. 不得无 Trace 调用资源（D-041）；
11. 不得无 Audit 执行高风险资源调用；
12. 不得由 Agent 批准 Policy 禁止项；
13. 不得在资源 Registry 中保存密钥明文；
14. 建设期资源（skills/R-建设执行/）与运行期资源（平台资源/）不得混放（D-008-REV1）；
15. 不得把未经确认的 Knowledge 当作 accepted 决策。
```

> 通用禁止与红线完整总表见 AGENTS.md §18；相关决策详见 01-决策记录.md；术语与风险级别（L0-L5）详见 02-术语表.md。

## 5. 资源调用统一流程速查

> 完整流程见 `01-决策记录.md` D-041 和本目录子文档 `05-资源调用与Case-Knowledge-Tool-MCP边界.md`。

```text
识别资源需求 → 查询 registry → 读取资源定义
  → 检查来源/许可/风险/权限 → 判断是否需要 Gate
  → 调用资源 → 记录 Trace → 必要时记录 Audit
  → 生成 Artifact/Evidence 或参考输出 → 交回 NodeLoop/TaskGraph
```

资源调用必须记录：来源、风险、权限、Trace；高风险调用必须 Audit。资源调用失败必须进入 failure_policy。结果必须回到 TaskGraph 路由，不得成为不可追踪黑盒。
