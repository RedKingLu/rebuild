## 1. Context 与 Memory 的区别

```text
Context：一次任务/节点/模型调用时装配给 Agent/Model/Tool 的输入集合——即时装配，可裁剪
Memory ：跨任务或跨过程保存的结构化信息——持久或半持久，必须严格准入
Trace  ：记录发生过什么（不是 Memory）
Evidence：证明某个 claim 的材料（不是 Memory）
Artifact：任务产物或交付材料（不是 Memory）
Knowledge：可检索知识或参考资料——不自动进入 Memory
```

核心规则：

```text
1. Context ≠ Memory ≠ Evidence ≠ Trace ≠ Artifact ≠ Knowledge
2. 模型输出不自动进入 Memory
3. Artifact 不自动晋升为项目文档或事实源
4. Knowledge 不自动进入 Memory——需经确认
```

## 2. Context 分层（C0-C6）

### 2.1 总览

```text
C0 Global Policy Context       — 稳定硬约束，优先级最高
C1 Product Definition Context   — 产品定义事实
C2 Scope / Baseline Context     — 当前项目范围与基线
C3 Run Context                  — 当前 Run 动态状态
C4 Node Task Context            — 当前 Task Node 任务
C5 Evidence / Artifact Context  — 证据与产物引用
C6 Dynamic Retrieval Context    — 按需检索，不永久塞入
```

规则：

```text
1. C0-C2 偏稳定事实和约束，不应被下级覆盖
2. C3-C5 偏当前 Run/任务/证据——随运行变化
3. C6 按需检索——检索结果用于决策时必须经过事实源和 Evidence 校验
4. C3 统一使用 Run Context——禁止 Mission 产品层残留（D-070）
5. 下级 Context 与上级冲突时，以上级为准
```

### 2.2 C0 Global Policy Context

可包含：项目治理硬规则、事实源层级、安全红线、密钥脱敏规则、Policy/Gate/Audit 规则、P/R 阶段不得混用规则、不设 Mission 产品层规则、历史版本只读参考规则。

```text
规则：优先级最高 / 不应被下级覆盖 / 应尽量短且稳定 / 变更必须有决策来源 / 不得包含密钥或临时任务信息
```

### 2.3 C1 Product Definition Context

可包含：产品定位、P0-P6 阶段定义、Project 作为用户可见主对象、产品范围、典型项目场景、用户可见流程、产品验收引用。

```text
规则：只能来自当前版本产品定义事实源 / 历史产品定义仅作 C6 动态参考 / 与 C0 冲突时以 C0 为准 / 不得被模型输出覆盖
```

### 2.4 C2 Scope / Baseline Context

可包含：当前项目范围、启用/裁剪的 P 阶段、技术栈范围、输入来源、项目约束、用户确认的目标、范围外事项、待确认项。

```text
规则：范围不清时必须 Gate / 范围变化必须产生 Plan Delta / 不得被 Agent 擅自扩大 / 应与 Stage Plan/Task Plan 对齐 / 范围外资源不得被静默调用
```

### 2.5 C3 Run Context

可包含：run_id/project_id/current_stage/execution_mode/Stage Plan/Task Plan/TaskGraph/active_gate/checkpoint/run_status/recent_trace_refs/blocking_issues。

```text
规则：不引入 Mission 产品层（D-070）/ 如历史字段出现 mission_id→R2 校准为 run_goal/objective/task_group_id 或删除 / 随 Run 状态更新 / 不得替代 Trace/Audit / 不得隐藏 Gate 或阻塞项
```

### 2.6 C4 Node Task Context

可包含：node_id/task_plan_ref/node_objective/input_refs/expected_outputs/required_skill/required_tools/model_policy/permission_boundary/risk_level/acceptance_criteria/failure_policy。

```text
规则：必须小而精 / 不得全量塞入项目材料 / 必须保留输入来源 / 权限边界不得被 Agent 覆盖 / 缺失关键输入时不得执行
```

### 2.7 C5 Evidence / Artifact Context

可包含：Artifact refs/Evidence refs/Trace refs/Audit refs/claim_refs/validation_results/acceptance_results/open_evidence_gaps。

```text
规则：只传引用和必要摘要——避免复制成第二事实源 / Evidence 必须支撑明确 claim / Evidence 不足不得 completed / P5 验证必须依赖可验证 Evidence / 不得被模型输出直接覆盖
```

### 2.8 C6 Dynamic Retrieval Context

可来自：当前项目文档/Workspace 文件/运行记录/Trace/Audit/Registry/Case/Knowledge/历史 archive/外部资料/用户新输入。

```text
规则：必须按需检索 / 必须标记来源 / 历史 archive 只读参考 / 外部资料标记来源和可信度 / 不得长期塞入 Memory / 检索结果用于决策时必须经过事实源和 Evidence 校验
```

## 3. Context 装配流程

```text
1. 读取任务目标
2. 读取 Agent Definition Contract（含 Context Recipe）
3. 读取 Skill Definition Contract（含 required_context）
4. 装配 C0-C2 稳定约束（优先级递减）
5. 装配 C3 Run Context
6. 装配 C4 Node Task Context
7. 装配 C5 Evidence/Artifact 引用
8. 按需检索 C6
9. 执行裁剪、摘要、脱敏
10. 记录 context_trace
11. 提交给 Agent/Model/Tool
```

禁止：

```text
未按层级全量塞入 / 未标记来源 / 未脱敏 / 将历史参考误作当前事实 / 将模型输出误作上级事实 / 忽略 Evidence 缺口
```

> Context Recipe 是 Agent/Skill 的上下文装配说明。每个 Agent Definition Contract 必须声明（D-018）。Recipe 至少说明：required_context_layers、optional_layers、retrieval_queries、source_priority、max_context_budget、forbidden_sources。具体字段由 R4/R6 定义，本文不固化 schema。

## 4. 上下文裁剪与摘要

裁剪优先级：

```text
1. 优先保留 C0-C2 硬约束
2. 优先保留当前 Stage/Task 相关内容
3. 优先保留 Evidence/Artifact 引用（而非全文复制）
4. 优先保留最新已确认事实
5. 删除重复表述
6. 删除无关历史材料
7. 删除未确认推断
8. 删除密钥和敏感信息
```

摘要规则：

```text
摘要必须保留来源引用 / 不得新增事实 / 必须标记不确定项 / 不得把建议写成决策 / 不得把模型推断写成 Evidence
```

## 5. Memory 分层

```text
Policy Memory         — 稳定策略和硬规则（只读，长期）
Project Memory        — 项目级已确认事实（项目生命周期）
Run Memory            — 当前 Run 内确认的推进状态和重要结论（Run 生命周期）
Agent Working Memory  — Agent 当前任务的短期工作状态（任务生命周期，结束后清理）
```

核心规则：

```text
1. Memory 写入必须有准入条件（见 §6）
2. Memory 写入必须可追溯（Trace 或决策引用）
3. 与 Policy Memory 冲突时以 Policy Memory 为准
4. 下级 Memory 不得覆盖上级
```

### 5.1 Policy Memory

可保存：事实源层级、安全规则、密钥脱敏规则、Gate 规则、Policy 优先级、P/R 阶段命名规则、不设 Mission 产品层规则、历史版本只读参考规则。

```text
规则：必须来自 accepted 决策或已批准 Policy / 不得由单次模型输出写入 / 变更必须可审计 / 不得保存密钥
```

### 5.2 Project Memory

可保存：项目目标、用户确认范围、项目技术栈事实、项目约束、已确认阶段裁剪、长期有效的项目偏好、关键决策引用、重要 Artifact/Evidence 索引。

不得保存：未确认推断、临时错误日志、一次性任务计划、已过期旧版事实、密钥/Token/env 明文、模型猜测、未审核外部资料。

### 5.3 Run Memory

可保存：当前 Run 目标、当前阶段、执行模式、Stage Plan/Task Plan 引用、TaskGraph 状态摘要、active_gate、阻塞项、已确认 Plan Delta、关键 Trace/Audit 引用。

```text
规则：随 Run 生命周期变化 / Run 结束后归档或冻结必要摘要 / 不得升级为 Project Memory 除非经过确认 / 不得覆盖 Policy Memory / 不得保存密钥明文
```

### 5.4 Agent Working Memory

可保存：当前子步骤、临时分析摘要、待检查项、当前工具调用状态、未完成输出草稿、短期错误上下文、下一步建议。

不得保存为长期记忆：临时错误日志、一次性任务计划、未确认推断、模型草稿、敏感信息、密钥、过期上下文。

```text
规则：不等于 Trace——关键动作必须写 Trace / 重要结论必须经确认后才能进入 Run/Project Memory / 任务结束后应清理或归档必要摘要 / 不得跨 Agent 泄露不该共享的上下文
```

## 6. Memory 写入准入

### 6.1 允许写入（8 条）

```text
1. 来源明确    3. 有适用范围    5. 不违反 Policy    7. 与现有事实不冲突
2. 已确认      4. 有有效期      6. 不含敏感明文     8. 有 Trace 或决策引用
```

### 6.2 必须拒绝（9 类）

```text
密钥 / Token / env 明文 / 未确认推断 / 临时错误日志
/ 一次性任务计划 / 已过期旧版事实 / 未经审核的社区材料 / 模型输出中的未经验证结论
```

---

## 7. Memory 生命周期

```text
created → updated → superseded / deprecated / expired → archived / deleted_by_policy
```

规则：

```text
1. 不得静默覆盖重要 Memory
2. 被替代 Memory 必须保留 superseded 关系
3. 过期 Memory 不得用于当前事实判断
4. 历史 Memory 可作为参考但必须标记状态
5. 删除敏感信息必须记录安全处理，不保留明文
```

## 8. 上下文污染防护

### 8.1 常见污染来源

```text
历史版本旧事实 / 用户举例被扩大为完整范围 / 模型猜测被写成事实
/ 临时计划被写入长期记忆 / 旧 Mission/Phase/S0-S7/F0-F6 表述残留
/ 社区资源未经审核 / 上下文过长导致关键约束丢失 / 工具输出摘要丢失来源
```

### 8.2 防护规则

```text
1. 每次复杂任务先查事实源——不凭记忆
2. 区分事实、推断、建议（AGENTS.md §6.5）
3. 保留来源引用——不丢失溯源
4. 不确定项必须停下来或进入待确认项
5. 历史材料只读参考——不自动成为当前事实
6. C0-C2 硬约束优先——不被长上下文淹没
7. 任务长时分步读取、分步写入、分段校验
8. Memory 写入前必须检查准入（§6）
```

## 9. 与其他组件的关系速查

| 组件 | 关键约束 |
|---|---|
| **ModelGateway** | 接收已裁剪/已脱敏的上下文；模型输出不得自动进入 Memory；Trace 应记录 context_refs |
| **Agent/Skill** | Agent Contract 必须声明 Context Recipe + Memory Policy；不得自行全量读取；不得把临时推断写入长期 Memory |
| **NodeLoop/TaskGraph** | 节点间传递优先引用非复制全文；失败/返工/重试须重新校验上下文；Gate resume 后须重检上下文有效性 |
| **Evidence/Artifact** | 进入 Context 使用引用；Evidence 进入 Context 使用 claim+source 引用；Evidence 不足不得通过摘要掩盖 |

## 11. 红线

```text
1. 不得全量塞入上下文——必须按层装配
2. 不得把历史 archive 自动当作当前事实
3. 不得把模型输出自动写入 Memory
4. 不得把未确认推断写入 Memory
5. 不得把临时错误日志写入长期 Memory
6. 不得把一次性任务计划写入长期 Memory
7. 不得把已过期旧版事实写入 Memory
8. 不得在 Memory/Context/Trace/Audit 中保存明文 Key/Token/Secret/Password
9. 不得用 Memory 替代 Evidence
10. 不得用 Agent Working Memory 替代 Trace
11. 不得让上下文摘要掩盖 Evidence 不足
12. 不得让 C6 动态检索绕过事实源层级
13. 不得保留 Mission 产品层残留（D-070）
```
