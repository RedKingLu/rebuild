# P-eval-harness（迁移正确性评估框架）

## 适用阶段与触发条件
P5 验证阶段，对任何迁移交付物做正确性判定时触发。核心思想：**评估先于实现**——在 P4 编码前（或并行）即定义验证断言，迁移完成后批量执行，以客观结果驱动 go/no-go，直接对齐平台 D 验收。

## 输入
- 源系统行为规范、接口契约、关键业务规则
- 源系统抽取的对照数据（功能等价基准、数据一致基准）
- P4 迁移产出（目标系统可执行/可访问入口）
- 验收标准与 D 门要求

## 执行步骤
1. **定义断言**：迁移前明确三类断言——①功能等价（同输入下目标与源输出一致）②数据一致（迁移后数据与源对账：行数、校验和、关键字段）③接口契约（请求/响应结构、状态码、错误语义与源等价）。每条断言关联到需求/规范条目。
2. **设计评估集**：分能力评估（capability，验证功能达成）与回归评估（regression，验证既有行为未破坏），覆盖正常、边界、异常路径。
3. **选 grader**：能机器判定的用 code grader（精确比对/容差比对/契约校验）；语义类用 model grader（经 ModelGateway，且必须人工抽检复核）；高风险/不确定项用 human grader（人工裁决）。
4. **批量执行**：对评估集运行 k 次（含模型/外部依赖的非确定项需多次），记录每条断言通过/失败/跳过。
5. **pass@k 统计**：计算 pass@k 等指标，识别不稳定（flaky）项与确定性失败项。
6. **go/no-go 判定**：依阈值给出整体判定——关键断言全过且整体达标→go；否则 no-go 并列出阻塞项。
7. **回写**：失败项归因（迁移缺陷/断言错误/环境问题），驱动 P4 返工或断言修正。

## 输出 / 产物（Artifact / Evidence）
- 断言清单（三类，关联需求条目）
- 评估集定义（能力 + 回归，含输入与期望）
- 执行结果矩阵（每断言 pass/fail/skip，pass@k）
- go/no-go 判定报告与阻塞项清单
- grader 配置与人工抽检记录
- 原始执行日志（可复现）

## 质量门 / 验收标准
- 每条断言可追溯到需求/规范，无孤立断言
- 数据一致断言覆盖行数 + 校验和 + 关键字段对账
- 接口契约断言覆盖结构、状态码、错误语义
- model grader 结论有人工抽检复核，不单独定生死
- go 判定要求关键断言 100% 通过；存在确定性失败则 no-go
- 结果可复现，flaky 项已识别并标注

## 信创迁移要点
- 数据一致须考虑源（Oracle/MSSQL）与目标（达梦/openGauss）的类型映射、精度、字符集差异，对账容差需基于业务定义而非默认相等。
- 接口契约等价需注意目标栈框架默认行为差异（日期格式、空值、分页、错误码），不可假设默认一致。
- 功能等价基准数据来自源系统，须脱敏后用于评估，禁止包含真实密钥/敏感个人信息。

## 反例 / 禁止
- 禁止迁移完成后才临时编断言（评估须先于或并行实现）
- 禁止仅以「跑通了」代替断言级判定
- 禁止 model grader 单独决定 go/no-go 而无人工复核
- 禁止把不稳定 flaky 通过当作真实通过
- 禁止在评估数据中包含真实密钥/未脱敏敏感数据

## 与平台集成
- model grader 及辅助分析的模型调用一律经 ModelGateway；模型判定结论须人工抽检，模型输出不等于 Evidence。
- 评估若需对生产数据/系统执行写操作（L4-L5），须经用户 Gate。
- 断言清单、评估集、结果矩阵、判定报告挂 Artifact/Evidence，执行动作记 Trace/Audit，评估集登记 Registry。
- 本 skill 产出的 Evidence 必须支撑明确的正确性 claim；关键断言未全过或证据不足，不得标记 completed，对齐 D 验收的 no-go。
