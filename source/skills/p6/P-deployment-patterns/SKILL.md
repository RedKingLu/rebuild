# P-deployment-patterns（交付部署模式）

## 适用阶段与触发条件
P6 交付阶段，迁移产物通过 P5 验证后进入上线。本 skill 重新 grounding 云默认假设：信创目标多为**内网/离线 on-prem 环境**（麒麟/统信 OS、国产中间件、私有镜像仓库），无公有云弹性与公网拉取。覆盖部署方案、发布策略、回滚预案与上线检查清单。

## 输入
- P5 验证通过证据（eval-harness go、benchmark 达标、browser-qa SHIP）
- 镜像/制品（P4 容器化产出，已入私有仓库 Harbor）
- 目标环境拓扑（节点、网络分区、国产中间件版本、DB 集群）
- 运维窗口、变更审批、回滚约束（数据迁移是否可逆）

## 执行步骤
1. **环境核对**：确认目标麒麟 OS 版本、CPU 架构（ARM64/飞腾）、中间件（东方通 TongWeb/宝兰德 BES）、DB（达梦/openGauss/GaussDB）版本与验证环境一致。
2. **离线制品准备**：所有镜像、依赖、字体、驱动预置到内网仓库与离线源，确认无公网拉取依赖（断网可部署）。
3. **CI/CD（内网）**：在内网流水线完成构建→签名→扫描→推仓；流水线本身运行于隔离网络，凭据经密钥管理注入。
4. **发布策略选型**：依业务连续性要求选——滚动（默认，逐节点替换）、蓝绿（双环境切换，需双倍资源）、灰度/金丝雀（按比例放量，需流量切分能力）。on-prem 资源受限时优先滚动 + 健康门。
5. **健康检查**：部署每节点设就绪/存活探针，业务级健康（DB 连通、中间件就绪、关键接口 200）通过后才纳入流量。
6. **数据迁移与切换**：若涉及数据切换，明确割接窗口、停写、增量同步、对账（衔接 P-eval-harness 数据一致断言），确认可回退点。
7. **回滚预案**：预置上一版本镜像与配置，明确回滚触发条件、步骤、数据回退策略（不可逆数据变更须前置备份与确认）。
8. **上线检查清单核验**：逐项核对清单（见下），全部通过方可放量。

## 输出 / 产物（Artifact / Evidence）
- 部署方案文档（拓扑、策略、步骤、窗口）
- 内网 CI/CD 流水线配置与构建签名记录
- 健康检查配置与上线探测结果
- 数据割接与对账记录（如涉及）
- 回滚预案文档与回滚演练记录
- 上线检查清单（逐项签署）

## 质量门 / 验收标准
- P5 验证证据齐备且为 go/SHIP，方可进入 P6
- 部署在断网内网环境可完整执行，无公网依赖
- 每节点健康检查通过后才接流量
- 回滚预案明确且经演练，不可逆变更有前置备份
- 上线检查清单全项通过并留签署记录
- 制品已签名 + 漏洞扫描通过（等保合规）

## 场景要点（按项目场景取用）
- 内网/离线是常态，部署脚本与依赖必须自包含，禁止上线时临时联网下载。
- ARM64 节点须验证全部依赖已为目标架构构建，避免 x86 制品误部署。
- 国产中间件（东方通/宝兰德）部署配置与 Tomcat/WebLogic 不同，连接池、类加载、JVM（毕昇 JDK）参数须按目标中间件适配。
- 等保要求：制品签名、漏洞扫描、最小权限、审计留痕；上线变更须走变更审批。

## 反例 / 禁止
- 禁止在生产上线时联网拉取镜像/依赖
- 禁止无回滚预案或回滚未演练即上线
- 禁止跳过 P5 验证证据直接部署
- 禁止不可逆数据变更前不做备份/确认
- 禁止部署脚本中硬编码生产密钥、连接串、证书

## 与平台集成
- 部署方案/脚本若用模型辅助生成，调用经 ModelGateway；产出须经清单核验，模型输出不等于 Evidence。
- 生产部署、数据割接、回滚均为最高风险外部写动作（L5），必须经用户 Gate 显式确认，逐步放量。
- 部署方案、流水线记录、健康探测、对账、回滚演练、检查清单挂 Artifact/Evidence，部署动作记 Trace/Audit，发布版本登记 Registry。
- 上线检查清单与 P5 Evidence 共同构成 D 验收依据；任一项不达标不得判 completed。
