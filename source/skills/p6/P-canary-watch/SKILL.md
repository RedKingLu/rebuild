# P-canary-watch（灰度观测）

## 适用阶段与触发条件
- 阶段：P6 交付。迁移目标系统已部署到信创目标环境（麒麟/统信 OS + 达梦/openGauss/GaussDB + 国产中间件），进入灰度/试运行窗口。
- 触发：发布完成、切流前后、回滚演练、巡检任务到点；或上游 Gate 批准上线后自动挂起观测窗口。
- 不适用：P0–P5 构建期、未部署的纯代码产物、无可达 URL/端点的离线交付。

## 输入
- 被观测目标：内网可达的 URL / API 端点 / SSE 流地址 / 静态资源清单。
- 观测窗口：`interval`（采样间隔，如 30s）+ `duration`（持续时长，如 30min / 24h）。
- 基线阈值：错误率上限、P95/P99 延迟上限、关键接口可用性下限（来自 P5 验证基线，不得现编）。
- 回滚触发条件：连续 N 次健康检查失败 / 错误率突破阈值 / 关键依赖（数据库连接、中间件）不可达。
- 受限网络说明：内网常无外网探针、无云监控，须声明实际可采集的指标边界。

## 执行步骤
1. **确认可达性**：先做一次性连通探测（HTTP 200 / SSE 建连 / 资源 200），不可达则直接判 Fail，不进入循环。
2. **建立采样循环**：按 `interval` 周期采集——HTTP 状态码、响应体关键字段、SSE 心跳、静态资源完整性、console error、响应延迟。
3. **性能回归比对**：每个采样点与 P5 基线比对，标注回归项（延迟↑、错误率↑、可用性↓）。
4. **据实采集**：内网无法采集的指标（如外部 APM、真实 CPU/IO）明确标记「不可用」，不臆造数值。
5. **触发判定**：命中回滚触发条件 → 生成告警事件 + 建议回滚；命中窗口结束 → 生成观测报告。
6. **回滚路由**：自动回滚属外部写/高风险（L4–L5）操作，必须经用户 Gate 裁决；本 Skill 只产出建议与证据，不自行回滚。

## 输出 / 产物（Artifact / Evidence）
- 观测报告（Artifact）：窗口区间、采样次数、各指标时间序列、回归项清单、是否命中触发条件。
- 证据（Evidence）：原始采样记录（时间戳 + 实测值），可追溯；模型对采样的解读独立标注，不混入 Evidence。
- 告警事件（如触发）：触发条件、命中时刻、建议动作（回滚/扩容/降级）。
- 全部写入 Trace/Audit 并登记到 Registry，关联本次 run 与目标版本号。

## 质量门 / 验收标准
- 采样数据为真实实测值，无编造；不可采集项显式标「不可用」。
- 报告含明确结论：Pass（窗口内全部指标达标）/ Fail（命中触发条件）/ ◐（部分指标不可采集，有条件通过）。
- 回滚建议附触发条件命中证据，未经用户 Gate 不得执行回滚。
- 阈值来源于 P5 基线且被引用，而非本阶段临时设定。

## 场景要点（按项目场景取用）
- 内网受限：多数项目无公网探针、无第三方监控 SaaS，监控指标据实采集，缺失即标缺失。
- 国产栈健康项：达梦/openGauss/GaussDB 连接池存活、国产中间件（如东方通 TongWeb / 金蝶 Apusic）心跳、麒麟/统信 OS 服务状态须纳入采样。
- 字符集/时区/locale 回归易在国产 OS 上暴露，须纳入关键接口响应正确性校验。
- 灰度切流比例（5%→20%→50%→100%）与回滚预案应与迁移上线方案一致，观测窗口覆盖至少一个完整业务周期。

## 反例 / 禁止
- 禁止在无连通性的情况下空跑循环并报「健康」。
- 禁止用模型推测填充未采集到的指标值。
- 禁止本 Skill 自行执行回滚/重启/切流等外部写操作（须走用户 Gate）。
- 禁止将模型对日志的总结当作 Evidence 直接归档。
- 禁止打印/留存任何内网凭据、连接串中的密码、Token。

## 与平台集成
- 所有模型调用经 ModelGateway，token/用量计入预算；无计价时诚实标记不可用。
- 采集结果 → Artifact/Evidence + Trace/Audit + Registry，模型输出 ≠ Evidence。
- 回滚/切流等 L4–L5 外部写操作统一走 HITL Gate，由用户裁决。
- 与 P-automation-audit-ops 协同：上线后自动化任务的存活也纳入观测面。
