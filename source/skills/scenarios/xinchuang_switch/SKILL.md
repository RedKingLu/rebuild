# 信创切换（xinchuang_switch）

> 本场景为平台**典型场景之一**。目标态候选须与项目的 `migration_target`（目标 CPU 架构 + 目标 OS）比对后取用，不得脱离真实源与真实目标环境断言兼容性。

## 目标态词表

**数据库候选（三候选）**

- 达梦 DM8：Oracle 语法兼容度较高，提供 Oracle 兼容模式；JDBC 与 .NET 驱动均由厂商提供。
- 人大金仓 KingbaseES：提供 Oracle / MySQL 兼容模式，底层为 PostgreSQL 系。
- openGauss / GaussDB：PostgreSQL 系内核，SQL 方言与 PG 接近而与 Oracle/MSSQL 差异明显。

**操作系统候选**

- 麒麟 Kylin（银河麒麟服务器版 / 桌面版）
- 统信 UOS（服务器版 / 桌面版）
- openEuler

**CPU 架构候选**

- 鲲鹏（aarch64）、飞腾（aarch64）
- 龙芯 LoongArch（loongarch64，非 MIPS 兼容，工具链独立）
- 兆芯（x86_64 兼容）

**中间件与运行时替换候选**

- 应用服务器：Tomcat / 东方通 TongWeb / 宝兰德 BES
- 消息与缓存：Kafka / RocketMQ、Redis 与其国产发行版
- 运行时：OpenJDK 与国产 JDK 发行版（毕昇 JDK / 龙井 JDK）；.NET Framework 须先跨平台化再谈国产 OS 落地

## 迁移与重构模式

- 数据库切换：先做对象清点（表 / 视图 / 序列 / 存储过程 / 触发器 / 自定义类型），再分层迁移 schema → 对象 → 数据；方言转换与数据搬迁分开验证，逐层留证。
- 零停机切换：expand-contract（先兼容双写、再收敛），分批迁移大表并带校验和 / 抽样比对，禁止一次性整库切换而无回滚预案。
- .NET 技术栈：`.NET Framework` 不能直接落到国产 Linux OS，须先完成跨平台运行时迁移（`.NET 8/9`），再处理国产 OS / CPU 上的原生依赖与部署。
- 容器化：基础镜像须换为目标 OS 的国产化基础镜像，且镜像架构须与目标 CPU 一致（`linux/arm64` 与 `linux/amd64` 不可混用）。
- 原生依赖：含 C/C++ 扩展、P/Invoke、JNI 的依赖须在目标 CPU 架构上重新编译，不能沿用 x86_64 预编译产物。
- 兼容性核实：任何"完全兼容"的结论都须以目标库/目标 OS 上的真实执行结果为准，厂商宣称的兼容度不作为验收证据。

## 常见陷阱与已知不兼容点

- **达梦对 Oracle 的兼容非 100%**：部分系统包、`ROWNUM` 分页语义、优化器 hint 行为与 Oracle 存在差异，须逐项验证而非按兼容模式默认通过。
- **openGauss / KingbaseES 走 PG 系语义**：`MERGE`、序列用法、标识符大小写折叠、`||` 字符串拼接、空串与 `NULL` 的等价性，与 Oracle / MSSQL 语义不同，须专门覆盖测试。
- **字符集与排序规则**：GBK 旧库 → UTF-8 目标库需显式处理，否则出现中文乱码与排序结果差异；比较与 `ORDER BY` 结果可能随排序规则变化。
- **驱动层差异**：达梦 JDBC / .NET 驱动、GaussDB 驱动的连接串格式、默认隔离级别、批量提交行为与原库不同，应用配置须同步修改。
- **外键与约束的结构性缺失**：旧库常见"零外键"（约束靠应用层维护）的情形，迁移后若照搬结构会把隐式约束丢在应用侧 —— 须在评估阶段显式清点。相关执行细则见 P4 skill `P-database-migrations`，本包不复制其正文。
- **国产 CPU 上的原生依赖编译**：LoongArch 与 aarch64 缺少部分上游预编译轮子 / NuGet 原生包，须自行构建工具链或替换依赖。
- **国产 OS 的系统库版本**：glibc / OpenSSL 版本与主流发行版不同，静态链接假设与 CI 镜像常在目标 OS 上失效。

## 反例与禁止

- 禁止在未核实兼容性矩阵、未在目标库真实执行的情况下断言某国产库"完全兼容"原库。
- 禁止只做方言字符串替换而不验证语义等价（分页 / 空值 / 大小写 / 事务隔离）。
- 禁止在 x86_64 上构建产物后直接声明国产 CPU 平台可用。
- 禁止把"数据行数一致"当作数据迁移成功的唯一判据（须含校验和或抽样比对）。
- 禁止对源库执行任何写操作或 DDL。
