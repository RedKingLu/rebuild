# 软件移植 —— 风险清单（具体不兼容点）

> 每条须是可验证的具体技术事实。核实方式一并给出。

- Linux 文件系统区分大小写而 Windows / macOS 默认不区分，资源路径大小写错误只在 Linux 上暴露 —— 核实：在区分大小写的文件系统上完整构建并运行。
- 硬编码 `\` 路径分隔符在 Unix 上不被识别为分隔符 —— 核实：检索字符串字面量中的路径拼接。
- `CRLF` 与 `LF` 差异影响按行解析的文本协议、脚本 shebang 与签名校验 —— 核实：以目标平台换行符生成样本并跑通解析路径。
- 结构体对齐填充与字节序在跨架构时不同，二进制序列化格式可能不可互读 —— 核实：在源架构写入、目标架构读取同一份二进制样本。
- Windows 的 `long` 为 32 位（LLP64）而 Unix 64 位平台为 64 位（LP64） —— 核实：检索依赖 `long` 宽度的算术与序列化代码。
- P/Invoke 与 JNI 的库命名与查找路径平台相关（`.dll` / `.so` / `.dylib`） —— 核实：在目标平台运行并检查库加载是否成功。
- Linux 默认导出全部符号、Windows 需显式导出，缺失导出时"编译通过但运行找不到符号" —— 核实：对产物做动态符号解析检查。
- `fork` 语义与 POSIX 信号在 Windows 上无直接对应 —— 核实：清点进程创建与信号处理调用点并确认已改用平台等价机制。
- iOS 的后台执行与文件访问权限模型比 Android 严格，Android 可行的后台策略在 iOS 上会被系统终止 —— 核实：在 iOS 真机上做后台驻留与恢复测试。
- 目标平台缺少源平台默认字体，导致缺字与布局溢出 —— 核实：在目标平台截图检查含中文界面的渲染。
- 区域设置默认值差异改变日期与小数分隔符解析 —— 核实：以不同区域设置运行并比对解析结果。
- 交叉编译产物未在目标真机验证时，工具链 sysroot 与目标系统库版本不一致的问题不会暴露 —— 核实：在目标真机而非仅模拟器上运行。
