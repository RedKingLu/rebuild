# 通用重构（兜底场景包）

> 本包为**兜底通用方法论**，**无专用场景知识**。若本项目属于某个明确场景，建议在 `source/skills/scenarios/` 下建立或选择对应场景包（平台典型场景与用户自定义场景同等支持）。本包**不预设任何目标技术栈**。

## 目标态词表

- 目标态**须由项目的 `migration_target`（目标 CPU 架构 + 目标 OS）与用户输入确定**；本包不预设任何语言、运行时、数据库或中间件候选。
- 项目未提供目标态信息时：诚实声明"目标环境未定"，并在 `open_questions` 中列出待补事实，**不得臆造目标栈建议**。

## 迁移与重构模式

- 依赖梳理：先建立真实依赖清单与调用边界，再讨论改造顺序。
- 边界切分：按可独立验证的边界切分改造单元，使每个单元都能单独构建与回归。
- 增量替换：expand-contract / 并行双写 / 灰度切流，避免一次性整体替换。
- 回归护栏：改造前先建立可复跑基线（构建 + 测试 + 关键行为抽样），改造后逐轮比对。

## 常见陷阱与已知不兼容点

- 隐式依赖：运行期反射、动态加载、环境变量、系统时区与区域设置不出现在依赖清单中，静态分析必然漏项。
- 配置漂移：构建期 / 部署期 / 运行期多份配置取值不一致，改一处不生效。
- 基线缺失：无回归基线时，"改造后能构建"会被误当作"行为等价"。

## 反例与禁止

- 禁止在无场景知识时臆造目标栈建议（须诚实标注"无专用场景知识"）。
- 禁止把"能编译 / 能启动"当作重构完成的判据。
- 禁止在未建立回归基线的情况下开始大范围改造。
